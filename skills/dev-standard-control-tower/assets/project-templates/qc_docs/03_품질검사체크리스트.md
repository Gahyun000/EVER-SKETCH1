# 품질검사 체크리스트

## 문서와 추적성

- [ ] 승인된 요구사항 기준선이 있다.
- [ ] 모든 요구사항이 설계와 테스트에 연결된다.
- [ ] 변경요청이 기준 문서에 반영되었다.
- [ ] 핵심 엔진 기술문서가 최신이다.
- [ ] 주요 기능별 T0~T3 선정과 근거가 있다.
- [ ] T1 이상 요구사항이 하네스와 검증기 ID에 연결된다.

## UI

- [ ] 승인 HTML 시안과 구조·문구·상태가 일치한다.
- [ ] 로딩·빈값·오류·권한 없음이 정의되어 있다.
- [ ] 긴 텍스트와 주요 해상도에서 깨짐이 없다.
- [ ] 모달의 포커스와 배경 스크롤이 안전하다.
- [ ] 색상 외 상태 표현과 키보드 접근을 확인했다.

## 기능과 데이터

- [ ] 정상·오류·경계 조건을 검증했다.
- [ ] 권한을 서버에서 검증한다.
- [ ] 트랜잭션 실패 시 데이터가 일관된다.
- [ ] 날짜·시간대·금액·상태값 표현이 일치한다.
- [ ] 마이그레이션 검증과 복구 방법이 있다.

## 보안

- [ ] 저장소와 로그에 비밀정보가 없다.
- [ ] 외부 입력 검증과 안전한 출력 처리가 있다.
- [ ] 개인정보 목적·접근·보존·파기가 정의되어 있다.
- [ ] 의존성 라이선스와 취약점을 확인했다.

## 운영

- [ ] 배포·스모크·롤백 절차가 검증되었다.
- [ ] 핵심 지표, 로그, 추적 ID 및 경보가 있다.
- [ ] 백업과 복구 책임이 정해져 있다.
- [ ] 알려진 제약과 잔여 위험이 인수자에게 전달되었다.

## 하네스와 루프

- [ ] 입력·출력 스키마와 거부 조건이 구현되었다.
- [ ] 도구 허용목록, 권한, 시간 제한과 멱등성을 검증했다.
- [ ] LLM 자기평가가 아닌 결정론적 검증기로 성공을 판정한다.
- [ ] T2 이상은 상태 전이, 종료조건, 반복·시간·비용 한도를 검증했다.
- [ ] 승인 대기, 사용자 취소, 체크포인트 재개와 중복 실행 방지를 검증했다.
- [ ] T3는 드라이런, 운영 경보, 킬 스위치와 복구를 검증했다.
- [ ] 프롬프트 인젝션, 도구 오용과 데이터 혼입 테스트를 수행했다.
