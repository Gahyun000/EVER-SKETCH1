# 하네스 및 루프 검증 체크리스트

## 기법 선정

- [ ] 기능별 T0~T3 등급과 선택 근거가 있다.
- [ ] 단일 패스로 해결할 수 없는 이유를 검토했다.
- [ ] T2·T3는 기술책임자 승인을 받았다.
- [ ] L등급과 AI 권한 A등급이 위험에 맞게 조정되었다.

## 계약과 권한

- [ ] 입력·출력 스키마와 거부 조건이 있다.
- [ ] 모든 도구가 허용목록과 구조화 계약을 가진다.
- [ ] 읽기·쓰기·외부 전송 권한이 최소화되었다.
- [ ] 부작용 도구에 멱등성과 보상 작업이 있다.
- [ ] 운영 배포·삭제·대량 변경·과금에 인간 승인이 있다.

## 상태와 루프

- [ ] 상태와 전이가 구조화되어 있다.
- [ ] 성공·실패·승인대기·취소·한도초과를 구분한다.
- [ ] 최대 단계, 시간, 비용, 토큰과 자원 한도가 있다.
- [ ] 동일 오류와 품질 정체 시 중단한다.
- [ ] 모델의 자연어 선언만으로 성공 처리하지 않는다.
- [ ] 체크포인트와 중복 실행 방지가 있다.
- [ ] 사용자 취소와 킬 스위치가 동작한다.

## 검증

- [ ] 스키마·업무 규칙·정합성 검증기가 있다.
- [ ] 수치와 금지조건을 결정론적으로 검사한다.
- [ ] LLM 자기평가만으로 완료를 판정하지 않는다.
- [ ] 근거가 필요한 출력은 출처와 위치를 확인한다.
- [ ] 검증 실패 항목만 제한적으로 보완한다.

## 테스트

- [ ] 계약과 상태 전이 테스트가 통과했다.
- [ ] 정상 종료와 모든 비정상 종료를 검증했다.
- [ ] 반복·시간·비용 한도를 검증했다.
- [ ] 네트워크·도구·상태 저장 실패를 주입했다.
- [ ] 취소·재개·롤백과 롤백 실패를 검증했다.
- [ ] 프롬프트 인젝션과 도구 오용을 검증했다.
- [ ] 다른 고객·프로젝트 데이터 혼입이 없다.
- [ ] 무거운 테스트를 자원 한도 안에서 순차 실행했다.

## 운영

- [ ] 실행 ID, 단계, 도구, 검증과 비용 로그가 있다.
- [ ] 비밀정보와 개인정보가 로그에서 마스킹된다.
- [ ] 실패율, 반복, 비용과 승인 대기 경보가 있다.
- [ ] 운영자가 실행 상태를 조회하고 중지할 수 있다.
- [ ] 드라이런과 단계적 권한 확대 증적이 있다.
- [ ] 모델·프롬프트·도구·검증기 버전을 추적한다.

## 출고 판정

- [ ] Blocker·Critical 결함이 0건이다.
- [ ] 필수 시나리오와 보안 테스트가 실제 수행되었다.
- [ ] 가짜 성공, 승인 우회와 무제한 반복이 불가능하다.
- [ ] 롤백과 수동 전환 책임자가 지정되었다.
- [ ] 남은 위험과 예외가 승인되었다.
