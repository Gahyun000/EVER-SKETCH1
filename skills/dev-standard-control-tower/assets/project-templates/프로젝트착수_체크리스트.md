# 프로젝트 착수 체크리스트

## G0 착수

- [ ] 프로젝트 목적과 성공 지표가 정의되었다.
- [ ] 포함·제외 범위가 합의되었다.
- [ ] 사업, PM, 기술, QA, 보안, 운영 책임자가 지정되었다.
- [ ] 프로젝트 수준 L1~L4가 지정되었다.
- [ ] AI 권한 A0~A3가 지정되었다.
- [ ] 주요 기능별 개발기법 T0~T3가 선정되었다.
- [ ] 계약·법률·개인정보 제약을 확인했다.

## 문서 준비

- [ ] 프로젝트 개요서
- [ ] 회의록과 제공 자료 목록
- [ ] 요구사항 정의서와 용어집
- [ ] 요구사항 추적표
- [ ] 프로세스 정의서와 프로세스 흐름도
- [ ] HTML 기준 시안과 화면 설계서
- [ ] API·DB·보안·운영 설계
- [ ] 사용자 매뉴얼 약식
- [ ] 개발자 매뉴얼 약식
- [ ] 운영·배포 매뉴얼 약식
- [ ] 개발기법 선정서
- [ ] T1 이상 기능의 하네스 설계서
- [ ] 품질계획서
- [ ] 주요 산출물별 합성 데이터 품질검사 기준서
- [ ] T1 이상 기능의 하네스 검증계획

## 개발환경

- [ ] 저장소와 보호 브랜치가 준비되었다.
- [ ] README와 프로젝트 AGENTS가 있다.
- [ ] 의존성 잠금 파일이 있다.
- [ ] 개발·검증·운영 환경이 분리되었다.
- [ ] 비밀정보 저장 방식이 정해졌다.
- [ ] 포맷, 정적 검사, 테스트, 빌드 명령이 동작한다.
- [ ] 무거운 테스트의 자원 제한이 정의되었다.
- [ ] T1 이상이면 `harness/`와 `tests/harness/` 구조가 준비되었다.
- [ ] T2 이상이면 상태 저장, 체크포인트, 취소·재개 방법이 정해졌다.
- [ ] T3이면 드라이런, 대시보드, 경보와 킬 스위치 계획이 있다.
- [ ] 개발 완료 시 실제 구현 기반 Windows·macOS 원클릭 실행 파일을 생성·검증하는 계획이 있다.

## 개발 시작 판정

다음 질문 중 하나라도 `아니오`이면 구현을 시작하지 않는다.

- 요구사항이 한 가지 의미로 해석되는가?
- 각 요구사항에 측정 가능한 인수조건이 있는가?
- 화면·API·DB의 주요 계약이 승인되었는가?
- 개인정보와 권한 처리가 정의되었는가?
- 테스트와 완료 판정 방법이 준비되었는가?
- AI·외부 도구 기능의 입력·출력 계약과 검증기가 준비되었는가?
- 루프의 성공·실패·승인대기·한도초과를 기계적으로 판정할 수 있는가?
- 작업자나 모델이 자신의 권한·도구·예산을 확대할 수 없게 설계되었는가?
