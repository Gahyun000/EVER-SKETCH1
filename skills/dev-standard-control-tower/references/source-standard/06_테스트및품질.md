# UDS-106 테스트 및 품질 표준

버전: 1.1.1 | 상태: 검토초안

## 1. 품질 원칙

품질은 개발 완료 후 확인하는 활동이 아니라 요구사항 작성 시 인수조건을 정의하는 활동부터 시작한다. 테스트는 성공 경로뿐 아니라 오류, 경계, 권한, 데이터 품질 및 복구를 검증한다.

## 2. 테스트 수준

| 수준 | 목적 | 책임 |
|---|---|---|
| 정적 검사 | 문법, 타입, 스타일, 취약 패턴 | 개발 |
| 단위 테스트 | 함수·모듈의 독립 동작 | 개발 |
| 통합 테스트 | DB·API·외부 연계 계약 | 개발·QA |
| 하네스 테스트 | 입력·도구·검증기·상태·한도 | 개발·QA |
| 루프 테스트 | 성공·실패·취소·재개·승인대기 | 개발·QA |
| 시스템 테스트 | 사용자 시나리오와 비기능 | QA |
| 인수 테스트 | 고객 요구와 업무 적합성 | PM·고객 |
| 운영 검증 | 배포, 관측, 백업, 복구 | 운영 |

## 3. 테스트 케이스 필수 필드

테스트 ID, 요구사항 ID, 목적, 사전조건, 데이터, 절차, 기대결과, 실제결과, 증적, 상태, 수행자, 수행일을 기록한다.

## 4. HTML 기준 시안 검증

HTML 시안은 다음 시각 기준에 사용한다.

- 레이아웃, 정보 구조, 문구, 버튼과 상태
- 주요 해상도와 긴 텍스트
- 로딩, 빈값, 오류, 권한 없음
- 모달, 포커스, 배경 스크롤

HTML 시안은 API 정확성, DB 정합성, 보안, 성능 및 접근성 검사의 대체물이 아니다.

## 4.1 산출물별 품질검사 기준서

화면설계서, HTML 시안, DB설계서, 프로세스 정의서, API설계서, 요구사항 정의서와 매뉴얼 등 프로젝트의 각 주요 산출물마다 `templates/qc_docs/05_산출물별품질검사기준서_템플릿.md`를 복제하여 별도 기준서를 만든다.

품질 기준 생성·검수 엔진은 별도의 공통 제품을 의미하지 않는다. 신규 프로젝트 생성 에이전트, 프로젝트 검증 하네스 또는 승인된 품질 작업자가 다음 결정 절차를 실행하는 것을 의미한다.

1. 대상 산출물에서 필수 필드, 타입, 상태, 업무 규칙, 예외와 연결 ID를 추출한다.
2. 실제 정보가 아닌 합성 데이터로 정상, 빈값, 경계, 오류와 권한 사례를 만든다.
3. 각 사례의 기대 결과와 기계적으로 판정 가능한 합격 기준을 작성한다.
4. 대상 산출물을 기준서와 대조하여 `통과 / 실패 / 차단 / 미수행`으로 판정한다.
5. 실패 위치, 근거, 결함 ID와 증적을 기록하고 보완 후 같은 기준으로 재검수한다.

화면설계서와 HTML은 화면 ID·필드·상태·메시지·권한·UI SKILL을, DB설계서는 타입·제약·관계·개인정보·마이그레이션을, 프로세스 정의서는 단계·역할·입출력·규칙·예외를 기준으로 삼는다. 원본 산출물에 없는 요구를 검수 엔진이 임의로 추가하지 않는다.

## 5. 결함 등급

| 등급 | 기준 | 릴리스 |
|---|---|---|
| Blocker | 데이터 손실, 보안사고, 서비스 불능 | 금지 |
| Critical | 핵심 기능 불능, 우회 없음 | 금지 |
| Major | 중요 기능 오류, 제한적 우회 | 책임자 승인 필요 |
| Minor | 영향이 제한된 오류 | 잔여 이슈 등록 가능 |

## 6. 기본 출고 기준

- 승인 요구사항 테스트 100% 수행
- Blocker·Critical 0건
- Major는 원칙적으로 0건
- 핵심 회귀 테스트 통과
- 보안 검사에서 출고 차단 취약점 0건
- 성능 목표 충족 또는 승인된 예외 존재
- 배포·롤백·모니터링 검증 완료
- T1 이상 하네스 필수 시나리오 수행
- T2 이상 종료조건, 한도, 체크포인트, 취소·재개 검증 완료
- T3 드라이런, 운영 경보, 킬 스위치와 복구 검증 완료
- 테스트 증적과 버전 식별 가능

## 7. 시스템 자원 안전

- 무거운 테스트와 모델 적재는 순차 실행한다.
- CPU, 메모리, 디스크, GPU 예상량을 확인한다.
- 실제 운영 데이터 대신 최소 합성 데이터를 사용한다.
- 긴 테스트는 시간 제한과 중단 방법을 둔다.
- OOM 또는 시스템 불안정 징후가 있으면 즉시 중단하고 경량 검증으로 전환한다.
- 검증하지 못한 항목은 통과로 기록하지 않는다.
- 하네스·프롬프트·모델·도구·검증기 버전을 고정하고 증적에 기록한다.
- LLM 자기평가만으로 테스트 통과를 판정하지 않는다.

## 8. 품질 증적

명령, 실행환경, 소스 버전, 시작·종료시각, 결과 요약, 실패 로그, 스크린샷 또는 리포트 경로를 보관한다. 단순히 “정상”이라고 기록하지 않는다.
