# UDS-109 문서 및 기록관리 표준

버전: 1.0.0 | 상태: 검토초안

## 1. 정본 원칙

표준과 승인 산출물은 고정된 정본 경로에서 버전 관리한다. 날짜 폴더는 회의록, 작업기록, 분석, 검토 및 협업 이력에 사용한다. 정본 문서를 날짜별로 복제하여 서로 다른 최신본이 생기지 않게 한다.

## 2. 문서 메타데이터

각 문서는 문서번호, 제목, 버전, 상태, 소유자, 작성자, 검토자, 승인자, 작성일, 시행일, 보안등급을 갖는다.

버전 규칙:

- Major: 절차나 책임이 바뀌는 호환되지 않는 변경
- Minor: 새 항목 또는 의미 있는 확장
- Patch: 오탈자와 의미를 바꾸지 않는 보완

## 3. 파일명

정본: `[문서번호]_[문서명]_v1.0.0.md`  
작업기록: `[에이전트]_[구분]_[작업명]_[YYYY-MM-DD].md`  
협업: `[세션ID]_[에이전트]_[요청|회신]_[작업명]_[YYYY-MM-DD].md`

파일명에 사용할 수 없는 문자와 과도하게 긴 제목을 피한다.

## 4. 프로젝트 기록 폴더

```text
docs/
├── index.md
├── 공통/
├── 기획/
├── 개발일지/YYYY-MM-DD/
├── 계획/YYYY-MM-DD/
├── 분석/YYYY-MM-DD/
├── 검토/YYYY-MM-DD/
├── 협업/YYYY-MM-DD/
├── 기술문서/
└── 아이디어/YYYY-MM-DD/
```

기술문서는 기능 또는 엔진의 정본이므로 날짜 폴더 대신 고정 경로에서 버전을 관리한다.

## 5. 개발진행대장

대장은 다음 필드를 포함한다.

- 일시(KST)
- 세션 ID
- 작성 주체
- 구분: 일반, 요청, 회신, 검토, 계획, 분석, 결과
- 요구사항·결함 ID
- 작업명
- 변경 경로
- 검증 결과
- 상태: 예정, 진행, 완료, 보류
- 승인자 또는 확인자

요청과 회신은 같은 세션 ID를 사용한다.

## 6. 문서 승인과 폐기

초안에는 승인 완료 표현을 사용하지 않는다. 승인본 수정 시 버전을 올리고 변경이력을 기록한다. 폐기 문서는 삭제보다 `폐기` 상태와 대체 문서를 표시하여 과거 결정의 근거를 보존한다.

## 7. 보존과 접근

프로젝트 계약, 법률, 개인정보 및 회사 정책에 따라 보존기간과 접근권한을 정한다. 비밀정보를 일반 문서에 직접 기록하지 않고 안전한 참조 위치만 표시한다.
