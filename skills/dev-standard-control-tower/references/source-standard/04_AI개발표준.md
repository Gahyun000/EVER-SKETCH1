# UDS-104 AI 개발 표준

버전: 1.0.0 | 상태: 검토초안

## 1. 원칙

AI는 생산성을 높이는 실행자이지만 제품 책임자, 승인자 또는 사실의 최종 출처가 아니다. AI의 자율성은 승인된 범위와 검증 가능한 목표 안에서만 허용한다.

## 2. AI 권한 등급

| 등급 | 허용 범위 | 인간 승인 |
|---|---|---|
| A0 제안 | 분석, 초안, 대안 제시 | 모든 결과 검토 |
| A1 제한 실행 | 문서·코드 작성, 정적 검사 | 변경 병합 전 |
| A2 감독 실행 | 정해진 도구로 반복 작업과 테스트 | 외부 영향 전 |
| A3 운영 자동화 | 승인 정책에 따른 자동 처리 | 정책·예외·배포 승인 |

신규 프로젝트 기본값은 A1이다. A3는 입력 범위, 도구 허용목록, 비용·시간·재시도 제한, 감사로그, 중단 장치 및 복구 절차를 검증한 엔진에만 적용한다.

## 3. 개발 AI와 제품 AI의 분리

- 개발 AI: 사람의 설계에 따라 코드와 문서를 작성한다. 업무 규칙을 결정하지 않는다.
- 제품 AI/에이전틱 엔진: 승인된 정책과 도구 범위에서 자율 실행할 수 있다.
- 제품 AI의 자율성이 개발 AI에게 요구사항 변경 권한을 부여하지 않는다.

## 4. 필수 입력 패키지

AI 작업에는 가능한 한 다음을 제공한다.

- 작업 목적과 제외 범위
- 요구사항 ID와 인수조건
- 관련 설계와 Markdown 화면 설계 기준
- 저장소 구조와 수정 허용 경로
- 사용 가능한 도구와 금지 작업
- 테스트 명령과 자원 제한
- 완료 보고 형식

## 5. 판단 금지 영역

AI는 다음을 임의로 확정하지 않는다.

- 고객 의도와 계약 해석
- 법률·규제 준수 여부
- 개인정보 처리 목적과 보존기간
- 결제, 보험, 의료 등 고위험 업무 규칙
- 운영 데이터 삭제 또는 마이그레이션
- 합격 기준과 우선순위 변경
- 근거 없는 숫자, 통계, 표 데이터

## 6. 에이전틱 루프 안전장치

루프를 도입하기 전에 `UDS-111 하네스 및 루프 엔지니어링 표준`에 따라 T0~T3 개발기법을 선정한다. 에이전틱 루프는 반드시 하네스가 상태, 도구, 검증, 승인과 종료조건을 통제하는 T2 또는 T3 구조로 구현한다.

1. 목표와 성공조건을 기계적으로 판정할 수 있어야 한다.
2. 최대 단계, 실행시간, 비용, 토큰, 재시도 횟수를 설정한다.
3. 동일 오류 3회 또는 개선 없는 반복 3회 시 중단한다.
4. 삭제·배포·과금·외부 전송은 승인 체크포인트를 둔다.
5. 도구와 접근 경로는 허용목록 방식으로 제한한다.
6. 각 단계의 입력, 출력, 도구 호출, 오류, 판단 근거를 기록한다.
7. 강제 종료 후 재개 가능한 체크포인트를 둔다.
8. 운영자는 즉시 중지할 수 있어야 한다.

작업자 또는 모델이 자신의 권한, 도구 목록, 비용 한도, 반복 한도와 성공조건을 변경하게 해서는 안 된다.

## 7. AI 생성물 검증

- 코드: 리뷰, 정적 분석, 테스트, 보안 검사
- 문서: 사실성, 버전, 링크, 용어, 승인 상태
- 데이터: 출처, 스키마, 행 수, 합계, 중복, 누락
- 분석: 근거 문서와 인용 위치
- UI: 승인 시안 대비 시각·기능 검증

AI가 스스로 작성한 테스트만으로 완료를 판정하지 않는다. 핵심 요구사항은 사람이 정의한 인수조건으로 검증한다.

## 8. 기록

작업 기록에는 에이전트명, 세션 ID, 요청 요약, 참조 문서, 변경 파일, 실행 명령, 테스트 결과, 승인 필요사항을 남긴다. 프롬프트 전문에 비밀정보가 포함될 수 있으므로 저장 범위를 통제한다.
