# UDS-107 보안 및 개인정보 표준

버전: 1.1.1 | 상태: 검토초안

## 1. 기본 원칙

- 최소 권한과 기본 거부
- 필요 최소한의 데이터 수집
- 저장·전송 구간 보호
- 비밀정보의 코드·로그·문서 분리
- 추적 가능한 관리자 행위
- 검증된 의존성과 공급망
- 보안사고를 전제로 한 탐지와 복구

## 2. 데이터 분류

| 등급 | 예시 | 처리 원칙 |
|---|---|---|
| 공개 | 공개 홈페이지 자료 | 무결성 관리 |
| 내부 | 내부 절차, 비공개 설계 | 승인된 구성원만 |
| 기밀 | 계약, 소스 핵심, 인증정보 | 암호화·접근기록 |
| 개인정보 | 식별자, 연락처, 민감정보 | 목적·동의·보존·파기 통제 |

## 3. AI 사용 제한

- 승인되지 않은 외부 AI 서비스에 내부·기밀·개인정보를 입력하지 않는다.
- 입력 전 마스킹 또는 합성 데이터 전환을 우선한다.
- 모델 제공자의 데이터 보존, 학습 사용, 처리 위치 및 삭제 조건을 확인한다.
- AI 출력에 비밀정보가 재현되는지 검토한다.
- 프롬프트와 응답 로그도 데이터 분류 대상이다.

## 4. 인증과 권한

- 계정 공유를 금지한다.
- 관리자와 일반 사용자 권한을 분리한다.
- 서버는 UI 숨김과 별개로 권한을 검증한다.
- 중요 작업은 재인증 또는 추가 확인을 고려한다.
- 권한 변경, 다운로드, 삭제, 배포 등 중요 행위를 감사 로그에 남긴다.

## 5. 비밀정보

API 키, 비밀번호, 토큰, 인증서 및 개인키를 저장소에 커밋하지 않는다. 비밀 저장소 또는 환경 주입 방식을 사용하고, 노출 시 즉시 폐기·교체한다. 예제 파일에는 가짜 값만 둔다.

## 6. 안전한 구현

- 모든 외부 입력의 형식, 길이, 범위를 검증한다.
- SQL, 명령, HTML, URL 등 사용 맥락에 맞는 안전한 API를 사용한다.
- 업로드 파일은 확장자만 신뢰하지 않고 크기, 형식, 저장경로를 검증한다.
- 오류 응답에 내부 경로, 스택, 쿼리, 비밀정보를 노출하지 않는다.
- SSRF, 경로 탐색, 인젝션, 권한 상승을 위협 모델에 포함한다.

## 7. 공급망

의존성은 공식 출처와 잠금 파일을 사용한다. 신규 도입과 주요 업데이트는 라이선스와 취약점을 검토한다. 설치 스크립트의 임의 코드 실행을 고려하고, 검증되지 않은 패키지를 AI가 자동 설치하지 못하게 한다.

## 8. 사고 대응

노출 또는 침해가 의심되면 추가 변경을 중단하고 증적을 보존한다. 보안책임자에게 보고하고, 키 폐기, 접근 차단, 영향 분석, 통지, 복구 및 재발 방지를 수행한다.

## 9. 하네스 보안

- 외부 문서와 사용자 입력을 명령이나 상위 지시로 취급하지 않는다.
- 모델은 도구 허용목록, 권한, 예산, 반복 한도와 성공조건을 변경할 수 없다.
- 자연어 출력을 쉘·SQL·삭제·배포·외부 전송 명령으로 직접 실행하지 않는다.
- 테넌트·고객·보험사·프로젝트 식별자를 실행 컨텍스트와 모든 도구 호출에서 검증한다.
- 승인 토큰은 대상, 작업, 유효기간과 실행 ID에 결합하고 재사용을 방지한다.
- 로그와 체크포인트에서 비밀정보·개인정보·원문 프롬프트를 최소화하고 마스킹한다.
- 프롬프트 인젝션, 권한 상승, 도구 오용, 데이터 혼입과 비용 폭주를 보안 테스트에 포함한다.
