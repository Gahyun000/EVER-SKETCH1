# UDS-108 배포 및 운영 표준

버전: 1.1.1 | 상태: 검토초안

## 1. 환경 분리

개발, 검증, 운영 환경을 분리하고 설정과 자격증명을 독립 관리한다. 운영 데이터의 개발 환경 복제를 원칙적으로 금지하며 필요 시 승인된 익명화 절차를 사용한다.

## 2. 배포계획

배포계획에는 다음을 포함한다.

- 배포 버전과 변경 목록
- 요구사항·결함·PR 연결
- 대상 환경과 담당자
- 사전 점검과 백업
- 실행 순서와 예상 시간
- DB 변경과 호환성
- 서비스 중단 여부와 공지
- 스모크 테스트
- 관측 지표와 성공 기준
- 롤백 조건과 절차

## 3. 배포 승인

G4 품질 승인 전 운영 배포를 금지한다. 긴급 배포는 승인자, 사유, 영향, 백업 및 복구 방법을 기록하고 배포 후 1영업일 이내에 누락된 문서와 테스트를 보완한다.

## 4. 롤백

롤백은 단순히 이전 코드를 재배포하는 것에 그치지 않는다. DB 스키마, 데이터 변환, 큐 메시지, 캐시, 외부 연계 및 파일 저장소의 호환성을 검토한다. 되돌릴 수 없는 변경은 전진 수정 계획과 백업 복원 조건을 명시한다.

## 5. 관측 가능성

서비스는 최소한 다음을 제공한다.

- 구조화 로그와 추적 ID
- 오류율, 응답시간, 처리량
- CPU, 메모리, 디스크, 큐 등 자원 지표
- 핵심 업무 성공·실패 지표
- 상태 점검 엔드포인트
- 경보 기준, 수신자, 대응 절차

로그에는 비밀번호, 토큰, 전체 주민등록번호, 불필요한 본문 데이터를 남기지 않는다.

## 6. 장애관리

장애 발생 시 탐지, 등급 분류, 임시조치, 원인분석, 복구, 고객 공지, 재발방지 순으로 관리한다. 책임 추궁보다 서비스 복구와 사실 보존을 우선한다.

사후분석에는 타임라인, 영향, 탐지 경로, 직접·근본 원인, 잘된 점, 개선 항목, 담당자와 기한을 기록한다.

## 7. 백업과 복구

데이터 중요도에 따라 RPO와 RTO를 정의하고 백업 성공 여부뿐 아니라 실제 복구 가능성을 정기적으로 검증한다. 백업도 운영 데이터와 동일한 보안 기준으로 보호한다.

## 8. 운영 인수

운영 전 담당자, 연락망, 구성도, 환경변수, 배포·중지·재기동, 모니터링, 장애 대응, 백업·복구, 알려진 제약 및 라이선스를 전달한다.

T3 하네스 또는 운영 자동화가 있으면 다음을 추가로 인수한다.

- 하네스·프롬프트·모델·도구·검증기 버전과 롤백 버전
- 상태 저장소, 체크포인트와 재개 절차
- 실행·반복·비용·검증 실패 대시보드
- 승인 대기, 실패율, 데이터 경계와 비용 급증 경보
- 신규 실행 차단과 진행 실행 중지를 위한 킬 스위치
- 수동 전환, 권한 축소와 복구 훈련 결과
- 모델·도구 변경의 단계적 배포와 드라이런 절차
