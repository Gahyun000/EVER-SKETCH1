# UDS-103 요구사항 및 설계 표준

버전: 1.0.0 | 상태: 검토초안

## 1. 요구사항 작성

각 요구사항은 하나의 검증 가능한 의도를 표현한다.

| 필드 | 설명 |
|---|---|
| ID | `REQ-F-001`, `REQ-NF-001`, `REQ-SEC-001` 형식 |
| 제목 | 짧고 고유한 이름 |
| 출처 | 고객, 법령, 회의록, 내부 정책 |
| 설명 | 행위자, 조건, 동작, 결과 |
| 우선순위 | Must, Should, Could |
| 인수조건 | 관찰·측정 가능한 Given/When/Then 또는 판정식 |
| 예외 | 오류, 빈 값, 권한 없음, 시간 초과 등 |
| 상태 | 초안, 검토, 승인, 구현, 검증, 폐기 |
| 연결 | 화면, API, DB, 코드, 테스트 ID |

`적절히`, `빠르게`, `필요시`, `사용하기 쉽게`처럼 판정할 수 없는 표현은 수치나 조건으로 구체화한다.

## 2. 요구사항 종류

- 기능: 사용자가 수행하는 업무와 시스템 반응
- 비기능: 성능, 가용성, 확장성, 접근성, 호환성
- 데이터: 소유자, 출처, 형식, 품질, 보존, 삭제
- 보안: 인증, 권한, 암호화, 감사, 위협 대응
- 운영: 배포, 모니터링, 장애, 백업, 복구
- 제약: 일정, 기술, 계약, 라이선스, 규제

## 3. 화면 설계

화면별로 목적, 사용자, 진입 조건, 컴포넌트, 상태, 입력 검증, 권한, 메시지, API, 로딩·빈값·오류 상태를 정의한다.

공통 UI 기준:

1. 날짜와 시간은 별도 요구가 없으면 한국 표준시 24시간제로 표시한다.
2. 저장·수정·삭제·실행처럼 영향이 있는 작업은 프로젝트 공통 확인창을 사용한다.
3. 모달은 배경 스크롤, 포커스 이동 및 키보드 접근을 통제한다.
4. 표 셀은 의미 없는 한 글자 세로 배치나 의도치 않은 두 줄 깨짐이 없도록 한다.
5. 목록 화면은 필요한 검색조건, 조회, 페이지 이동, 로딩·빈값·오류 상태를 갖춘다.
6. 목록 행 클릭으로 상세 진입하는 경우 중복된 상세 버튼을 기본 생성하지 않는다.
7. 장시간 분석은 프로젝트 공통 모달에서 실시간 실행 로그, 실행 ID, 진행률, 현재 단계, KST 24시간제 시각, 상태 및 취소 가능 여부를 표시한다. 모달을 닫아도 실행 작업을 임의로 취소하거나 상태를 손상시키지 않는다.
8. 색상만으로 상태를 구분하지 않는다.
9. UI가 있는 프로젝트는 `SKILL/ui-development-standard/SKILL.md`를 필수 적용하며 해당 SKILL의 완료 체크를 통과하지 못하면 화면 구현 완료로 판정하지 않는다.

조회 화면은 시작일, 종료일, 검색어, 조회 버튼과 페이지 이동을 기본으로 한다. 행 클릭으로 상세 화면에 진입하며 중복된 상세보기 버튼은 만들지 않는다.

신규 등록·수정 화면은 필드 정의, 필수값, 클라이언트·서버 검증, 중복 검사, 저장 중 중복 제출 방지, 미저장 변경 경고, 성공 후 이동, 실패 시 입력 보존 및 권한·동시성 오류 처리를 정의한다.

실행·저장·삭제·수정은 프로젝트 공통 버튼과 자체 제작 확인창을 사용한다. 브라우저 기본 `alert`, `confirm`, `prompt`를 업무 확인 절차로 사용하지 않는다.

## 4. HTML 기준 시안

- G2 이전에 주요 화면과 핵심 상태의 HTML 시안을 승인한다.
- 시안은 정상 화면만이 아니라 로딩, 빈 데이터, 검증 오류, 서버 오류, 권한 없음, 긴 텍스트 및 작은 화면을 포함한다.
- 시안의 각 요소를 화면 설계 ID와 연결한다.
- AI는 승인 시안에 없는 메뉴, 필드, 업무 규칙을 임의로 추가하지 않는다.
- 시안 변경은 화면 설계와 요구사항 추적표에 함께 반영한다.

## 5. API 설계

엔드포인트별 목적, 인증, 권한, 요청·응답 스키마, 오류코드, 멱등성, 페이지네이션, 시간 제한, 재시도, 감사로그 및 버전 정책을 정의한다.

오류 응답은 최소한 오류 코드, 사용자 메시지, 추적 ID를 포함하며 내부 스택이나 비밀정보를 노출하지 않는다.

## 6. DB 설계

- 테이블·컬럼의 업무 의미와 소유자를 기록한다.
- 기본키, 외래키, 유일성, NULL, 기본값을 명시한다.
- 금액, 날짜, 시간대, 상태값의 표현을 통일한다.
- 개인정보 여부, 암호화, 마스킹, 보존 및 삭제 정책을 표시한다.
- 스키마 변경에는 전진·후진 호환성과 롤백 방안을 포함한다.
- 샘플 데이터는 익명 또는 합성 데이터만 사용한다.

## 7. 추적성

모든 승인 요구사항은 최소 한 개의 설계 항목과 테스트에 연결되어야 한다. 구현되지 않거나 테스트되지 않은 요구사항은 릴리스할 수 없다. 반대로 요구사항에 연결되지 않은 기능은 제거하거나 변경승인을 받아야 한다.
