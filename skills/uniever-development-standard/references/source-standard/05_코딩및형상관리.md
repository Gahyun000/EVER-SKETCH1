# UDS-105 코딩 및 형상관리 표준

버전: 1.0.0 | 상태: 검토초안

## 1. 저장소 기본

- `README`에 목적, 설치, 실행, 테스트, 환경변수, 배포 개요를 기록한다.
- 의존성 버전은 잠금 파일로 고정한다.
- 환경별 설정과 비밀정보를 코드에서 분리한다.
- 생성 파일, 대용량 모델, 운영 데이터는 저장소 정책에 따라 제외한다.
- 포맷터, 린터, 테스트 및 빌드 명령을 자동화한다.

## 2. 브랜치와 커밋

- 보호 브랜치 직접 변경을 금지한다.
- 브랜치명 예: `feature/REQ-F-001-login`, `fix/BUG-123-timeout`.
- 한 변경은 하나의 목적을 가진다.
- 커밋 메시지는 `type(scope): summary`를 권장한다.
- 커밋 또는 PR에 요구사항·결함 ID를 연결한다.
- 강제 푸시, 히스토리 재작성, 파괴적 복원은 명시적 승인 없이 수행하지 않는다.

## 3. 코드 리뷰

리뷰어는 다음을 확인한다.

- 요구사항과 설계 일치
- 정상·오류·경계 조건
- 권한과 입력 검증
- 데이터 정합성과 트랜잭션
- 예외 처리와 관측 가능성
- 성능과 자원 사용
- 테스트 적절성
- 개인정보·비밀정보 노출
- 불필요한 범위 확대

작성자는 AI 생성 여부와 관계없이 코드의 정확성에 책임진다.

## 4. 구현 원칙

1. 기존 코드베이스의 구조와 명명 규칙을 따른다.
2. 함수와 모듈은 하나의 명확한 책임을 갖는다.
3. 중복 제거보다 이해 가능성과 변경 안전성을 우선한다.
4. 입력 경계에서 검증하고 내부 타입을 명확히 한다.
5. 오류를 삼키지 말고 처리 가능한 형태로 전달한다.
6. 시간대, 통화, 소수점, 인코딩을 명시한다.
7. 네트워크 호출에는 시간 제한과 재시도 정책을 둔다.
8. 재시도 가능한 작업은 멱등성을 고려한다.
9. 외부 서비스는 인터페이스로 격리하고 테스트 대역을 제공한다.
10. 핵심 알고리즘에는 의도와 제약을 설명하는 기술문서를 둔다.
11. AI·자동화·외부 도구 기능은 `UDS-111`에 따라 T0~T3를 선정한다.
12. T1 이상은 입력·출력 계약, 정책, 도구 어댑터와 결정론적 검증기를 모델 호출과 분리한다.
13. T2 이상은 구조화된 상태 머신, 반복 한도, 체크포인트, 취소와 재개를 구현한다.
14. 자유 형식 모델 출력을 쉘, SQL, 파일 삭제, 배포 또는 외부 전송 명령으로 직접 실행하지 않는다.

## 5. 의존성

신규 라이브러리 도입 시 필요성, 대안, 라이선스, 유지보수 상태, 알려진 취약점, 번들·메모리 영향 및 제거 가능성을 검토한다. 자동 설치는 버전이 고정되고 사용자가 승인한 설치 절차 안에서만 수행한다.

## 6. 실행 스크립트

프론트엔드와 백엔드 구현이 완료되면 해당 프로젝트의 실제 기술 스택, 설치 명령, 실행 명령, 환경변수와 포트를 사용하여 다음 원클릭 실행 파일을 프로젝트 안에 작성한다.

- Windows: 더블클릭 가능한 `.bat` 또는 `.cmd` 파일. 필요하면 내부에서 프로젝트용 PowerShell 스크립트를 호출할 수 있다.
- macOS: 실행 권한이 부여된 `.command` 또는 `.sh` 파일

표준 저장소의 범용 예시 파일을 그대로 복사하여 완료 처리하지 않는다. 프로젝트의 실제 프론트엔드·백엔드 실행 명령을 확인한 뒤 생성한다.

실행 파일은 다음을 수행해야 한다.

1. 프로젝트 루트를 기준으로 동작한다.
2. 필수 런타임, 환경파일과 프론트·백엔드 디렉터리를 확인한다.
3. 의존성이 없으면 사용자 승인을 받은 뒤 잠금 파일 기반으로 설치한다.
4. 프론트와 백엔드 포트 사용 여부를 확인하고, 충돌 시 안전한 대체 포트를 선택하거나 명확한 해결 방법을 출력한다.
5. 백엔드와 프론트엔드를 함께 실행한다.
6. 두 서비스의 준비 상태를 확인한다.
7. 준비 완료 후 실제 프론트엔드 주소를 기본 브라우저로 연다. 자동 열기는 설정으로 끌 수 있어야 한다.
8. 로그 위치, 접속 주소, 사용 포트와 종료 방법을 출력한다.
9. 실행기 종료 시 자신이 시작한 하위 프로세스를 안전하게 종료한다.

G3 개발완료 전에 Windows와 macOS 실행 파일을 각각 실제 대상 환경에서 실행 검증한다. 환경을 확보하지 못한 플랫폼은 `미검증`으로 기록하며 검증 없이 완료로 표시하지 않는다.
