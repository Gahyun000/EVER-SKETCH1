# UDS-101 개발 거버넌스 표준

버전: 1.1.1 | 상태: 검토초안 | 소유자: AI팀장

## 1. 목적

프로젝트의 의사결정권, 실행 책임, 검토 책임 및 승인 책임을 분리하여 AI 또는 특정 개인의 독단적 결정을 방지한다.

## 2. 기본 역할

| 역할 | 주요 책임 | 승인 권한 |
|---|---|---|
| 사업책임자 | 사업 목표, 범위, 예산, 최종 인수 | 범위·최종 완료 |
| PM/PO | 요구사항, 일정, 우선순위, 고객 협의 | 요구사항·변경요청 |
| 기술책임자 | 아키텍처, 기술 선택, 품질 기준 | 기술 설계·배포 준비 |
| 개발자 | 구현, 단위 테스트, 기술문서 | 자기 작업 완료 선언 |
| QA | 테스트 설계, 결함 관리, 품질 판정 | 품질 게이트 |
| 보안책임자 | 개인정보·보안·공급망 검토 | 보안 게이트 |
| 운영책임자 | 배포, 모니터링, 장애·복구 | 운영 배포 |
| AI 에이전트 | 승인 문서 기반 작성·분석·검증 지원 | 승인 권한 없음 |

한 사람이 여러 역할을 맡을 수 있으나 L3 프로젝트에서는 개발 완료 판정과 품질 승인을 같은 사람이 단독 수행하지 않는다.

## 3. 의사결정 원칙

- 업무 의미와 고객 요구는 PM/PO가 결정한다.
- 기술 선택은 기술책임자가 근거와 대안을 기록한 후 승인한다.
- 합격 여부는 사전 정의된 인수조건과 테스트 결과로 판단한다.
- AI 제안은 결정이 아니라 검토 대상이다.
- 구두 합의는 회의록 또는 변경요청서에 반영되기 전까지 개발 기준이 아니다.

## 4. 승인 게이트

| 게이트 | 진입 조건 | 승인 기준 | 승인자 |
|---|---|---|---|
| G0 착수 | 목표와 이해관계자 식별 | 범위·역할·등급 확정 | 사업책임자 |
| G1 요구사항 | 회의록과 자료 분석 완료 | 요구사항·인수조건 승인 | PM/PO·고객 |
| G2 설계 | 프로세스·화면·DB·인터페이스·개발기법 작성 | T0~T3 선정, T1 이상 하네스 설계와 요구사항 추적 가능 | 기술책임자·고객 |
| G3 개발완료 | 코드·리뷰·단위테스트 완료 | T1 이상 계약·검증기, T2 이상 상태·한도 구현, 실제 프로젝트용 Windows·macOS 원클릭 실행 파일 작성·검증 | 기술책임자 |
| G4 품질 | 통합·보안·성능·하네스 검증 완료 | 루프·장애·취소·재개 포함 출고 기준 충족 | QA·보안책임자 |
| G5 배포 | 배포·롤백·관측 준비 | T3 드라이런·경보·킬 스위치와 복구 가능성 확인 | 운영책임자 |
| G6 종료 | 인수와 산출물 완료 | 잔여 이슈 합의 | 사업책임자·고객 |

## 5. 변경관리

승인 이후 범위, 업무 규칙, 화면, DB, API 또는 인수조건을 바꾸려면 변경요청서가 필요하다. 변경요청서는 요청자, 사유, 영향, 우선순위, 비용·일정, 설계 변경, 테스트 변경, 승인 여부를 포함한다.

단순 오탈자처럼 동작에 영향이 없는 변경은 작업기록으로 갈음할 수 있다. 판단이 애매하면 변경요청으로 처리한다.

## 6. 예외관리

표준 예외는 다음을 기록하고 기술책임자 승인을 받는다.

- 적용하지 못하는 조항
- 불가 사유
- 위험과 보완 통제
- 적용 기간
- 종료 또는 재검토 일자

편의, 일정 압박 또는 AI의 제안만으로 예외를 허용하지 않는다.

## 7. 완료 기준

- 각 게이트의 승인 증적이 있다.
- 요구사항부터 테스트까지 추적된다.
- 미해결 위험과 책임자가 기록되어 있다.
- 최종 산출물이 정본 위치에 등록되어 있다.
