# UDS-102 프로젝트 수행 절차

버전: 1.1.1 | 상태: 검토초안

## 1. 표준 흐름

### 단계 1. 착수

1. 고객 및 내부 이해관계자 미팅
2. 회의록 작성과 사실 확인
3. 제공 문서·데이터·시스템 분석
4. 범위, 제외 범위, 역할, 일정, 적용 수준 확정
5. G0 착수 승인

필수 산출물: 프로젝트 개요서, 이해관계자 목록, 회의록, 자료목록, 위험 초안

### 단계 2. 요구사항 정의

1. 기능·비기능·데이터·보안·운영 요구사항 작성
2. 요구사항별 ID와 인수조건 부여
3. 우선순위와 릴리스 범위 확정
4. 모순·누락 검토
5. 고객 리뷰 및 G1 승인

필수 산출물: 요구사항 정의서, 용어집, 요구사항 추적표

### 단계 3. 설계

1. 현재 및 목표 프로세스 흐름도 작성
2. HTML 화면 시안과 화면 설계서 작성
3. API·외부 연계·오류 규격 작성
4. 논리·물리 DB 설계와 데이터 사전 작성
5. 보안·권한·로그·운영 설계
6. 기능별 T0~T3 개발기법 선정
7. T1 이상 입력·출력·도구·검증기 하네스 설계
8. T2 이상 상태·종료조건·한도·체크포인트·취소 설계
9. 요구사항과 설계 매핑
10. 고객·기술책임자 G2 승인

Markdown 화면 설계서는 승인된 화면 구조, 문구, 상태 및 상호작용을 표현해야 한다. 표와 ASCII 와이어프레임, 필요 시 Mermaid를 사용하며 실제 운영 데이터나 비밀정보를 포함하지 않는다.

### 단계 4. 개발

1. 작업 단위와 완료조건 확정
2. 브랜치 생성 및 구현
3. 단위 테스트와 정적 검사
4. 코드 리뷰
5. T1 이상 하네스 계약·정책·도구 어댑터·검증기 구현
6. T2 이상 구조화된 상태와 제한 루프 구현
7. 기술문서와 변경기록 갱신
8. 실제 구현에 맞는 Windows·macOS 프론트/백엔드 원클릭 실행 파일 작성
9. 의존성 설치, 포트 충돌, 준비 확인, 브라우저 연결과 종료 동작 검증
10. G3 개발완료 승인

핵심 엔진, 복잡한 알고리즘, 외부 연계, 데이터 마이그레이션은 별도 기술문서를 작성한다.

### 단계 5. 검증

1. 설계 대비 구현 검토
2. 요구사항 기반 기능 테스트
3. 통합·회귀·권한·보안·성능 테스트
4. 하네스 계약·루프·장애·취소·재개·한도 테스트
5. PM 단위 업무 검증
6. 고객 리뷰와 결함 보완
7. G4 품질 승인

### 단계 6. 배포 및 안정화

1. 배포계획과 롤백계획 승인
2. 개발·검증·운영 환경별 배포
3. 스모크 테스트와 관측 확인
4. T3 드라이런, 경보, 킬 스위치와 복구 확인
5. 안정화 기간 결함 처리
6. G5 운영 승인

### 단계 7. 인수 및 종료

1. 사용자·개발자·운영 매뉴얼 확정
2. 요구사항 추적표 최종 점검
3. 잔여 이슈와 유지보수 책임 합의
4. 고객 최종 인수
5. 회고 및 표준 개선사항 등록
6. G6 종료 승인

## 2. 작업 유형별 축소 절차

| 유형 | 생략 가능 | 생략 불가 |
|---|---|---|
| L1 경미 | 별도 화면·DB 설계 | 작업 목적, 영향 확인, 리뷰, 테스트 |
| L2 일반 | 고객 형식의 일부 문서 | 요구사항, 설계, 추적표, 테스트, 배포 |
| L3 중요 | 원칙적으로 없음 | 모든 게이트와 독립 검토 |
| L4 긴급 | 사전 G1~G4 일부 | 승인 기록, 백업, 검증, 사후 문서화 |

## 3. 중단과 재개

문서 부족, 승인 불명확, 보안 위험 또는 시스템 안정성 위험이 발견되면 작업을 중단한다. 재개 조건은 누락 문서 보완, 책임자 결정, 위험 완화 및 변경 범위 재확정이다.
