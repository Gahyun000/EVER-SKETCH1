# 유니에버(주) AI팀 개발표준

문서번호: UDS-000  
버전: 1.1.1  
상태: 검토초안  
기준일: 2026-06-15  
소유부서: 유니에버(주) AI팀

## 1. 목적

본 표준은 AI를 활용하는 소프트웨어 프로젝트가 담당자나 기술 스택에 따라 흔들리지 않도록, 착수부터 종료까지 필요한 문서, 승인, 개발, 검증, 배포 및 운영 기준을 정의한다.

AI는 승인된 요구사항과 설계를 구현하는 수단이다. 요구사항, 업무 규칙, 데이터 의미, 보안 수준 및 최종 합격 여부를 임의로 결정하지 않는다.

## 2. 적용 원칙

1. 요구사항 또는 설계 근거가 없으면 구현을 시작하지 않는다.
2. 누락이나 모순을 발견하면 구현을 중단하고 문서를 먼저 보완한다.
3. 모든 결과는 요구사항 ID, 설계 항목, 코드 변경, 테스트 결과로 추적 가능해야 한다.
4. HTML 화면 시안은 UI 합의 기준이며 기능·보안·성능 합격을 대신하지 않는다.
5. AI가 만든 결과는 인간 책임자가 승인하기 전까지 초안이다.
6. 운영 영향이 있는 작업은 배포, 복구 및 관측 방법을 함께 준비한다.
7. 자동화는 무한 반복, 과도한 자원 사용 및 승인 범위 이탈을 방지해야 한다.

## 4. 표준 적용 순서

1. 프로젝트 책임자가 적용 수준을 정한다.
2. 기능별 개발기법 `T0~T3`를 선정하고 `templates/start_docs`의 필수 산출물을 작성한다.
3. 요구사항과 설계가 승인되면 개발을 시작한다.
4. 구현 중 변경은 변경요청서와 추적표에 반영한다.
5. `templates/qc_docs`의 기준으로 검증한다.
6. 승인된 경우에만 배포한다.
7. 종료 승인 후 `templates/end_docs` 산출물을 확정한다.

빠른 시작에는 [프로젝트 착수 체크리스트](templates/프로젝트착수_체크리스트.md)를 사용한다. 반복 AI 작업은 [SKILL 템플릿](SKILL/SKILL_템플릿.md)으로 실행 한도와 승인 지점을 먼저 정의한다. UI가 포함된 프로젝트는 [UI 개발 표준 SKILL](SKILL/ui-development-standard/SKILL.md)을 필수 적용한다.

개발기법에 따라 완성형 표준 SKILL을 선택한다.

- T1: [하네스 엔지니어링 표준 SKILL](SKILL/harness-engineering-standard/SKILL.md)
- T2·T3: 하네스 엔지니어링 표준 SKILL과 [하네스 기반 루프 엔지니어링 표준 SKILL](SKILL/harness-loop-engineering-standard/SKILL.md)을 함께 적용

신규 프로젝트 전체 문서와 HTML 기준 시안을 자동 생성할 때는 [신규 프로젝트 생성 마스터 프롬프트](PROMPTS/신규프로젝트_생성_마스터프롬프트.md)를 사용한다.

AI, 자동화, 외부 도구 또는 반복 실행이 포함된 기능은 [개발기법 선정서](templates/start_docs/14_개발기법선정서_템플릿.md)로 T0~T3를 결정한다. T1 이상은 [하네스 설계서](templates/start_docs/15_하네스설계서_템플릿.md)와 [하네스 검증 체크리스트](templates/qc_docs/04_하네스검증체크리스트.md)를 적용한다.

## 5. 적용 수준

| 수준 | 적용 대상 | 최소 의무 |
|---|---|---|
| L1 경미 | 문구, 단순 설정, 영향이 제한된 수정 | 작업기록, 검토, 기본 테스트 |
| L2 일반 | 일반 기능, API, 화면, 배치 변경 | 요구사항, 설계, 코드리뷰, 테스트, 배포계획 |
| L3 중요 | 개인정보, 결제, 핵심 엔진, 대외 서비스 | 전체 게이트, 보안검토, 성능검증, 롤백훈련 |
| L4 긴급 | 장애·보안사고의 긴급 복구 | 선조치 승인, 증적 보존, 1영업일 내 사후 문서화 |

## 6. 정본과 변경

- 정본은 본 저장소의 `standards/` 문서다.
- 프로젝트별 기록은 날짜 폴더에 보관하되 정본을 복제하여 별도 규칙으로 변형하지 않는다.
- 표준 변경은 변경 사유, 영향 분석, 승인자, 시행일 및 이전 버전과의 차이를 기록한다.
- 상태는 `초안`, `검토중`, `승인`, `폐기` 중 하나로 표시한다.

## 7. 즉시 중단 조건

다음 중 하나가 발생하면 구현 또는 자동 실행을 중단한다.

- 승인된 요구사항과 현재 지시가 충돌한다.
- 업무 규칙, 데이터 정의 또는 인수조건이 둘 이상으로 해석된다.
- 개인정보·비밀정보 노출 가능성이 확인된다.
- 삭제, 대량 변경, 운영 배포 등 복구가 어려운 작업에 승인이 없다.
- 테스트가 시스템 안정성을 해칠 가능성이 있다.
- AI 실행이 정해진 횟수, 시간, 비용 또는 자원 한도를 초과한다.
