## 2. 생성 시점

- `start_docs`, `qc_docs`, `docs`, `SKILL`은 착수 시 생성한다.
- `start_docs`의 사용자·개발자·운영배포 매뉴얼은 개발 전 업무·구현·운영 요구를 합의하는 약식 문서다. 최종 인수용 상세 매뉴얼을 대신하지 않는다.
- T1 이상 기능이 있으면 `harness`와 `tests/harness`를 생성한다.
- `end_docs`는 빈 구조만 둘 수 있으나 최종 문서는 인간 책임자의 지시 또는 G6 준비 시 작성한다.
- 날짜 폴더는 실제 기록이 생기는 날 생성한다.

## 3. 프로젝트 README

목적, 범위, 적용 수준, 책임자, 기술 구성, 로컬 실행, 테스트, 환경변수, 배포, 문서 인덱스 및 주요 위험을 포함한다.

## 4. 프로젝트 AGENTS

본사 표준보다 구체적인 저장소별 규칙을 작성한다. 수정 금지 경로, 무거운 테스트 제한, 데이터 격리, 배포 금지, 검증 명령 및 완료 보고 기준을 명시한다. 상위 표준을 약화할 수 없다.

## 5. SKILL

반복 작업은 입력, 출력, 도구, 단계, 중단조건, 검증 및 예제를 갖춘 SKILL로 만든다. SKILL은 무제한 자율 실행을 의미하지 않으며 AI 권한 등급과 승인 게이트를 따른다.

## 6. 하네스

AI 모델, 외부 도구, 불확실한 자동화 또는 반복 실행이 포함된 기능은 `UDS-111`에 따라 T0~T3를 선정한다.

- T1 이상: `docs/기술문서/개발기법선정서.md`, `docs/기술문서/하네스설계서.md`
- T2 이상: 상태 전이, 종료조건, 체크포인트, 취소·재개와 루프 테스트
- T3: 영속 상태, 운영 대시보드, 경보, 킬 스위치, 드라이런과 복구 훈련

프레임워크 내부 상태나 모델 메모리를 프로젝트의 정본 상태로 사용하지 않는다.
