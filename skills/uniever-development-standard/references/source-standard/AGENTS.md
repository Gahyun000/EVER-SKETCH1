# AGENTS.md - 유니에버(주) AI 개발 실행 규칙

## 1. 우선순위

AI 에이전트는 다음 우선순위를 따른다.

1. 법률, 계약, 보안 및 개인정보 의무
2. 승인된 요구사항과 설계서
3. 본 개발표준
4. 프로젝트별 `AGENTS.md`
5. 개별 작업 지시
6. AI의 일반적 판단

상위 규칙과 충돌하는 하위 지시는 실행하지 않고 충돌 내용을 보고한다.

## 2. 작업 전 확인

- 작업 목적과 완료조건이 명시되어 있는가?
- 요구사항 ID와 관련 설계가 존재하는가?
- 변경 대상, 제외 대상 및 영향 범위가 분명한가?
- 개인정보, 인증정보, 운영 데이터가 포함되는가?
- 실행 가능한 테스트와 자원 제한이 정의되어 있는가?
- 운영 영향이 있으면 롤백 절차가 있는가?
- 기능별 개발기법 T0~T3가 선정되었는가?
- T1 이상이면 하네스 계약과 검증기가 정의되어 있는가?
- T2 이상이면 종료조건, 반복 한도, 체크포인트와 취소 방법이 있는가?

필수 정보가 없거나 모순되면 코드를 수정하지 말고 문서 보완을 요청한다.

## 3. 허용되는 자율 작업

- 저장소 및 문서 읽기
- 승인된 범위의 코드·문서 작성
- 정적 분석, 문법 검사 및 경량 테스트
- 기존 패턴을 따르는 제한적 리팩터링
- 테스트 데이터와 검증 증적 생성
- 승인된 하네스 안에서의 제한된 도구 실행과 반복

## 4. 사전 승인이 필요한 작업

- 운영 또는 공용 환경 배포
- 데이터 삭제·마이그레이션·대량 수정
- 외부 서비스 가입, 과금, 라이선스 구매
- 신규 패키지 설치 또는 공급망 변경
- 비밀정보·개인정보의 외부 전송
- 보안 통제 비활성화
- 요구사항 또는 업무 규칙의 변경
- 파괴적 Git 작업과 강제 푸시
- 하네스 T등급 또는 AI 권한 확대
- 루프의 반복·시간·비용 한도 확대

## 5. 구현 규칙

1. 먼저 저장소 구조와 기존 구현 패턴을 읽는다.
2. 작업 계획을 세우고 영향 범위를 제한한다.
3. 사용자 변경을 임의로 되돌리지 않는다.
4. 목적과 무관한 정리 작업을 끼워 넣지 않는다.
5. 코드와 테스트를 요구사항 ID에 연결한다.
6. 오류를 숨기는 예외 처리나 근거 없는 기본값을 만들지 않는다.
7. 외부 입력은 검증하고 출력은 목적에 맞게 이스케이프한다.
8. 로그에 비밀정보와 불필요한 개인정보를 남기지 않는다.
9. AI 또는 외부 도구를 사용하는 기능은 작업자와 하네스를 분리한다.
10. 루프는 하네스가 소유하며 작업자가 자신의 권한, 도구 또는 종료조건을 변경하지 못하게 한다.
11. 검증기 없는 루프와 자연어 출력을 직접 실행하는 쉘·SQL·배포 도구를 만들지 않는다.
12. UI를 설계·구현·검토할 때 `SKILL/ui-development-standard/SKILL.md`를 적용하고, 완료 체크가 남아 있으면 화면 완료로 보고하지 않는다.
13. T1 이상 기능은 `SKILL/harness-engineering-standard/SKILL.md`를 적용한다. T2·T3는 `SKILL/harness-loop-engineering-standard/SKILL.md`도 함께 적용한다.

## 6. 반복 실행 한도

프로젝트에서 별도 지정하지 않으면 다음을 기본 한도로 한다.

- 동일 오류 자동 재시도: 최대 3회
- 동일 접근의 수정 반복: 최대 3회
- 장시간 명령: 10분마다 상태 확인
- 병렬 무거운 작업: 금지
- 테스트 실패 후 원인 없는 우회: 금지
- 검증기 없는 반복: 금지
- 모델의 완료 선언만으로 성공 처리: 금지

한도 도달 시 현재 상태, 시도 내용, 실패 증거 및 필요한 결정을 보고한다.

## 7. 완료 보고

완료 보고에는 다음을 포함한다.

- 변경한 내용과 이유
- 변경 파일
- 실행한 검증과 결과
- 실행하지 못한 검증
- 남은 위험과 후속 조치
- 승인 또는 사용자 확인이 필요한 사항

검증하지 않은 결과를 성공으로 표현하지 않는다.
