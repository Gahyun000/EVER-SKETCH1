팀 관리 — 표준 조회 화면

시안 v2.0 · 2026-09-04 · 검토용. 아직 코드에 넣지 않았습니다.
색 표시는 검토용입니다 — 실제 화면에는 안 들어갑니다. 기본으로 꺼 두었고, 아래 「검토용: 칸 경계」로 켜 보실 수 있습니다.

1. default_skill 표준에 미달했던 점

docs/표준지침/유니에버_공통표준개발지침서_체크리스트.md 의 공통 UI 기준을 다시 읽었습니다. 제가 만든 검색은 네 군데가 표준에 못 미쳤습니다.

표준 문구v1.9 는v2.0 에서
① 「조회 화면은 시작일, 종료일, 검색어, 조회 버튼과 페이지 이동을 기본으로 한다」 검색칸 하나뿐. 날짜도 조회 버튼도 페이지도 없었다 표준 조회줄을 그대로. 「내 이북」 화면과 같은 모양
② 「목록 화면은 … 로딩·빈값·오류 상태를 갖춘다」 셋 다 없었다 아래 ③에서 눌러서 확인
③ 「시안은 정상 화면만이 아니라 로딩, 빈 데이터, 검증 오류, 서버 오류, 권한 없음, 긴 텍스트 및 작은 화면을 포함한다」 정상 화면만 보여드렸다 상태 전환 버튼으로 전부
④ 「색상만으로 상태를 구분하지 않는다」 주황 배경 + 주황 배지. 글자(「아직 팀이 없는 사람」)가 함께 있어 통과는 하지만, 「팀 삭제」 비활성은 흐림 + 툴팁뿐이었다 비활성 이유를 글자로 함께 적는다
표준이 이미 말하고 있던 것 하나 — 「표 셀은 의미 없는 한 글자 세로 배치나 의도치 않은 두 줄 깨짐이 없도록 한다」. 대표님이 계속 짚으신 「두줄이슈」가 표준 문구로 적혀 있었습니다. 제가 먼저 챙겼어야 했습니다.

3. 검색이 달라진 점

무엇을어떻게 · 왜
①「조회」 버튼을 눌러야 걸린다 v1.9 는 치는 대로 걸렀습니다. 표준은 조회 버튼을 요구합니다. 서버에 물어보는 화면이 되면 글자마다 요청이 나가고, 무엇보다 「내 이북」 화면과 손놀림이 달라집니다. 같은 제품에서 검색이 두 가지로 동작하면 안 됩니다. 엔터로도 걸립니다.
②시작일 ~ 종료일 사람의 가입일로 거릅니다. 팀은 그릇이라 날짜로 거르지 않습니다. 쓸모: 「이번 주 승인한 사람들만 골라 팀에 넣기」 — L1 이 실제로 하는 일입니다.
③개수 · 페이지 「전체 4명 · 1/1 페이지 · 20명씩」. 「내 이북」과 같은 자리·같은 문구입니다. 묶음(그룹)이 있어도 세는 단위는 사람입니다.
④초기화 날짜·검색어를 한 번에 비웁니다. 표준 조회줄의 짝입니다.
⑤맞은 글자에 표시 v1.9 에서 넣은 노란 칠은 그대로 둡니다 — 왜 걸렸는지 글자로 알려주는 장치라 「색상만으로 구분하지 않는다」에도 맞습니다.
날짜 칸이 이 화면에 정말 필요한지는 대표님이 판단해 주세요. 표준은 조회 화면의 기본으로 요구하고, 「이번 주 가입자 배정」이라는 쓸모도 있습니다. 다만 사람이 10~20명뿐이면 거의 안 쓰는 칸이 둘 늘어나는 것이기도 합니다. 빼신다면 「필요한 검색조건」으로 판단한 승인된 이탈로 작업대장에 적어 두겠습니다 — 표준을 몰라서 뺀 것과 알고 뺀 것은 다릅니다.
