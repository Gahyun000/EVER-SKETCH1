ebook_html · 5차 기획안

구글 슬라이드형 편집기 + HWP(한글), 그리고 "HTML을 편집 가능한 덱으로"

ebook_html을 구글 슬라이드처럼 슬라이드를 편집하는 도구로 재설계한다. HTML 가져오기는 html_pdf_agent의 깔끔한 덱 변환을 그대로 써서, 미리보기를 거쳐 메인 캔버스에 편집 가능한 PPT로 들어온다. 기존 자유 캔버스 도구와 이북/문서 기능은 살리고, 부족한 문서 편집은 HWP(한글) 기능으로 채운다.

작성 2026-07-29 (KST) · 선행 문서: 2·3·4차 기획서 · 참조 목업: docs/에디터_목업.html

1배경 · 목표

왜 5차인가

4차까지의 임포터는 HTML을 카드/블록으로 가져왔지만, ① 긴 섹션이 (2)(3)으로 쪼개져 목차가 지저분하고, ② 결과 디자인이 우리 표지틀 덱만큼 깔끔하지 않았다. 한편 html_pdf_agent가 같은 계열/일반 HTML을 표지틀 덱(PPTX)으로 깔끔하게 뽑는 것이 검증됐다. 5차는 그 변환을 ebook_html로 들여오고, 편집 경험 자체를 구글 슬라이드 + HWP 수준으로 끌어올린다.

목표 A
편집 가능한 PPT
캔버스에서 글자·도형을 구글 슬라이드처럼 직접 수정.
목표 B
깔끔한 가져오기
html_pdf_agent 덱 변환을 그대로 사용(분할·중복 없음).
목표 C
HWP(한글) 편집
글자·문단모양·글맵시·표·맞춤법 등 문서 편집 보강.
원칙
기존 기능 유지
자유 캔버스 도구·이북/문서 기능은 없애지 않는다.

2핵심 흐름 — 가져오기

변환 → 미리보기(사람 확인) → 메인 캔버스 반영
1 · 가져오기
HTML 선택
파일 선택 + 테마(라이트/다크)
→
2 · 변환
덱으로 변환
서버 /api/deck (extractor→deck_builder→PPTX·썸네일)
→
3 · 미리보기(모달)
확인 · 다운로드
슬라이드 미리보기 + PPTX·PDF 다운로드(모달 안)
→
4 · 사람 확정
"메인 캔버스로 가기"
버튼을 눌러야 캔버스에 반영
→
5 · 캔버스
편집 가능 요소
덱 레이아웃을 편집 요소로 로드
현재는 4단계에서 이미지 슬라이드가 캔버스에 들어가 수정이 안 된다. 5차의 핵심은 이를 편집 가능한 요소(텍스트박스·카드·꼬리)로 바꾸는 것이다. 상단 자동 다운로드 링크는 제거하고 다운로드는 미리보기 모달로 모은다.

6구현 로드맵

1
가져오기 흐름 정리 다음
미리보기 모달 복원(다운로드 모달 안) + "메인 캔버스로 가기" 버튼 · 상단 자동 다운로드 링크 제거 · 발표→슬라이드쇼 · 폰트 프리셋 제거.
2
우측 속성 패널 예정
선택 요소의 글자모양·문단모양(HWP) · 레이아웃·테마(구글 슬라이드) 편집 패널 + 아이콘 열.
3
덱 IR → 편집 요소 로드 예정
deck_builder가 아는 좌표로 각 슬라이드를 편집 가능한 요소(텍스트박스·카드·꼬리)로 캔버스에 로드. "덱 디자인 그대로 + 수정 가능".
4
HWP 기능 심화 예정
글맵시·표·각주·개요·맞춤법 등 우선순위 정해 순차 추가.

7리스크 · 다음 결정

  • 편집 요소 재현 정밀도 — 덱 레이아웃을 편집 요소로 옮길 때 폰트·줄바꿈 차이. deck_builder 좌표를 그대로 쓰면 최소화.
  • HWP 우선순위 — 글맵시·표 계산·개요·각주 중 무엇을 먼저? (사용자 결정 필요)
  • 캔버스 비율 — 세로 이북(3:4) 기준. 가로 덱 지원 시 레이아웃 재계산 필요.
  • LibreOffice 의존 — 미리보기·PDF는 soffice 필요. 없으면 편집 페이지로 폴백.
