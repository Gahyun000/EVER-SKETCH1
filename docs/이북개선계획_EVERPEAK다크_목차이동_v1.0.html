  • 라이트/다크를 문서 단위로 선택 — 라이트는 EVER-PEAK 솔루션소개, 다크는 그 다크판과 동일 계열
  • 목차가 책 안의 정돈된 페이지로 들어가고, 항목·페이지번호를 누르면 정확히 이동 (뷰어·PDF 어디서든)

1배경 & 목표

왜 ebook_html인가. 원래 이북은 제가 만든 PPT 틀을 슬라이드 하나하나 고쳐 만들었고, 그게 번거로워서 "틀을 편하게 수정해 이북으로 뽑는 도구"로 ebook_html을 만들었습니다. 그 방향은 유지합니다.

기준 디자인. 가장 잘 나온 형태는 EVER-PEAK_솔루션소개_다크입니다. 다크 배경 · 파랑 강조(#2462EB) · CONTENTS / OPPORTUNITY 같은 영문 키커 · 번호칩 목차 · EVER-PEAK · UNIEVER · 02 / 23 푸터가 특징이고, 목차의 항목·페이지번호가 실제로 눌립니다.

이번 목표(한 문장). ebook_html에서 만든 이북을 EVER-PEAK 라이트/다크 중 골라 그 모양으로 뽑을 수 있고, 그 목차가 책 안에서 자연스럽게 · 클릭하면 이동하게 만든다. 목차 이동은 편집 도구 안이 아니라 완성된 이북이 열리는 모든 곳(플립 뷰어 · 내보낸 PDF)에서 작동해야 한다.

테마는 다크 전용이 아니다. 기준은 두 개다 — 라이트 = EVER-PEAK_솔루션소개, 다크 = EVER-PEAK_솔루션소개_다크(같은 레이아웃, 색만 반전). 사용자가 문서를 만들 때 라이트/다크를 고를 수 있어야 한다. 좋은 소식: 코드에 라이트/다크 재료가 이미 흩어져 있어(아래 §3.4) 새로 만드는 게 아니라 모아 잇는 작업이다.

2현황 진단 — 지금 이북이 만들어지는 흐름

실제 코드를 따라간 결과입니다. 근본 원인은 "이미지 평탄화" 한 곳에 있습니다.

ebook_html 편집(React 카드)
  └▶ exportBook.ts : 각 페이지를 PNG로 굽는다 (html-to-image) — 목차도 00. 목차.png로 평탄화
     └▶ server/app.py · /api/build : PNG들을 _build_input/<ts>/에 저장 → generator.py build 호출
        └▶ uniever_ebook/ebook-generator/generator.py : 이미지들을 묶어 플립 뷰어 생성
           └▶ ebooks/<id>/index.html + flip.js : 이게 "열리는 이북"

2.1 목차가 안 눌리는 진짜 이유

목차 페이지도 다른 페이지처럼 통째로 PNG 그림이 됩니다. 그림 속 글자는 클릭이 안 되므로, 뷰어가 목차를 눌리게 하려면 "이 사각형 영역을 누르면 몇 페이지로 간다"는 좌표(핫스팟)가 별도로 필요합니다. generator.py는 이 좌표를 두 경로로 얻습니다:

경로동작신뢰도
_hotspots.json정확한 좌표 파일이 있으면 그대로 사용 (우선순위 1위)높음 · 확정적
_auto_hotspots파일이 없으면 목차 PNG를 OCR해서 글자를 본문 제목과 맞춰 좌표를 추측낮음 · 자주 실패

지금 ebook_html은 _hotspots.json을 만들어 주지 않으므로 항상 OCR 추측 경로로 떨어집니다. generator.py 주석에도 남아 있듯 "목차 줄과 본문 제목이 맞지 않아 자동 링크를 만들지 못했습니다" 같은 실패가 나면 링크가 아예 없거나 엉뚱하게 붙습니다. 이사님이 보신 "위에 어정쩡하게 불러와지는" 현상이 이 계열입니다.

2.2 다크가 아닌 이유

목차 카드를 그리는 src/cards/PageView.tsx는 흰 배경 · 회색 글자(#3a4150)로 되어 있고, 색 토큰(src/design/tokens.ts)은 라이트 팔레트뿐입니다(다크 세트 없음). 뷰어 flip.css도 밝은 크롬입니다. 그래서 EVER-PEAK 다크의 느낌이 나지 않습니다.

제약 하나 — uniever_ebook 불변 계약.
쉽게 말하면: uniever_ebook은 이북을 실제로 찍어내는 공용 인쇄기(엔진 generator.py + 뷰어 flip.js/flip.css)이고 다른 이북들도 다 같이 씁니다. ebook_html은 그 인쇄기에 원고를 잘 넣어주는 편집 도구일 뿐, "인쇄기 자체는 뜯어고치지 않는다"가 이 프로젝트가 정해둔 규칙입니다(src/export/contract.ts에 명시). 인쇄기를 건드리면 그걸 같이 쓰는 다른 이북이 깨질 수 있어서요.

그래서 "충돌"이란: 다크는 두 겹입니다. ① 페이지(종이) 자체를 어둡게 — 다크 PNG를 구워 넣으면 되니 인쇄기 안 건드림, 충돌 없음. ② 뷰어 겉면(툴바·바깥 여백)까지 어둡게 — 이 색은 인쇄기 안의 flip.css가 정하므로 여길 고쳐야 함 = 인쇄기를 뜯는 것 = 계약과 충돌.

목차 클릭 이동은 충돌 없음(_hotspots.json만 넣으면 됨). 걸리는 건 딱 하나 — "다크일 때 뷰어 겉면까지 어둡게 할지"이며, §4의 D1·D4에서 결정합니다.

3해결 설계 — 빠진 고리 하나만 잇는다

권장안: ebook_html이 목차를 그릴 때 좌표를 같이 계산해 _hotspots.json으로 내보낸다. 뷰어는 손대지 않는다.

3.1 데이터 흐름 (개선 후)

ebook_html 목차 카드(다크 디자인)로 렌더 → PNG로 굽기
  + 각 목차 항목의 화면 좌표(비율)와 대상 seq를 함께 계산
  └▶ /api/build 페이로드에 hotspots[] 추가 → app.py가 _build_input/<ts>/_hotspots.json으로 저장
     └▶ generator.py가 OCR 대신 이 정확한 좌표를 사용 (기존 코드 그대로)
        └▶ flip.js가 항목마다 클릭 버튼을 깔고, 누르면 해당 페이지로 이동

3.2 좌표 계약 (이미 정해져 있음 — 여기에 맞추기만)

generator.py의 _load_hotspots가 읽는 형식입니다. 좌표는 페이지 대비 0~1 비율:

{
  "hotspots": [
    // 목차 "01 기회 …… 03" 줄을 누르면 seq=1 페이지로 이동
    { "seq": 1, "x": 0.06, "y": 0.34, "w": 0.88, "h": 0.07, "label": "기회" },
    { "seq": 2, "x": 0.06, "y": 0.42, "w": 0.88, "h": 0.07, "label": "해결" }
  ]
}

ebook_html은 목차 레이아웃을 직접 그리므로 각 줄의 x/y/w/h를 정확히 산출할 수 있습니다. (예: 목차 <li>의 getBoundingClientRect()를 페이지 컨테이너 크기로 나눠 비율화.) OCR 불필요 · 100% 정확.

3.3 목차·카드 디자인을 EVER-PEAK 라이트/다크 프리셋으로

PageView.tsx의 toc 카드를 EVER-PEAK 스펙으로 다시 그립니다: 영문 키커 CONTENTS, 번호칩(01·02…) + 항목명 + 한 줄 설명 + 우측 페이지번호, 하단 EVER-PEAK · UNIEVER · 02 / 23 푸터. 이때 색은 하드코딩하지 않고 테마 토큰에서 읽어, 같은 목차 컴포넌트가 라이트/다크 양쪽으로 렌더되게 합니다.

tokens.ts에 라이트/다크 두 세트를 두고 문서 단위 theme 값('light' | 'dark')으로 전환합니다. 목차뿐 아니라 표지·본문·콜아웃 카드가 모두 이 토큰을 참조하도록 통일합니다.

토큰라이트 (EVER-PEAK 솔루션소개)다크 (EVER-PEAK 다크)
페이지 배경#ffffff#0e1c30
제목/본문 글자#111318#ffffff / #c9d6e6
강조 파랑#2462EB#7db4ff
보조/구분선#5b6270 / #e6e8ee#8ea3bd / #23364f

※ 값은 코드에 이미 있는 LIGHT/DARK(deckToPages.ts) 팔레트를 기준으로 삼고, EVER-PEAK 원본과 대조해 M1에서 확정합니다.

3.4 이미 있는 재료 (새로 만들지 않고 모아 잇기)

라이트/다크는 맨땅이 아닙니다. 아래를 표준으로 승격·통합합니다:

위치현재 상태이번에 할 일
deckToPages.tsLIGHT/DARK 팔레트 + theme==='dark' 분기 존재이 팔레트를 tokens.ts 공용 테마로 승격
TopBar/ClassicBar.tsx덱 임포트용 라이트/다크 토글 존재(/api/deck로만 전달)이북 문서 테마 선택으로 확장·연결
RightPanel/MenuBar.tsx페이지 단위 배경 라이트/다크 핀 존재문서 기본 테마 아래의 페이지 예외로 정리
PageView.tsx노트·콜아웃엔 다크 분기 있음, 목차 카드엔 없음목차 포함 전 카드가 테마 토큰 참조
export/build 경로테마 값이 전달 안 됨선택 테마를 export→build까지 관통(핫스팟엔 무관)

3.5 목업 → 실제 컴포넌트 이식 지도

승인된 목업(docs/이북목업_EVERPEAK_라이트다크_목차이동.html)의 각 조각이 어느 실제 파일로 옮겨지는지의 대응표입니다. 새 디자인을 짜는 게 아니라 목업을 그대로 컴포넌트화합니다.

목업의 조각이식 대상 (ebook_html)이식 방식
:root / html.dark 색 변수src/design/tokens.ts라이트/다크 두 토큰 세트로 이식, theme로 전환
목차 페이지(tocHTML) — 키커·번호칩·설명·페이지번호src/cards/PageView.tsx (toc)하드코딩 라이트 목차를 목업 마크업으로 교체, 색은 토큰 참조
본문 카드(sectionHTML) — 키커·타이틀·번호카드·PASS박스src/cards/PageView.tsx (content)콜아웃/카드 스타일을 목업과 일치, 테마 대응

라이트/다크 토글TopBar.tsx · state/store.ts기존 덱 토글을 문서 테마 상태로 승격(§3.4)
목차 행 data-goto 클릭exportBook.ts → _hotspots.json목업의 클릭 = 실제로는 §3.2 핫스팟 좌표로 구현(M2)

※ 목업은 순수 HTML/JS 데모라 그대로 붙지는 않습니다. "화면·상호작용의 확정 스펙"으로 쓰고, React 컴포넌트/토큰 구조에 맞게 옮깁니다.

권장안 A — 다크 이미지 + 정확 핫스팟

  • 목차를 EVER-PEAK 다크 그대로 PNG로 굽고, 좌표를 _hotspots.json으로 동봉
  • 뷰어(uniever_ebook) 수정 0 → 불변 계약 완전 준수
  • 디자인 픽셀 100% 재현 + 클릭 확정

대안 B — 뷰어의 텍스트 목차 강화

  • flip.js엔 데이터 기반 텍스트 목차(tocPageHTML)도 이미 있음 (선택 가능·검색 유리)
  • 다만 EVER-PEAK 다크 룩으로 만들려면 flip.js/flip.css 수정 필요 → 불변 계약과 충돌
  • 2단계 개선 후보로 보류

→ 권장: A안. 계약을 지키면서 디자인·클릭을 동시에 만족합니다. B안은 후속(검색·접근성 강화) 여지로 남깁니다.

4결정 사항 (확정)

2026-08-10 확정 — 모든 결정이 정해져 M0부터 바로 착수 가능합니다.

✔ D3 확정 — 테마는 문서 단위 선택. 라이트(EVER-PEAK 솔루션소개)/다크(EVER-PEAK 다크)를 문서 통째로 고릅니다. 페이지별 예외는 2단계 후보로 보류.
D2 — 착수 M0에서 규명 (결정 아님). "위에 불러와지는" 목차가 ebook_html 자동 삽입 목차 카드 문제인지 뷰어 ☰ 목차 버튼 UX 문제인지, M0에서 화면으로 재현해 특정한 뒤 정돈합니다.
참고 — 대비가 거슬릴 경우의 절충안(계약 유지). 밝은 뷰어 안 다크 페이지의 경계가 세 보이면, ① 다크 이북 페이지에 옅은 테두리/그림자를 줘 경계를 부드럽게(ebook_html 쪽, 계약 준수), 또는 ② 나중에 뷰어 배경만 중간 톤으로 바꾸는 최소 예외를 별건으로 검토. 지금 확정에는 포함하지 않음.

5작업 계획 (마일스톤)

각 단계는 독립적으로 눈으로 확인 가능한 산출물을 냅니다.

M0현상 재현 & 기준 고정필수
EVER-PEAK 다크 원본과 AX 사업모델 이북을 나란히 열어 "좋은 목차 / 나쁜 목차"를 화면으로 특정(D2). 기준 목차 페이지의 좌표·색·타이포를 수치로 확정. 산출: 비교 스크린샷 + 목차 스펙 표.
M1라이트/다크 테마 토큰 & 목차 카드 디자인핵심
승인된 목업(docs/이북목업_EVERPEAK_라이트다크_목차이동.html)을 그대로 이식한다(§3.5 대응표). tokens.ts에 라이트/다크 두 세트 정리(§3.3~3.4), PageView.tsx 목차·본문·표지 카드를 목업 마크업으로 재구성하되 색은 테마 토큰에서 읽게 함. 산출: 편집기 미리보기가 목업과 육안 동일 · 같은 목차가 라이트/다크로 각각 렌더.
M1.5문서 테마 선택 UI & 관통필수
이북 만들 때 라이트/다크 선택(기존 토글 재사용)을 문서 테마로 승격하고, 그 값을 export→/api/build까지 전달. 산출: 토글만 바꿔 라이트 이북 / 다크 이북이 각각 생성됨.
M2핫스팟 좌표 산출 & 내보내기필수
exportBook.ts에서 목차 각 항목의 비율 좌표+대상 seq 계산 → /api/build 페이로드에 hotspots[] 추가. app.py가 _hotspots.json으로 기록. 산출: 생성된 이북에서 목차 클릭 → 정확히 이동.
M3목차 UX 정돈 (뷰어 무수정)핵심
D1=(a) 확정에 따라 뷰어 크롬은 손대지 않습니다(uniever_ebook 무수정). "위에 불러와지는" 목차 동작 정리(M0의 D2 결과 반영), ☰ 목차 버튼 일관화, 필요 시 다크 페이지에 옅은 테두리로 경계 마감(§4 절충안 ①). 산출: 목업과 육안 동등한 완성 이북.
M4검증 & 회귀필수
아래 §6 체크리스트로 실제 클릭·이동을 눈으로 확인. 기존 라이트 이북이 깨지지 않는지 회귀 확인 (e2e/ 스모크 활용). 산출: 검증 증적(스크린샷·GIF).
M5HTML 임포트 → 목차 자동 감지 → 카드구현 완료
이사님 실제 워크플로우(다양한 HTML 가져오기). 가져온 HTML을 통짜 이미지가 아니라 표지 + 목차(자동) + 섹션 카드로 들여와, 목차가 이북에서 클릭 이동되게 함.
① htmlImport.ts: 문서에 명시적 목차(Contents 네비 <a href="#id">)가 있으면 그걸 목차로 인식하고 각 항목을 대상 <section id>에 1:1 매핑(작성자 목차 + 정확한 페이지 매핑). 없으면 제목(H1/H2) 기반으로 폴백. 표(table)는 행 텍스트로, pre도 캡처, 빈 섹션 방지 안전망 포함.
② TopBar/ClassicBar: 섹션이 감지되면 카드 경로(importDoc) 우선 — 슬라이드/이미지 덱만 덱 경로.
검증: 실제 AX_전환_실행로드맵 HTML에서 표지 + 목차 13항목 + 12개 섹션(표 포함) 감지 확인, tsc 0.
M6(A) 긴 섹션 자동 분할 — 글씨 범벅 완화구현 완료
임포트 카드가 한 장에 우겨넣어 글씨가 작아지던 문제 해결. 사장돼 있던 paginate.ts(렌더 높이 측정 분할)를 임포트 카드 경로에 연결 — 긴 섹션은 "제목 (2)(3)"으로 자동 분할. 이어지는 페이지엔 contd 플래그를 달아 목차에는 안 보이되 seq는 소비(핫스팟 정렬 유지). 검증: tsc 0. LLM 불필요.
M7(B) LLM 요약 큐레이션 — EVER-PEAK식 자동화구현 완료 · 현지 LLM 테스트 대기
구현: ① server/app.py에 POST /api/summarize — 섹션 원문 → 게이트웨이 LLM → {headline, bullets 3~5, cardType} JSON. 유니에버 게이트웨이 호환으로 헤더+본문 모두에 user_id·api_key 전송(연결 테스트 호출부도 동일 보강). api_key는 서버 설정에서만 읽고 코드/응답에 노출 안 함. ② store.summarizeNotes() + ✨ AI 요약 버튼(양 툴바) — 본문 카드들을 요약으로 치환, 실패 섹션은 (A) 원문 유지 폴백.
HELIX 조사: HELIX 엔드포인트는 도메인 전용이라 미사용. HELIX가 쓰는 게이트웨이(211.224.106.178:8004/api/v1/inference/chat/completions, model gemma3:27b 등)를 ebook_html 환경설정에 넣으면 됨 — HELIX 코드 연동 불필요.
남은 검증: 게이트웨이가 사내망이라 클라우드에서 호출 불가 → 이사님 Mac에서 환경설정 입력 → 연결 테스트 → AI 요약으로 실제 확인 필요(tsc·py 문법은 통과).

6완료 판정 체크리스트

아래가 모두 실제 실행으로 확인돼야 "완료"입니다. (verification-before-completion 규약)

  • 라이트로 만든 이북이 EVER-PEAK 솔루션소개와, 다크로 만든 이북이 EVER-PEAK 다크와 육안으로 같은 계열이다.
  • 이북 만들 때 라이트/다크 토글만 바꿔도 해당 톤으로 생성되고, 목차 카드도 그 톤을 따른다.
  • 목차의 모든 항목을 눌렀을 때 각각 정확한 페이지로 이동한다(빗나감 0) — 라이트·다크 양쪽 모두.
  • _hotspots.json이 빌드 산출물에 생성되고, generator 로그에 "핫스팟 N개 적용"이 찍힌다(OCR 경로로 안 떨어짐).
  • 목차가 "위에 어정쩡하게 불러와지는" 현상이 사라졌다.
  • 내보낸 PDF에서도 목차 클릭 이동이 유지된다(뷰어 밖에서도 동작).
  • 기존 라이트 이북 생성이 그대로 동작한다(회귀 없음).
  • uniever_ebook 수정 여부가 D1 결정과 일치한다(무단 변경 없음).
