2차 기획 — 토글·예시영상·Agentic-PM 이식

1차에서 카드 빌더·자유 캔버스·발표·단축키를 완성했습니다. 2차는 오늘 회의 결과를 반영해 세 축을 추가합니다 — ①빈 화면에서 틀을 짜는 노션식 토글 + 발표 서식, ②상단 '예시영상' 인앱 가이드, ③Agentic-PM의 환경설정·채팅(백엔드 엔진 포함) 이식. 이번에도 코드는 아직 짜지 않고 계획부터 확정합니다.

1축 A — 노션 토글 + 발표 서식으로 '빈 화면에서 틀 만들기' NEW

지금은 왼쪽 카드에서 골라야 시작됩니다. 2차엔 빈 문서에서 글로 목차·틀부터 짤 수 있게, 노션식 블록 편집을 얹습니다. 그 아웃라인이 곧 페이지/발표 슬라이드가 됩니다.

1) 노션식 블록 편집

기능동작
슬래시 명령 /빈 줄에서 /를 치면 블록 메뉴(제목·본문·토글·목록·구분선·이미지…)가 떠서 골라 삽입.
제목 토글 >> + 스페이스로 접었다 펼치는 제목 토글 생성. 토글 안에 하위 내용을 넣어 틀을 계층으로 구성.
글자 서식볼드(⌘/Ctrl+B), 가운데 정렬, (확장) 기울임·밑줄·글머리.
빈 화면 시작카드를 안 골라도 빈 문서에서 바로 타이핑 → 틀 완성 후 페이지로 확정.

2) 발표(프리젠테이션) 서식

기능동작
배경 설정페이지/슬라이드 배경색(또는 이미지) 지정 — 표지·강조 슬라이드에.
정렬·강조제목/본문 가운데 정렬, 볼드 등으로 발표용 강약 조절.
토글→슬라이드 연결최상위 제목 토글 하나 = 한 섹션/슬라이드. 아웃라인을 접으면 발표 목차, 펼치면 내용.
초보 배려(1차 원칙 유지). /·> 같은 파워 기능은 기본은 숨기고 힌트로만 노출합니다("/를 눌러 블록 추가"). 카드 방식·토글 방식 둘 다 쓸 수 있게 해서, 낯선 임원은 카드로, 익숙한 사람은 토글로.

3) 상태모델 영향(설계 메모)

기존 Page는 카드(cardKey+fields)와 자유 캔버스(els/conns/strokes)를 가집니다. 여기에 블록 문서(blocks[]) 표현을 추가합니다: { id, type: heading|text|toggle|list|divider|image, text, children[], marks(bold/align), collapsed }. 발표·이북 렌더러(PageView)가 이 블록을 읽어 그리도록 확장합니다("보이는 그대로가 산출물" 원칙 유지).

2축 B — 상단 '예시영상' 버튼 = 인앱 가이드 NEW

"간단한 이북 하나를 ebook_html 컴포넌트로 어떻게 만들어 가는가"를, 영상 파일 없이 앱이 직접 단계별로 시연합니다(종이접기 방법영상 느낌). 1차의 튜토리얼 스포트라이트(TutorialCoach)를 '자동 재생 데모'로 확장합니다.

요소내용
진입상단바에 ▶ 예시영상 버튼. 누르면 데모 오버레이 시작(언제든 종료 가능).
재생 방식스크립트(단계 목록)를 순서대로 재생 — 대상 버튼 하이라이트 + 자막 설명 + 자동 진행. 실제 클릭을 흉내내며 "이렇게 카드 고르고 → 내용 채우고 → 이북 만들기"까지 보여줌.
안전 격리사용자의 실제 작업물과 섞이지 않도록 데모 전용 샘플(간단 이북) 위에서 재생하거나 별도 미리보기에서 시연.
확장여러 편(예: '자유 캔버스 편', '발표 편', '토글로 틀짜기 편')으로 늘릴 수 있는 스크립트 포맷.
인앱 가이드의 장점. 영상 파일 관리·재촬영이 필요 없고, UI가 바뀌면 스크립트만 고치면 됩니다. 1차의 튜토리얼 인프라를 재사용하므로 구현 비용도 낮습니다.

3축 C — Agentic-PM 환경설정 · 채팅 이식 PORT

회의 결정대로 백엔드 엔진까지 전부 동일 이식합니다. 다만 챗 엔진은 PM 화면 전용 로직이 커서, 재사용 코어와 PM 도메인 계층을 나눠 이식·중립화합니다.

3-1) 무엇을 어디서 가져오나 — 이식 맵

원본 (Agentic-PM)성격ebook_html 이식 위치 / 메모
■ 환경설정 (프론트 + 백엔드)

ChatPanel의 화면별 질문 가이드교체PM 예시("프로젝트 생성…")를 ebook_html 예시("표지 카드 추가", "이북 만들기…")로 교체.

3-2) 스택 정합(중요)

두 앱의 기반이 다릅니다. Agentic-PM은 Tailwind + lucide-react + react-markdown + 풀 FastAPI(챗엔진·SQLite App_Settings·.env·.auth_secret), ebook_html은 순수 CSS + zustand + 얇은 FastAPI(현재는 generator.py 호출만). 이식하려면:

항목계획
프론트 의존성lucide-react, react-markdown(+remark-gfm/breaks) 도입. 스타일은 Tailwind 전면 도입 대신 필요한 클래스(settings-*, 채팅)만 순수 CSS로 이식해 ebook_html을 가볍게 유지(권장).
백엔드 확장ebook_html 서버(server/app.py)에 챗·설정 라우터 + SQLite(App_Settings) + .env 로더를 추가. 기존 /api/build는 그대로.
인증Agentic-PM은 토큰 인증(agentic-pm-token)을 씀. ebook_html은 로컬 단일 사용자이므로 인증을 최소화/제거(로컬 전용).
실행 스크립트run.command가 이제 파이썬 의존성(챗엔진)까지 설치·기동하도록 갱신.
보안api_key는 브라우저에 저장하지 않고 서버 App_Settings에만(원본 원칙 유지). .env/.auth_secret 위치·권한 정리.

3-3) "채팅이 틀·이북을 대신 조작" — 지금 가능한가? (Q2 답)

결론: 기술적으로 가능합니다. 이식하는 챗 엔진에는 이미 ui_action 계약(make_ui_action, 프론트 onUiAction, auto_apply/requires_confirm)이 들어 있습니다. 즉 "말 → 화면 동작"의 배관이 원래부터 있습니다.

다만 그 액션들이 지금은 PM 대상(프로젝트·요구사항 생성 등)이라, ebook_html에서 쓰려면 ebook 액션으로 재매핑이 필요합니다 — 예: "표지 카드 추가", "이 카드 제목을 …로", "세로/가로 전환", "이북 만들기", "도형 추가". 이 재매핑은 명확하지만 실제 작업입니다.

권장 순서. 2차에서는 회의 결정대로 대화형까지 확실히 올리고(“안녕?→대답”, DOCX 내보내기), 동시에 ebook 액션 브리지의 뼈대(액션 레지스트리 + onUiAction→zustand 스토어 배선)를 깔아 안전한 액션 1~2개(예: 카드 추가)만 시범으로 켭니다. 나머지 "대신 조작"은 3차에서 플래그로 확장. 이렇게 하면 지금 당장 위험 없이 시작하고, 나중에 스위치만 켜면 됩니다.

4통합 아키텍처(2차 후)

[ 브라우저 ] ebook_html 프론트 (React + zustand) ├─ 카드 빌더 · 자유 캔버스 · 발표 (1차) ├─ ★ 블록/토글 에디터 + 발표 서식 (축 A) ├─ ★ 예시영상(인앱 가이드) 오버레이 (축 B) ├─ ★ 환경설정 화면(LLM) (축 C) └─ ★ 채팅 패널(SSE·DOCX) (축 C) │ ▼ [ 로컬 서버 ] ebook_html FastAPI (확장) ├─ /api/build ──────────────► uniever_ebook/generator.py (무수정, 1차) ├─ ★ /api/settings/llm(+test) ─► App_Settings(SQLite) · .env └─ ★ /api/chat (SSE) ─► chat_engine(core.run) ─► llm_client ─► (self/OpenAI/Anthropic)

별표(★)가 2차 신규. 1차 파이프라인과 uniever_ebook 무수정 원칙은 그대로 유지됩니다.

5마일스톤 (2차) · 게이트

1차와 같은 방식: 각 단계마다 스킬 사전 선언 → 게이트 통과(자동검증 포함). 순서는 리스크가 낮고 독립적인 것부터.

P0 착수 · 스택 정합
의존성 결정(lucide-react·react-markdown 도입, Tailwind 부분/전면 여부), 백엔드 확장 골격(라우터·SQLite·.env), Agentic-PM 코드 스냅샷 확보.✔ 게이트: 확장된 서버가 빈 /api/chat·/api/settings/llm 스텁으로 기동.
P1 환경설정 이식
SettingsPage + LlmSettingsCard + /settings/llm(GET/PUT/test) + App_Settings 저장.✔ 게이트: 설정 저장·재로딩·"연결 테스트" 동작(모의 또는 실 LLM).
P2 채팅 코어 이식(대화형)
재사용 코어(chat_engine core·session·sse·schema) + llm_client + ChatPanel. PM 도메인 계층은 비활성/중립화.✔ 게이트: "안녕?"에 스트리밍 응답 + 답변 DOCX 내려받기.
P3 노션 토글 + 발표 서식
블록 에디터(/ 슬래시·> 토글·볼드·가운데정렬), 배경 설정, 아웃라인→페이지/슬라이드 연결.✔ 게이트: 빈 화면에서 토글로 틀 작성 → 발표·이북에 반영.
P4 예시영상(인앱 가이드)
상단 ▶ 예시영상 버튼 + 스크립트 재생 엔진(TutorialCoach 확장) + 첫 데모(간단 이북 만들기).✔ 게이트: 버튼→데모 자동 재생·종료, 실제 작업물과 격리.
P5 챗 액션 브리지(스캐폴드)
ebook 액션 레지스트리 + onUiAction→스토어 배선, 안전 액션 1~2개 시범(플래그). 나머지는 3차.✔ 게이트: "표지 카드 추가해줘" 같은 시범 액션 1건이 실제로 반영(확인 절차 포함).
P6 검증 · 증적 · 핸드오버
Playwright 스모크 확장(설정 저장/테스트 모의·챗 대화·토글·예시영상), 문서화.✔ 게이트: 전체 스모크 PASS + 2차 핸드오버 문서.

6리스크 & 대응

리스크대응
스택 이질성 (Tailwind vs 순수 CSS)Tailwind 전면 도입 대신 필요한 클래스만 이식. 결정은 P0에서 확정.
백엔드 비대화 (얇은 서버 → 풀 챗엔진)설치·기동을 run.command로 자동화. 챗엔진은 계층 분리해 PM 죽은코드 최소화.
PM 도메인 결합 (전부 이식 시 PM 문구 노출)도메인 계층 중립화(가이드·명령 교체), 대화형만 노출.

보안 (api_key·비밀)서버 저장 원칙 유지, 로컬 파일 권한 정리. 로그에 키 미출력.
예시영상 오작동 (실제 데이터 변경)데모 전용 샘플/미리보기에서만 재생하도록 격리.
