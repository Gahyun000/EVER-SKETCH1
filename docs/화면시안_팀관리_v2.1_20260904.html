1. 돋보기 — 저건 제 목업이 때운 것입니다

⌕ v2.0 (틀림) — 글자 ⌕. 폰트마다 크기·모양이 다르고 작게 나온다 실제 (맞음) — lucide-react 의 <Search className="h-4 w-4" />, 16×16 SVG
「내 이북」 화면이 이미 그 아이콘을 쓰고 있습니다 (LibraryScreen.tsx → <Search className="h-4 w-4" />). 제 목업이 글자로 때운 것이라 작고 어색하게 나왔습니다. 아래 카드부터는 실제와 같은 16px SVG 로 바꿨습니다 — 두 화면의 검색칸이 똑같아 보입니다.

2. 순서 — 네 가지

배치 창 폭
팀 관리관리자 전용

팀이 곧 공유 범위입니다. 승인된 자료는 같은 팀에게만 보입니다.

팀을 바꿔도 로그인은 끊기지 않습니다 — 다음 요청부터 바로 새 팀이 적용됩니다. (권한 변경과 다릅니다.)
한 사람은 한 팀에만 속합니다. 다른 팀에 넣으면 이전 팀에서 빠집니다.
배치 버튼을 눌러 네 가지를 비교해 보세요. 검색은 「조회」 또는 엔터로 걸립니다.

3. 네 가지 비교

배치장점약점
㉮만들기 → 조회
지금		 조회줄이 표에 바로 붙는다. 검색은 표를 거르는 장치라 사이에 뭐가 끼면 안 된다 자주 쓰는 조회보다 가끔 쓰는 만들기가 위에 있다
㉯조회 → 만들기
물어보신 것		 조회가 위로 올라온다 조회줄과 표 사이에 만들기가 낀다. 「검색했는데 왜 여기 입력칸이…」가 된다. 결과 개수 줄과 표도 떨어진다
㉰만들기를 맨 아래 조회 → 표가 붙고, 만들기도 안 낀다 새 팀을 만들려면 표를 지나 끝까지 내려가야 한다
㉱머리줄 버튼
「내 이북」식		 「내 이북」과 똑같은 뼈대. 제목줄에 만들기 버튼 → 조회줄 → 개수 → 표. 평소엔 입력칸이 아예 없어 화면이 조용하고, 누르면 열린다 만들기가 한 번 더 누르는 일이 된다
㉱ 를 권합니다. 「내 이북」 화면이 이미 제목줄 오른쪽에 「＋ 새 이북」 → 조회줄 → 개수/페이지 → 목록 입니다. 같은 제품의 두 목록 화면이 같은 뼈대를 쓰면, 대표님이 한 번 익힌 자리가 두 곳에서 통합니다. ㉯ 는 권하지 않습니다 — 조회줄과 표 사이를 벌리는 유일한 안입니다.
