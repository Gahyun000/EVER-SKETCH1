「승인하시겠습니까 / 반려하시겠습니까」도, 「제출하시겠습니까」도 이미 있습니다. 표준을 안 지키는 건 창이 없어서가 아니라, 창이 저마다 손으로 만들어져 표준이 요구하는 동작을 빼먹고 있어서입니다. 아래 두 창을 직접 열어 비교해 보세요.

2그럼 무엇이 안 맞나

표준이 요구하는 「모달 격리」가 빠져 있습니다 표준은 확인창에 Esc로 닫기 · 포커스 가두기 · 닫을 때 포커스 되돌리기 · 배경 스크롤 잠그기 · 중복 제출 막기를 요구합니다. 결재 확인창들은 이걸 하나도 안 합니다 — <div className="es-confirm"> 로 직접 그렸기 때문입니다.
표준 항목관리자 결재작성자 제출지금 상태
대상·행동·결과를 적는다지킴지킴 문구는 오히려 표준보다 낫습니다 — 「얼어붙습니다」·「승인본은 안 바뀝니다」
확인/취소 라벨지킴지킴「승인/반려」·「제출/취소」
위험한 행동은 구분지킴일부 관리자 쪽은 .danger 로 빨강. 삭제 확인창은 색만 다르고 글로는 구분 없음
중복 제출 막기지킴없음 LibraryScreen.tsx 에는 진행 중 상태가 아예 없습니다 (busy 변수 0개). 확인창 4개 전부 두 번 눌리면 두 번 갑니다.
Esc 로 닫기없음없음 바깥을 눌러야만 닫힙니다
포커스 가두기 · 되돌리기없음없음 Tab 을 누르면 창 뒤의 버튼으로 빠져나갑니다. 닫아도 포커스가 안 돌아옵니다
배경 스크롤 잠그기없음없음 창을 띄운 채로 휠을 굴리면 뒤 목록이 움직입니다
role="dialog"없음없음 읽어 주는 도구가 그냥 div 로 봅니다
그리고 이 전부를 하는 물건이 이미 저장소에 있습니다 src/ui/Modal.tsx — Esc(캡처로 잡아 캔버스로 새는 것까지 막음), 포커스 가두기, 닫을 때 되돌리기, 배경 스크롤 잠금, role="dialog", busy 중 닫기 금지가 전부 들어 있습니다. 그런데 쓰는 곳은 4개뿐입니다 — 저장 확인 · 새 자료 · 의견 작성 · 앵커 유실. 결재·삭제·계정·팀 확인창 8개는 각자 손으로 그렸습니다. 표준을 안 따른 게 아니라, 따르는 물건을 만들어 놓고 안 쓴 것입니다.

4고칠 목록

  • ① 작성자 확인창 4개에 진행 중 잠금을 넣습니다. LibraryScreen.tsx 는 진행 중 상태가 아예 없습니다. 지금 「제출」을 두 번 빠르게 누르면 요청이 두 번 갑니다. 서버가 두 번째를 「이미 결재 대기 중입니다」로 막아 주긴 하는데 — 결과가 「제출됨」이 아니라 빨간 오류로 보입니다. 실제로는 성공했는데 실패한 줄 압니다. 표준이 이 항목을 콕 집어 요구하는 이유입니다.
  • ② 손수 만든 확인창 8개를 ui/Modal 로 바꿉니다. Esc·포커스·스크롤 잠금·role="dialog"가 한 번에 따라옵니다. 새로 만드는 게 아니라 갈아 끼우는 일입니다 — 문구는 지금 것이 더 좋으니 그대로 옮깁니다.
  • ③ 삭제 확인창은 글로도 구분합니다. 표준은 「시각적으로도 문구로도 구분」을 요구합니다. 지금은 버튼만 빨갛습니다. 색을 못 보는 사람에게는 승인 창과 같아 보입니다.
  • ④ 검사를 하나 더 답니다. 「es-confirm·lib-confirm 을 새로 쓰지 않는다」를 no_native_dialogs.test.mjs 옆에 둡니다. 안 그러면 다음에 급할 때 또 손으로 그립니다 — 이번 8개가 그렇게 생겼습니다.
