01 · 리허설의 목적

기능이 되는지 보는 자리가 아니다.
쓸 만한지 보는 자리다.

03 · EVER-SKETCH 기획의도와 설계사상

도구를 하나 더 만든 게 아니라
일하는 방식을 옮긴 것이다

이 장은 리허설에서 "왜 이렇게 만들었냐"는 질문이 나올 때 그대로 읽으면 되는 근거다.

기획의도 — 무엇을 없애려고 만들었나

1
파일을 옮기지 말고, 사람을 링크로 부른다
최종.pptx → 최종_수정.pptx → 최종_진짜최종.pptx가 생기는 이유는 단 하나, 원본이 여러 개이기 때문이다. 원본을 서버에 하나만 두면 이 문제는 사라진다. 버전은 사람이 파일 이름으로 관리하지 않고 서버가 기록한다.
2
피드백을 문서 안으로 넣는다
"3번째 표에 그거요"는 다시 물어봐야 하는 말이다. 지적은 그 칸·그 구간에 붙어야 한다. 그래서 표의 칸 범위를 끌어서 고르면 AI Agent · 03월~05월처럼 사람 말로 된 자리 이름이 자동으로 붙는다.
3
양식을 권고가 아니라 시스템으로
"이 양식으로 써 주세요"는 지켜지지 않는다. 임원마다 표가 달라지고, 취합할 때 관리자가 다시 맞춘다. 템플릿 정본을 서버가 배부하고, 열 추가·삭제 같은 구조 변경은 관리자만 할 수 있게 잠갔다.
4
취합을 사람 손에서 뗀다 — 아직 만들지 않았다
의도적으로 비워 뒀다. 회의장에서 무엇으로 띄우는지, 장 순서를 누가 정하는지를 추측으로 만들면 반드시 다시 만들게 된다. 오늘 그 답을 얻는 것이 이 리허설의 절반이다.

설계사상 — 코드를 이렇게 짠 이유

① 권한은 한 곳에서만 판정한다

판정은 permissions.decide(행위자, 행동, 대상) 딱 한 함수에서만 한다. 각 화면·각 라우트는 스스로 판단하지 않고 물어본다. 기본값은 거부다. 권한 규칙이 여러 곳에 흩어지면 한 곳만 고치고 다른 곳을 잊는 사고가 반드시 난다.

② 규칙을 잊지 못하게 테스트가 막는다

test_endpoint_coverage.py가 소스를 직접 읽어 모든 라우트에 로그인 확인과 권한 판정이 들어 있는지 검사한다. 권한 없이 새 기능을 붙이면 테스트가 깨진다. 사람의 기억에 맡기지 않는다.

③ 역할 이름이 진실, 숫자는 표시용

내부는 admin · writer · viewer로만 판정한다. 화면의 Lv1·Lv2·Lv3은 사람이 읽기 좋으라고 붙인 이름표일 뿐이다. 숫자로 비교(level <= 2)하면 등급이 하나 늘어나는 날 조용히 무너진다.

④ 열람자에게는 메모의 존재 자체를 숨긴다

미해결 건수도 보여주지 않는다. "0건"도 정보이기 때문이다. "몇 건 있다"만 알아도 그 장이 지금 시끄럽다는 사실이 새어 나간다. 확정 사항 — 이 원칙을 어기는 화면은 버그로 처리한다.

⑤ 고친 손과 닫는 손을 나눈다

작성자는 「고쳤습니다」까지만 누를 수 있고, 「해결」은 지적한 사람만 누른다. 자기 지적을 스스로 닫을 수 있으면 반영 확인이라는 절차가 무의미해진다. 미해결 숫자가 남아 있는 한 회의는 그 항목을 그냥 지나치지 못한다.

⑥ 조용히 틀리는 것을 가장 나쁘게 본다

표에 행을 하나 추가하면 아래 칸이 전부 밀린다. 지적이 엉뚱한 자리를 가리킨 채 아무도 모르고 회의에 들어가는 것 — 이게 최악이다. 그래서 추가할 때는 묻지 않고 따라 옮기고, 지울 때만 묻는다. 모달이 잦으면 사람들은 읽지 않고 누르게 되고, 그러면 정작 중요한 경고까지 흘려보낸다.

⑦ 고친 것은 되돌려서 확인한다

버그를 고칠 때마다 테스트를 쓰고, 고친 부분을 일부러 되돌려 그 테스트가 실패하는지 본다. 이 과정에서 "통과하지만 아무것도 지키지 않는 테스트"를 여러 번 잡아냈다 — 목록 정렬 검사는 정렬을 통째로 빼도 통과하고 있었다.

⑧ 브라우저 기본 창을 쓰지 않는다

alert · confirm 같은 브라우저 기본 창은 모양도 제각각이고 문구도 못 바꾼다. 대화상자는 껍데기 하나로 통일했고, 기본 창이 뜨는지 자동으로 감시하는 테스트를 붙였다.

⑨ 용어를 사람 말로 고친다

「회수」→「배부 무르기」 — 이미 본 자료를 되돌릴 수는 없으니, 회수라는 말이 오해를 만든다.
「5행 3~6열」→「AI Agent · 03월~05월」 — 좌표는 개발자의 말이지 임원의 말이 아니다.

🧩
한 줄로 말하면. EVER-SKETCH의 설계는 전부 "사람이 실수해도 시스템이 조용히 틀리지는 않게"에 맞춰져 있다. 권한은 한 곳에서, 규칙은 테스트가, 경고는 꼭 필요할 때만.
04 · 새로 만든 기능

얹은 것은 "사람 · 권한 · 회차" 계층

ebook_html에는 없던 것만 적었다. 편집기·표 편집·내보내기는 물려받은 것이다.

단계기능내용
W1계정과 권한 가입 → 관리자 승인 후 사용, 역할 3종(관리자·작성자·열람자), 계정 정지·해제, 비밀번호 보기/숨기기 · Caps Lock 경고, 관리자 명령줄 도구
W2회차(Cycle) 월간 회의 한 바퀴를 단계로 모델링: 작성 준비 → 작성 → 검토 → 발행 → 종료. 단계마다 누가 무엇을 볼 수 있는지가 달라진다
W2표준 템플릿 배부 정본 양식(v2.0, 실물 구조 반영)을 사람별 장으로 쪼개 배부. 열 추가·삭제 등 구조 변경은 관리자만
W2실물 PPT 배부 기존 PPTX를 올리면 슬라이드별로 편집 가능한 장으로 변환하고, 슬라이드마다 담당자를 지정해 배부. 배부 전 미리보기 제공
W2배부 무르기 잘못 배부했을 때 되돌린다. 이미 본 사람에게서 기억을 지울 수는 없다는 사실을 확인창에 그대로 적고, 쌓인 의견 건수를 함께 보여준다
W2제출 · 반려 · 승인 작성자가 제출하면 관리자가 승인하거나 되돌린다. 회차 단계에 따라 제출 취소 가능 여부가 갈린다
W3앵커 의견 문서 위 그 자리에 지적을 남긴다. 아래 7단계로 나눠 만들었다

W3 — 의견 기능은 이렇게 쌓았다

0
브라우저 기본 창을 걷어내고 대화상자를 하나로
모든 확인창·오류창이 같은 껍데기를 쓴다. Esc·바깥 클릭·처리 중 잠금이 한 군데서 처리된다
1
같은 회차 동료끼리 서로의 장을 본다 읽기 전용
관리자만 남의 장을 볼 수 있으면 「지적한 사람이 닫는다」가 성립하지 않는다. 같은 회차에 참여한 작성자끼리 서로의 장을 읽을 수만 있게 열었다. 열람자에게는 여전히 메모가 보이지 않는다
2
끌어 고른 범위 그대로 짚는다
칸 하나가 아니라 끌어서 고른 구간에 지적이 붙는다 — 「3월부터 5월까지가 겹칩니다」
3
짚은 자리를 사람 말로
5행 3~6열 → AI Agent · 03월~05월. 표의 머리글을 직접 읽어 이름을 만든다. 머리글이 선언돼 있지 않은 실물 PPT 표도 병합된 좌상단 칸을 단서로 알아낸다
4
내가 답해야 할 지적을 가려낸다
지적은 내 차례 → 상대 차례 → 끝난 것 순으로 정렬된다. 본인에게 달린 의견에는 누가 달았는지 이름이 보인다
5
「고쳤습니다」 → 「해결」, 두 손으로 나눈다
작성자는 고쳤다고 알리고, 지적한 사람만 닫는다
6
「처음부터 다시」
배부받은 원본 상태로 되돌린다. 무엇이 사라지는지 먼저 보여주고 되돌린다
7
표가 바뀌어도 지적이 자리를 잃지 않는다
행·열을 추가하면 묻지 않고 따라 옮기고, 지우려 하면 묻는다. 기본 선택은 「의견은 남기고 바꾸기」 — 검토 이력이 조용히 사라지는 것이 제일 나쁘다. 남은 지적은 목록에 「가리키던 칸이 없어짐」으로 표시되고 문서 위에는 그리지 않는다

체크리스트

셋 이상 빠지면 리허설을 미루는 편이 낫다. 준비가 덜 된 채로 돌리면 제품 문제와 준비 문제가 섞인다.

환경

  • 백엔드 구동 — uvicorn server.app:app --reload
  • 프런트 구동 — npm run dev 또는 빌드본
  • python-pptx 설치 확인 — 없으면 PPT 업로드가 503으로 막힌다
  • 브라우저 두 개 준비 (일반 창 + 시크릿 창) — 두 사람을 동시에 연기해야 한다
  • 화면 공유 · 프로젝터 해상도 확인 (1440 이상 권장)
  • DB 백업 1부 — 리허설 뒤 초기화할 수 있게

사람과 자료

  • 관리자 1명 — 회차를 열고 배부하고 검토를 시작하는 사람
  • 작성자 2명 — 임원 역할. 실제로 표를 고쳐 본다
  • 열람자 1명 — 아무것도 안 보이는 게 정상인지 확인하는 역할
  • 실물 PPT 1벌 — 표준 양식이 아니라 평소 쓰던 그대로
  • 기록 담당 1명 (관찰 기록표 작성 — 이 문서 하단)
  • 시드 관리자 계정 admin 비밀번호 확인
📄
실물 PPT가 이 리허설의 절반이다. 표준 양식은 우리가 만든 것이라 당연히 잘 돌아간다. 진짜 질문은 임원이 쓰던 PPT가 변환기를 통과하는가다. 깨끗하게 정리된 파일 말고, 실제로 지난달에 돌린 파일을 가져올 것.

시나리오 A · 15분

회차를 열고, 실물 PPT를 나눠 준다

임원에게 "새 양식을 배우세요"라고 하지 않는다. 쓰던 PPT를 그대로 올려서 슬라이드별로 나눠 준다.

1
관리자가입 → 승인 → 권한 부여
새 창에서 작성자 1명을 자가가입시킨다(희망 역할: 작성자) → 관리자 화면 사용자 관리에서 승인 → 그 순간부터 권한이 생긴다.

"가입은 누구나 할 수 있지만, 가입만으로는 아무것도 못 봅니다. 본인이 고른 역할은 '신청'이고, 실권한은 관리자가 승인하는 순간 생깁니다. 승인 전 계정으로 자료 주소를 직접 쳐 봐도 열리지 않습니다."

  • 승인 전 계정이 정말 아무것도 못 보는가
  • 승인 절차가 병목으로 느껴지는가 — 임원 20명이면 어떨지
2
관리자회차 개설
회차 화면 → + 회차 열기 → 년월(2026-09)과 제출기한 입력. 같은 달에 두 번은 열 수 없다.
  • 회차 단계가 준비 → 작성 중으로 자동으로 넘어가는가(배부 시)
3
관리자실물 PPT 업로드 핵심
배부하기 → 실물 PPT 선택 → 지난달에 실제로 쓴 파일 업로드 → 슬라이드 목록이 뜬다(표 개수·글상자 개수까지 표시).

"PPT를 그림으로 붙이는 게 아닙니다. 표는 표로, 글자는 글자로 들어옵니다. 그래서 배부받은 사람이 그 자리에서 칸을 고칠 수 있습니다."

  • 표가 표 모양대로 들어왔는가 — 열 너비·행 높이·병합
  • 제목·색 띠가 살아 있는가 (예전에 제목이 ‹#›로 들어온 적 있음)
  • 깨진 곳이 있다면 어디인가 — 스크린샷을 남길 것
  • 변환에 걸린 시간
4
관리자슬라이드별 배부
표지는 공통으로 체크(모두의 맨 앞에 붙는다) → 나머지 슬라이드마다 담당자 지정 → 아래 「이렇게 나갑니다」에서 누가 몇 장 받는지 확인 → 배부.

"누르기 전에 실제로 나갈 장이 미리보기로 보입니다. 그리고 '홍길동 — 공통 1장 + 담당 1장 = 2장'처럼 사람별로 몇 장인지 적혀 있습니다. 예전에 공통 체크가 빠진 줄 모르고 배부해서 표지가 안 나간 적이 있어서 넣은 장치입니다."

  • 배부 전 미리보기가 실제로 나간 것과 같은가
  • 공통 장이 모두의 맨 앞에 붙었는가
  • 담당자가 자기 장만 받았는가
시나리오 B · 15분

배부받은 장을 실제로 고쳐 본다

여기서 "PPT보다 불편하다"는 말이 나오면, 그게 오늘 얻을 수 있는 가장 값진 정보다.

1
작성자내 장 열기
로그인 → 회차 화면에 내 것과 동료 행이 함께 보인다 → 내 행 열기.
  • 내 것과 동료 것이 한눈에 구분되는가
  • 동료 행에 제출 상태가 안 보이는 것이 자연스러운가, 답답한가 — 지금은 "누가 아직 안 냈는지"를 관리자만 본다
2
작성자진행 구간 만들기 — 칸을 끌어서 병합
로드맵 표에서 3월~5월 칸을 끌어서 고른다 → 상단 툴바 표 · ⤢ 병합 → 합쳐진 칸에 단계 이름을 쓴다(예: 분석/설계) → 셀 배경색 5색 중 하나.

"엑셀처럼 끌어서 고르고, 병합하고, 이름을 씁니다. 색에는 뜻을 정해두지 않았습니다 — 뜻은 칸에 쓴 글자에 있습니다. 색에 '완료·지연' 같은 뜻을 우리가 붙이면, 임원이 쓰던 뜻과 어긋난 채로 취합됩니다."

  • 드래그가 손에 맞는가 — 예전에 문서가 42px 튀어서 한 줄 아래가 잡히던 문제가 있었다
  • 병합·해제가 기대대로 되는가
  • 머리글 행이 안 고쳐지는 것이 답답한가
3
작성자제출
회차 화면 → 내 행 제출. 다른 작성자 한 명은 일부러 제출하지 않고 둔다(D에서 쓴다).
  • 저장이 자동으로 되는 것이 믿기는가 — 「저장됨」 표시를 보게 되는지
  • 제출 뒤에 뭔가 더 하고 싶어지는가
📝
이 시나리오의 진짜 관찰 포인트 — 작성자가 몇 번 막히는가, 그리고 어디서 손이 멈추는가. 말로 설명해 주기 전에 스스로 찾는지 지켜볼 것. 설명해야만 되는 곳이 있다면 그건 화면이 말을 안 하고 있다는 뜻이다.
시나리오 C · 15분

지적 → 고침 → 해결, 한 바퀴

이 제품이 대체하려는 것은 편집기가 아니라 메일·구두로 오가던 피드백이다. 여기가 본론이다.

1
관리자회차를 「검토 중」으로 넘긴다
회차 화면 → 검토로 버튼. 이 순간부터 동료끼리 서로의 장에 지적할 수 있다.

"작성 중에는 서로 보기만 됩니다. 아직 쓰는 중인 것에 지적이 달리면 쓰는 사람이 흔들리니까요. 다 쓴 뒤 검토 단계로 넘기면 그때 열립니다."

2
작성자 B동료의 장을 열어 구간을 짚는다
동료 행 보기 → 로드맵에서 3월~5월 구간을 끌어서 고른다 → 툴바 💬 의견 달기 → 창에 「AI Agent · 03월~05월」이 찍혀 있는지 확인하고 내용 작성.

"칸 하나가 아니라 구간을 짚습니다. 그리고 목록에는 「5행 3~6열」이 아니라 표에 적힌 말 그대로 남습니다. 받는 사람이 표에서 다시 세어볼 필요가 없습니다."

  • 짚은 자리 이름이 실제 표 내용과 맞는가 (실물 PPT 변환본에서 특히)
  • 문서 위 핀과 주황 테두리가 그 자리에 보이는가
  • 남의 장이 읽기 전용으로 잠겨 있고, 왜 잠겼는지 화면이 말하는가
3
작성자 A내 장으로 돌아와 고친다
미리보기 머리에 「확인할 의견 N건」이 떠 있다 → 눌러서 목록 → 핀을 눌러 그 자리로 → 고친 뒤 「고쳤습니다」.

"지적받은 사람은 해결을 누를 수 없습니다. 「고쳤습니다」까지가 그쪽 몫이고, 닫는 것은 지적한 사람이 합니다. 안 그러면 '고쳤다'와 '정말 고쳤다'가 구분되지 않고, 발행 직전의 '미해결 0건'이 아무것도 보장하지 못합니다."

  • 「확인할 의견 N건」이 눈에 들어오는가 — 아니면 그냥 지나치는가
  • 「고쳤습니다」에 답글이 자동으로 한 줄 달리는 것이 자연스러운가
4
작성자 B확인하고 닫는다
자기가 쓴 지적이 「확인 차례」로 맨 위에 올라와 있다 → 내용 확인 → 해결. 핀이 사라진다.
  • 공이 넘어온 것을 알아채는가
  • 목록 순서(내 차례 → 기다리는 것 → 해결됨)가 납득되는가
5
열람자아무것도 안 보이는지 확인
열람자 계정으로 로그인 → 진행 중인 회차가 보이지 않아야 한다. 발행 전에는 명단도, 지적 건수도 안 나간다.

"열람자에게는 메모의 존재 자체를 노출하지 않습니다. 발행된 결과물만 봅니다 — 그래서 지금은 볼 것이 없는 게 정상입니다."

  • 열람자에게 정말 아무것도 안 보이는가
  • 그 상태가 고장처럼 보이는가 — 안내 문구가 필요한지
시나리오 D · 8분

망쳤을 때 빠져나오는 길

실전에서 반드시 생긴다. 관리자를 부르지 않고 스스로 빠져나올 수 있는지가 관건이다.

1
작성자「처음부터 다시」
아직 제출하지 않은 작성자가 표를 마구 헝클어뜨린 뒤 → 회차 화면 내 행 처음부터 다시 → 사라지는 것(쓴 칸 수·의견 건수)을 확인하고 체크 → 실행.

"지우는 게 아니라 되돌립니다. 배부본을 지우면 그 사람이 명단에서 사라지고, 관리자 화면에는 '3명 중 2명'으로 보입니다. 혼자 해결하려던 일이 오히려 관리자를 거치게 되죠. 그래서 자리는 그대로 두고 내용만 배부받은 상태로 돌립니다."

  • 확인창이 무엇이 사라지는지 정확히 말하는가
  • 「의견은 남기고 / 함께 지우고」 선택이 이해되는가
2
작성자제출 취소를 눌러 본다
제출한 작성자가 제출 취소를 시도 → 회차가 이미 검토 중이면 버튼이 잠겨 있고 "관리자에게 반려를 요청해 주세요"라고 뜬다 → 관리자가 반려로 풀어 준다.
  • 잠긴 이유가 바로 읽히는가
  • 반려 요청이 말로 해야 하는 것인지 — 알림이 필요한 지점인지
3
관리자「배부 무르기」
엉뚱한 사람에게 갔다고 가정 → 그 행 배부 무르기 → 창 맨 위 문구와 사라지는 의견 건수를 확인.

"이 창은 먼저 못 하는 것을 말합니다 — '이미 열어본 내용을 없던 일로 만들지는 못합니다.' 하는 일은 담당에서 빼고 더 이상 열지 못하게 하는 것입니다. 그래야 '이미 봤는데 무슨 소용이냐'는 오해가 안 생깁니다."

  • 이 설명이 납득되는가 — 아니면 여전히 무의미해 보이는가
  • 사라지는 의견 건수가 결정을 바꾸는가
4
작성자지적이 달린 줄을 지워 본다
의견이 달린 행을 골라 오른쪽 패널에서 🗑 행 삭제 → "이 표에 달린 의견 1건이 가리키는 칸이 사라집니다" 창이 뜬다 → 의견은 남기고 바꾸기.
  • 행을 추가할 때는 아무것도 안 묻는 것이 자연스러운가
  • 「가리키던 칸이 없어짐」 표시가 이해되는가
07 · 오늘 정할 것

취합·발행(W4)을 정하는
네 가지 질문

Q 01
확정본을 무엇으로 남기나
① EVER-SKETCH 문서 한 벌(링크로 열어 넘겨보기 · 슬라이드쇼)
② 이북(웹)으로 굽기
③ PPT 파일까지 함께
판단 기준 — 회의장 PC에서 실제로 무엇으로 띄우는가. 파일로 띄워야 하면 PPT 내보내기가 필수가 된다.
Q 02
장 순서를 누가 정하나
① 올린 슬라이드 순서 그대로
② 관리자가 발행 전에 끌어서 바꾼다
③ 부서·직급 순 자동
판단 기준 — 순서가 실제로 문제가 되는가. 안 되면 순서 편집 화면은 만들지 않는다.
Q 03
미제출·미해결이 남으면
① 보여주고 넘긴다 — "미제출 2명 · 미해결 5건입니다. 발행할까요?"
② 미제출이 있으면 막는다
③ 미해결까지 막는다
판단 기준 — 회의는 시간이 정해져 있다. 막아서 시스템 밖으로 나가는 것이 최악인지, 그냥 나가는 것이 최악인지.
Q 04
서로 보이는 범위가 편한가
지금은 작성 중부터 동료의 장이 보인다(읽기 전용).
눈치보기가 생기면 검토 단계로 늦출 수 있다 — 규칙 한 줄이다.
판단 기준 — 작성자가 남의 장을 실제로 열어봤는가, 그리고 그게 도움이 됐는가 부담이었는가.
✅
네 질문에 답이 나오면 W4는 짧게 끝난다. 편집·배부·피드백은 이미 다 있고, 남은 것은 모아서 내는 것 하나다.

09 · 문제 대처

리허설 중 막히면

아래는 개발 중에 실제로 겪은 것들이다. 같은 증상이 나오면 당황하지 말 것.

증상원인대처
PPT 업로드가 503으로 실패 python-pptx 미설치 화면에 설치 명령이 그대로 뜬다 — 그대로 실행 후 재시도
고쳤는데 화면이 그대로 브라우저에 옛 파일이 남음 ⌘/Ctrl + Shift + R 로 강력 새로고침
배부한 회차의 원본을 못 바꿈 정상 동작 — 나간 자료와 어긋나는 것을 막는다 바꾸려면 배부 무르기 후 다시 올린다
동료 장을 열었는데 안 고쳐짐 정상 동작 — 남의 장은 읽기 전용 미리보기 머리에 이유가 적혀 있다
남의 장에 의견 버튼이 잠김 회차가 아직 「작성 중」 관리자가 검토로 넘기면 열린다
제출 취소가 안 됨 회차가 「검토 중」 이후 관리자가 반려로 풀어 준다
변환된 표가 이상하게 작음 예전 변환기 판으로 만든 자료 화면에 낡은 자료 안내가 뜬다 — 다시 올린다
열람자에게 아무것도 안 보임 정상 동작 — 발행 전이다 그대로 두고 기록에 남긴다 (Q01과 연결)
10 · 예상 질문

나올 만한 질문과 답

Q 01
"PPT를 안 쓰고 이걸 쓰라는 겁니까?"

아닙니다. 쓰던 PPT를 그대로 올립니다. 그걸 슬라이드별로 나눠 드리면, 각자 자기 장만 그 자리에서 고칩니다. 새 양식을 배우실 필요가 없습니다. 그리고 PPT·PDF로 다시 내보내는 기능은 그대로 있습니다.

Q 02
"내 자료를 다른 임원이 다 본다는 겁니까?"

같은 회차에 참여한 사람끼리만 보이고, 읽기 전용입니다. 고치는 것은 끝까지 본인 것만입니다. 연 이유는 하나입니다 — "앞 장과 숫자가 다릅니다" 같은 지적은 앞 장을 볼 수 없으면 애초에 할 수 없고, 막아두면 결국 캡처를 메신저로 주고받게 됩니다. 그게 훨씬 위험합니다. 불편하시면 검토 단계부터 보이도록 늦출 수 있습니다.

Q 03
"제가 실수로 다 지우면 어떻게 됩니까?"

자동 저장되고 버전이 남습니다. 그리고 아예 헝클어졌으면 「처음부터 다시」로 배부받은 상태로 되돌릴 수 있습니다 — 관리자를 부르지 않아도 됩니다. 되돌리기 전에 무엇이 사라지는지(쓴 칸 수·달린 의견 수)를 보여드립니다.

Q 04
"지적을 받으면 제가 닫으면 되나요?"

아닙니다. 고치신 뒤 「고쳤습니다」까지가 담당자 몫이고, 닫는 것은 지적한 분이 합니다. 스스로 닫을 수 있게 하면 "고쳤다"와 "정말 고쳤다"가 구분되지 않고, 발행 직전의 「미해결 0건」이 아무것도 보장하지 못하게 됩니다.

Q 05
"회의 자료는 결국 어떻게 나옵니까?"

솔직히 말씀드리면 그 부분은 오늘 정합니다. 문서 한 벌로 링크에서 넘겨볼지, PPT 파일로 뽑을지 — 회의장에서 실제로 무엇으로 띄우시는지 보고 만드는 게 맞다고 판단했습니다. 추측으로 만들면 다시 만들게 되니까요. 오늘 답을 주시면 바로 붙입니다.

Q 06
"메일로 알림이 오나요?"

지금은 화면 안에서만 알립니다 — 「확인할 의견 N건」, 의견 탭 숫자, 회차 목록의 미해결 칸. 메일·메신저 연동은 일부러 미뤘습니다. 알림이 많으면 사람들이 규칙을 만들어 걸러버리고, 그 순간 알림은 없는 것과 같아집니다. 오늘 "몰라서 지나쳤다"가 실제로 나오면 그때 붙입니다.

Q 07
"보안은 괜찮습니까? 사외로 나가지 않나요?"

사내망에서만 돕니다. 외부로 나가는 경로가 없고, 접속은 기존 사내 VPN을 씁니다. 권한은 화면이 아니라 서버가 판정합니다 — 버튼을 숨기는 건 UX이고, 막는 건 서버입니다. 주소를 직접 쳐 넣어도 권한이 없으면 열리지 않습니다.

마무리

  • 치명 이슈가 있으면 그것부터 고친다. 없으면 W4 착수
  • 기록표 ③(시간 실측)을 10월 목표의 기준선으로 남긴다
  • 실물 PPT에서 깨진 곳은 파일과 함께 넘긴다 — 변환기 개선용
  • 2차 리허설(임원 대상) 일정과 교육 시간을 잡는다
