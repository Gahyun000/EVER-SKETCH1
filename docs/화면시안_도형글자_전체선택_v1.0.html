안 ㄱ
  • 얻는 것 — 처음 채울 때 한 번에 덮어씀(신고된 불편). 이미 쓴 글자의 오타 고치기는 지금 그대로.
  • 잃는 것 — 규칙이 둘이라 「왜 이번엔 전체 선택이 안 되지?」가 생길 수 있음. 오른쪽 위 기본 표시 같은 단서가 있으면 덜함(선택 사항).
  • 구현 메모 — 글자를 비교해서 판정하지 않습니다. 사람이 일부러 「가지 2」라고 쓴 것까지 기본으로 오인하기 때문입니다. 마인드맵·새 도형이 만들 때 요소에 ph: true 를 달고, 한 글자라도 고치면 지웁니다.
안 ㄴ
  • 얻는 것 — 규칙 하나. 설명할 게 없음. 통째로 바꾸기도 한 번에.
  • 잃는 것 — 이미 쓴 문장의 한 글자만 고치려면 매번 한 번 더 눌러야 함. 9월에 「더블클릭했는데 아무 일도 안 일어난 것처럼 보인다」는 이유로 누른 자리 커서를 넣었던 결정을 되돌리는 셈.
  • 구현 메모 — onDoubleClick 에서 좌표를 넘기지 않으면 끝(한 줄).
제 의견 — ㄱ. 신고된 일(처음 채우기)은 두 안 모두 풀립니다. 갈리는 곳은 이미 쓴 글자를 고칠 때인데, 보고서에서는 통째로 바꾸기보다 오타 한 글자 고치기가 훨씬 잦습니다. ㄴ 은 그 잦은 일에 매번 한 번씩 더 누르게 합니다.
