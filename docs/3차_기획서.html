3차 기획 — HTML Import: 붙이면 표지·목차·페이지로 자동 분해

이사님이 주시는 HTML 문서 파일을 올리면, 규칙이 이를 표지·목차·페이지 카드로 자동 분해합니다. 원본의 색·서식은 버리고 새 design.md로 정규화하며, 필요하면 ‘AI로 정리’ 버튼으로 카드타입·문구를 다듬습니다(항상 사람이 확인). 뒷단(내보내기·이북 굽기)은 그대로 — uniever_ebook 무수정. 1·2차와 같이 코드 전 계획부터 확정합니다.

1왜 3차인가 — 문제와 핵심 난제

1차는 손으로 카드를 조립하는 빌더, 2차는 토글·채팅·환경설정을 더했습니다. 입력은 여전히 사람의 손이었습니다.

이사님은 완성된 HTML 문서로 자료를 주십니다. 그걸 이북 형태로 옮기려면 지금은 카드를 하나씩 다시 짜야 해서 번거롭습니다. 3차는 그 앞단을 바꿉니다: HTML을 넣으면 파싱이 카드 묶음을 만들어 주고, 사람은 다듬기만 합니다.

핵심 난제 (이 한 줄이 3차의 90%)HTML은 끊김 없이 흐르는데, 이북은 고정 크기 카드 한 장 한 장입니다. 그래서 3차의 대부분은 “HTML의 무엇을, 어디서 잘라, 어떤 카드에 담을까”라는 규칙입니다. 나머지(내보내기·이북 굽기)는 이미 되어 있습니다.
이미 깔린 레일‘빈 페이지’의 블록 모델(제목·소제목·본문·목록·구분선·토글)과 목차 자동 카드가 이미 있습니다. HTML을 이 블록으로 번역만 하면, 새 렌더러 없이 기존 이북 파이프라인을 그대로 탑니다.

2변환 파이프라인 (3단계)

결정적(규칙) 부분과 AI 부분을 깔끔히 분리합니다. 규칙만으로도 완성된 이북이 나오고, AI는 그 위에 얹는 제안일 뿐이라 LLM이 없거나 틀려도 안전합니다.

[1] 규칙 파싱 (LLM 없이, 항상 동작) HTML 파일 업로드 → DOMParser ├─ 첫 h1 + 리드문 → 표지 ├─ section들의 h2 목록 → 목차(자동 카드) └─ 각 section → ‘빈 페이지’ 하나 (내부 요소를 블록으로) └─ 넘치면 ‘제목 (2)(3)’ 자동 이어붙임 │ [2] AI로 정리 (선택, 제안만) │ ← 버튼을 눌러야 실행 ├─ 카드타입 제안 (“이 섹션은 KPI 카드가 어울려요”) ├─ 문구 다듬기 (기존 ✨ 재사용) └─ 표지 제목/부제 손질 ── 전부 사람이 ‘수락’ 후 적용 │ [3] 확인 · 편집 · 굽기 │ 빌더(필름스트립·에디터)에 그대로 로드 → 손으로 고침 → ‘이북 만들기’ → PNG 폴더 → generator.py (무수정)

2) 분할 · 넘침 규칙

제목(H1/H2)마다 새 페이지를 시작합니다(H1은 표지/장 구분, H2는 페이지 제목). 한 섹션의 블록들을 카드에 채우다 높이를 넘으면 자동으로 제목 (2), (3) 페이지로 이어붙입니다.

넘침 판정 (권장)새 계산기를 만들지 말고, PageView가 이미 렌더하는 실제 높이를 재사용합니다. 글자수 추정보다 정확하고, 내보내기(export)도 같은 렌더를 쓰므로 미리보기와 결과가 어긋나지 않습니다.

3) 정규화 (서식 버리기)

원본의 색·폰트·박스 테두리 같은 껍데기는 버리고 내용만 가져옵니다. 모든 텍스트는 design.md의 폰트·색 토큰으로 다시 칠해져, 어떤 이사님 문서를 넣어도 한 가지 이북 룩으로 통일됩니다.

4‘AI로 정리’ (선택) AI

규칙 결과가 이미 완성본이므로, AI는 있으면 좋은 다듬기입니다. 전부 제안 → 사람이 수락 구조라 안전합니다.

기능동작
카드타입 제안“이 섹션은 성과가 많으니 KPI 카드가 어울려요” 같은 배지 → 수락 시 해당 카드로 전환.
문구 다듬기기존 ✨ 문구 다듬기 재사용 — 길게 늘어진 문단을 이북용으로 압축.
표지 문구 손질표지 제목/부제를 더 또렷하게 제안.
기존 배관 재사용2차의 챗 액션 브리지(ui_action → zustand, 확인 절차)가 이미 있습니다. ‘AI로 정리’는 그 위에 카드타입·문구 액션만 얹으면 되어 구현 비용이 낮습니다. LLM이 꺼져 있으면 이 버튼만 비활성 — 규칙 결과는 그대로 멀쩡합니다.

5design.md 연결 — 강조박스 → 콜아웃

서식은 정규화하지만, 이사님 문서의 색깔 강조박스는 “이건 중요해”라는 신호라 의미가 큽니다. 서브 색(초록·앰버)을 살려 콜아웃 3종으로 받습니다.

정보 (Info)참고·부연. 배경 #EAF1FE · 좌측 바 파랑 #2462EB. — 원본의 파란 박스에서.
핵심 (Key)중요·결론·성공. 배경 #E9F5EF · 좌측 바 초록 #3E9E6E. — 원본의 초록 박스에서.
주의 (Warning)경고·유의사항. 배경 #FBF0E1 · 좌측 바 앰버 #D98A2A. — 원본의 노랑/주황/빨강 박스에서.

노트 페이지 배경도 기존 파스텔 5종을 브랜드 틴트(블루·그린·앰버·중립)로 갈아끼워 콜아웃과 한 시스템으로 묶습니다.

7아키텍처 (3차 후)

[ 브라우저 ] ebook_html 프론트 (React + zustand) ├─ 카드 빌더 · 자유 캔버스 · 발표 · 단축키 (1차) ├─ 블록/토글 · 예시영상 · 환경설정 · 채팅 (2차) ├─ ★ HTML 가져오기 (파일 업로드) (3차) ├─ ★ 규칙 파서 (DOMParser → 표지·목차·페이지 블록) (3차) └─ ★ ‘AI로 정리’ (챗 액션 브리지 재사용) (3차) │ ▼ [ 로컬 서버 ] ebook_html FastAPI └─ /api/build ─────────► uniever_ebook/generator.py (무수정)

별표(★)가 3차 신규. 파싱은 브라우저 안에서 끝나고(서버 왕복 없음), 뒷단·uniever_ebook 무수정 원칙은 그대로입니다.

8마일스톤 (3차) · 게이트

1·2차와 같은 방식: 각 단계 스킬 사전 선언 → 게이트 통과(자동검증). 리스크 낮은 골격부터.

P0 입력 · 파서 골격
상단 📄 HTML 가져오기(파일 업로드) + DOMParser + 결과를 store.pages로 주입하는 배관.✔ 게이트: 임의 HTML 업로드 → 페이지 N장이 빌더에 로드.
P1 표지 · 목차 자동 생성
첫 h1+리드문 → 표지, h2 목록 → 목차(자동 카드) 연결.✔ 게이트: 표지·목차가 자동으로 생성·정렬.
P2 분할 · 넘침 이어짐
H1/H2 경계로 페이지 분할 + 실제 렌더 높이로 넘침 판정 → 제목 (2)(3) 이어붙임.✔ 게이트: 긴 섹션이 여러 장으로 자연스럽게 이어짐.
P3 정규화 · 콜아웃 · design.md 반영
원본 서식 제거 + 강조박스→콜아웃 3종 + tokens.ts/index.css에 design.md 토큰 반영(파스텔→틴트).✔ 게이트: 서로 다른 HTML도 한 가지 이북 룩으로 통일.
P4 ‘AI로 정리’ 버튼
카드타입 제안·문구 다듬기·표지 손질(제안→수락). 챗 액션 브리지 재사용. LLM 없으면 버튼만 비활성.✔ 게이트: 제안 수락 시 실제 반영, 규칙 결과는 독립적으로 완성.
P5 검증 · 증적
스모크: 샘플 HTML → 예상 페이지 수·제목·표지/목차 존재 확인. 대량 페이지 export 확인.✔ 게이트: 샘플 문서들에 대해 스모크 PASS.
P6 핸드오버
3차 핸드오버 문서 + 사용법(HTML 가져오기·AI로 정리) 갱신.✔ 게이트: 전체 스모크 PASS + 핸드오버 문서.

9리스크 & 대응
