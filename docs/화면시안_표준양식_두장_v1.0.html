표준 양식 — 한 장으로 둘까, 두 장으로 나눌까

「한 장 한 장 나눠서 두 장으로 만들어도 될 듯」에 대한 시안입니다. 정하실 것은 한 가지 — 아래 ㉮ ㉯ ㉰ 중 하나입니다.

먼저, 걱정하지 않으셔도 되는 것 세 가지 ① 취합 코드는 아직 없습니다. 저장소 전체에서 「취합」은 주석과 테스트 설명에만 나옵니다 — 여러 사람 자료를 한 권으로 엮는 코드는 아직 한 줄도 없습니다. 두 장으로 바꿔도 지금 도는 것 중 깨지는 건 없습니다.
② 뷰어는 이미 여러 장을 봅니다. 좌우 화살표·쪽 번호(3 / 7)·섬네일이 다 있습니다. 새로 만들 것이 없습니다.
③ 슬롯은 쪽에 매여 있지 않습니다. SLOT-B 를 찾을 때 「1쪽의」라고 쓴 곳이 없어서, 2쪽으로 옮겨도 편집 정책·코멘트 앵커가 그대로 따라갑니다.

1세 갈래

2「1인 1장」이 지키려던 것

약속의 근거는 사양서 v2.0 에 「취합 단위 = 사람」 한 줄입니다. 지키려던 건 쪽수가 1이라는 것이 아니라 사람마다 구조가 똑같다는 것입니다. 그래서 ㉯(2장 고정)는 이 약속을 그대로 지키고, ㉰(넘칠 때만)는 깹니다 — 어떤 사람은 2쪽이 있고 어떤 사람은 없으면, 엮은 책에서 「몇 번째 쪽이 이슈 리스트인가」가 사람마다 달라집니다.

그리고 이건 원래부터 열어 둔 질문이었습니다 사양서 v1.0 §7.2 「리허설에서 확정」 표의 2번 항목이 그대로 이겁니다 — 「1인 1장이 충분한지 — 사업이 많은 본부는 2장 필요할 수 있음 / 잠정: 1장 유지 / 확정 시점: W5 리허설 실측」. 지금 실제로 써 보시고 「모자란다」가 나온 것이니, 이건 약속을 어기는 게 아니라 예약해 둔 질문에 답이 나온 것입니다. 다만 답이 나왔으면 아래 여섯 군데를 같이 고쳐야 합니다 — 한 군데만 고치면 「문서는 1장이라는데 코드는 2장」이 되고, 그게 지금 slot_allows 와 「＋ 새 페이지」에서 이미 벌어진 일입니다.

3남는 구멍 하나 — 「＋ 새 페이지」

어느 쪽으로 정하시든 「＋ 새 페이지」 버튼은 여전히 아무도 막지 않습니다. 2장으로 정해도 사용자가 3장, 5장을 만들 수 있고 그때 취합은 다시 깨집니다. 지금은 약속만 있고 잠금이 없는 상태 — slot_allows() 가 테스트에서만 쓰이고 서버는 state 를 그대로 저장하던 것과 정확히 같은 모양입니다.
제안: 표준 양식으로 만든 자료에서는 쪽 추가·삭제를 화면에서 아예 감추고, 서버 저장에서도 쪽수가 정해진 값과 다르면 거부합니다. 그래야 이번엔 약속이 실제로 지켜집니다.
