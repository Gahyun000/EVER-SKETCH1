# 작업이력대장 — 2026-08-11 · 덱→PPTX 밀도 정리(자동 압축 + LLM 요약)

> '글 많은 원문이 그대로 슬라이드에 쏟아지는' 문제를 변환기 앞단(`extractor.py`)에서 정리한다.
> 편집 가능한 PPTX 구조·EVER-PEAK 팔레트는 유지하고, **내용 밀도만** 성글게. 결정: 사용자 "둘 다".
> 활동 기록이며 정본 문서를 대체하지 않는다.

## 배경
- 팔레트를 EVER-PEAK 로 맞춰도 미리보기만큼 안 예쁜 핵심 원인은 **밀도** — extractor 가 원문 문단·불릿을
  거의 그대로 카드 설명(≤130자)에 담아 '글 벽'이 됐다(긴 카드 겹침도 발생). 미리보기 덱은 사람이 문장을 추린 것.
- 결정(사용자): **둘 다** — ① 항상 자동 압축(휴리스틱), ② LLM 연결 시 요약으로 업그레이드.

## 적용 스킬(사전 선언)
- uniever-development-standard — 작업대장.
- karpathy-guidelines — 압축·요약 배선까지만. IR 스키마·deck_builder·프론트 무변경(과잉구현 금지).
- test-driven-development — extractor 압축/요약 단위테스트(mock summarize_fn) + /api/deck e2e.
- verification-before-completion — 실제 파이프라인 before/after 렌더 대조 + 테스트.

## 변경
- `server/deck/extractor.py`
  - **자동 압축(항상)**: `_condense()`(첫 문장 우선·~76자)로 카드 설명 축약, 리드 ~92자, **페이지당 카드 ≤6**(MAX_CARDS),
    표지 카드 ≤3. 원문 덤프 → 성근 슬라이드. 긴 단일문장 겹침도 상한으로 해소.
  - **LLM 요약(옵션)**: `extract(html, theme, title, summarize_fn=None)`. `summarize_fn(title,text)->{headline,bullets}` 을
    주면 섹션을 헤드라인(리드)+핵심 bullets(카드)로 더 압축. 실패·빈값·예외는 휴리스틱으로 폴백(무크래시).
- `server/deck/convert.py` — `convert(..., summarize_fn=None)` 로 통과.
- `server/app.py` `/api/deck` — LLM 설정이 `configured` 면 `_llm_chat`+`_SUMM_SYS` 기반 `summarize_fn` 을 만들어 주입,
  없으면 None(휴리스틱). 기존 `/api/summarize` 요약 규격 재사용.
- 신규 `server/deck/test_extractor.py`. IR 스키마·`deck_builder.js`·프론트는 무변경.

## 검증 증적(2026-08-11, 컨테이너 = 실제 파이프라인 bs4+pptxgenjs 3.12.0+soffice)
- `python3 test_extractor.py` → **ALL PASS (10)**: 카드 설명 ≤76자, 페이지당 카드 ≤6, 표지 ≤3, 리드 상한,
  _condense 첫 문장/상한, LLM bullets→카드·headline→리드, summarize None/예외 → 휴리스틱 폴백.
- **before/after 렌더 대조**(글 많은 샘플, 팔레트 동일): 원문(글 벽·카드 겹침) → 자동 압축(첫 문장·겹침 해소) →
  LLM 요약(섹션당 핵심 3줄, 미리보기처럼 성글게). 비교 이미지 첨부.
- `/api/deck` e2e(FastAPI): 휴리스틱 200·ok·섹션 카드 최대 desc **72자**; LLM(monkeypatch) 200·섹션 카드=요약 bullets.
- `py_compile`(convert/app), `node --check`(deck_builder) 통과. 디바이스 반영.

## 남은 여지

- 통짜 이미지(픽셀 100%·편집 불가) 내보내기를 별 버튼으로 병행 제공(옵션 1).
