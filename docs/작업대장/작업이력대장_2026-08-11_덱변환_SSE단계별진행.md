> 앞선 '동적 로딩(스켈레톤)'을 **진짜 단계별 진행**으로 승격 — 추출→빌드→PDF→슬라이드별 렌더를
> 서버가 SSE 로 흘리고, 프론트가 바를 실제로 채우며 렌더된 슬라이드가 스켈레톤을 하나씩 대체.
> 적용 스킬: harness-loop-engineer(스트림 파이프라인), frontend-design, verification-before-completion.

## 변경
- `server/deck/convert.py` — `convert_stream()` 제너레이터 추가. 이벤트: extract(6%)→build(24%)→pdf(40%)→
  render(슬라이드별, 45→98% + 썸네일 URL)→done(result: pages/pptx_url/pdf_url/thumbs/ir). 기존 `convert` 유지.
- `server/app.py` — `POST /api/deck/stream`(StreamingResponse, text/event-stream) + `_deck_summarizer()` 공용화.
  LLM 설정 있으면 섹션 요약 주입(없으면 휴리스틱). 기존 `/api/deck` 그대로 폴백용 유지.
- `src/builder/chrome/ClassicBar.tsx` — `onImportFile` 을 fetch 스트림 리더로: 이벤트마다 pct/stage/live썸네일 갱신.
  `BusyView` 를 실시간판으로: 진행률로 바 채움(determinate), 도착한 썸네일이 스켈레톤 자리를 실제 슬라이드로 대체,
  캡션에 단계 문구+%+파일명. 스트림 실패 시 `/api/deck` 비스트리밍 폴백.
