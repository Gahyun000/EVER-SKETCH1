## 1. 판단 — **뜻이 안 섞이게 하는 규칙 셋**

이번 정리의 핵심은 44곳을 바꾸는 것이 아니라 **말 하나에 뜻 하나를 묶는 것**입니다.
지금은 「회수」 하나가 서로 다른 **네 가지**를 가리킵니다.

| 지금 「회수」가 가리키는 것 | 곳 | 정리 뒤 |
|---|---|---|
| 낸 사람이 대기 중인 결재를 되가져옴 (`withdrawn`) | 10 | **「회수」 — 여기만** |
| **자료를 지움** | **4** | **「삭제」로 바꾼다** |
| 메모리 해제 (`history.ts`) | 1 | 그대로 — 프로그래밍 용어다 |
| 옛 「배부 회수」 화면 (없어진 기능) | 2 | 과거형이면 그대로, 현재형이면 고친다 |

### 규칙 ① 「회수」는 **결재 전용**이다

자료를 지우는 것은 **삭제**다. 지금 네 곳이 자료 삭제를 「회수」라고 부른다 —
**여기를 안 고치면 통일이 아니라 뜻이 하나 더 늘어난다.**

| 자리 | 지금 | 바꿀 말 |
|---|---|---|
| `projects.py:311` | 자료를 **회수**했는데 그 자료에 달린 메모는 | 자료를 **지웠는데** |
| `projects.py:313` | **회수** 사유가 '잘못 배부' 라면 | **삭제** 사유가 '잘못 만든 자료' 라면 |
| `test_comments.py:8` | 자료를 **회수**하면 지적도 함께 사라진다 | 자료를 **지우면** |
| `test_comments.py:306` | **회수**했는데 지적 내용은 DB 에 남는다 | **지웠는데** |

예외 하나: `src/canvas/history.ts:29` 「메모리 회수」는 결재와 아무 상관이 없는
프로그래밍 용어다. 그대로 둔다.

### 규칙 ② 「거두」는 **안 쓴다** — 단, 그게 옛 말이었다는 기록은 남긴다

26곳을 「회수」로 바꾼다. 딱 한 곳만 남긴다:

> `page_shape.test.mjs:3` — *2026-09-08, 결재 **「거두기 → 회수」**를 확인하려고…*

여기서 「거두기」는 **그날 무슨 말을 쓰고 있었는지가 곧 내용**이다.
이걸 「회수 → 회수」로 바꾸면 문장이 뜻을 잃는다.

### 규칙 ③ 「배부」는 **과거형으로만** 쓴다

회차·배부는 2026-09-04 에 걷어냈다. 코드도 API 도 없다.
그런데 글이 **현재형으로** 말하면 다음 사람은 없는 화면을 찾아 헤맨다.

- **현재형 19곳** → 고친다
- **과거형·근거 15곳** → **손대지 않는다**

지우지 않는 게 중요하다. 예를 들어
`test_template_geometry.py:6` 「배부를 **눌렀다면** 임원들에게는 **빈 종이**가 **갔다**」는
표를 왜 종이 안에 그려야 하는지의 **근거**다. 지우면 규칙만 남고 이유가 사라진다.

## 5. **다시 섞이지 않게 — 검사로 못 박는다**

한 번 고쳐 놓고 끝내면, 다음에 누가 새 주석을 쓸 때 다시 섞입니다.
그래서 `term_recall.test.mjs` 를 만들어 규칙 셋을 검사로 옮깁니다.

| 검사 | 규칙 |
|---|---|
| 「거두」가 없다 | 규칙 ② — 남길 한 곳만 예외로 적어 둔다 |
| 자료를 지우는 파일에 「회수」가 없다 | 규칙 ① — `projects.py`·`comments.py`·`test_comments.py` |
| 「배부」가 현재형으로 안 쓰인다 | 규칙 ③ — 과거형(…었/했/전에는/없앴)은 통과 |
| 예외 목록이 실제로 그 자리에 있다 | 예외가 죽으면 검사가 조용히 헐거워진다 |

**예외를 목록으로 적는 것이 핵심입니다.** 그래야 다음에 누가 예외를 늘릴 때
목록에 한 줄을 적으면서 **왜 예외인지 한 번 생각하게** 됩니다.
