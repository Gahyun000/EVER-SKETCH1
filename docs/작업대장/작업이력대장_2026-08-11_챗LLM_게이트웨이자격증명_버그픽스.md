# 작업이력대장 — 2026-08-11 · 챗 LLM 호출 게이트웨이 자격증명 버그픽스

> 증상: 환경설정 **연결 테스트는 성공**하는데, 챗봇에 질문하면 **"LLM 연결 안 됨"** 폴백이 뜬다.
> 적용 스킬: systematic-debugging(경로 대조로 원인 격리), verification-before-completion(요청 캡처 검증).

## 원인(격리)
- 챗/생성/편집이 쓰는 `server/chat.py::_call_llm` 과, **연결 테스트**(`app.py::_llm_test_call`)·**요약**(`app.py::_llm_chat`)의
  자격증명 첨부 방식이 달랐다.
  - 테스트/요약(성공): `Authorization` + **`x-api-key` 헤더** + **본문 `api_key`·`user_id`**(유니에버 게이트웨이 호환).
  - `_call_llm`(실패): `Authorization` 헤더 + `X-User-Id` 만 — **본문 자격증명·x-api-key 없음**.
- 유니에버 자체 게이트웨이가 본문 자격증명을 요구 → 테스트는 통과, 챗의 실제 호출은 거부 → `_call_llm` None → `_fallback_reply`("연결 안 됨").
- URL 은 무관: 테스트·챗 모두 동일한 `llm_endpoint()` 로 생성 → 주소는 같았다. 차이는 자격증명뿐.
- 영향 범위: 챗 대화 + 생성 레인(G4) + 편집 레인(G5) 전부(모두 `_call_llm` 경유). `/api/plan`·`/api/edit`·`/api/summarize`·`/api/deck` 요약은 `_llm_chat` 사용이라 원래 정상.

## 수정
- `server/chat.py::_call_llm` 의 self(비-anthropic) 분기를 `_llm_chat` 과 동일하게:
  `x-api-key` 헤더 추가 + 본문에 `api_key`·`user_id` 포함.

## 검증 증적(2026-08-11)
- `py_compile` 통과.
- 요청 캡처 테스트(`urlopen` 목킹): `_call_llm` 이 이제 헤더 `authorization`+`x-api-key`+`x-user-id`, 본문 `api_key`+`user_id` 를 실어 보내고,
  게이트웨이 응답(choices[0].message.content) 파싱 성공 확인.

## 반영 후 필수
- **서버 재시작 필요**: uvicorn 이 `--reload` 없이 떠서 chat.py 변경이 자동 반영 안 됨. `run.command` 터미널 Ctrl+C 후 재실행(또는 서버 재기동).
- 재시작 후 챗에 "안녕" 등 질문 → 게이트웨이 실답변이 오면 성공. 그래도 실패면 게이트웨이 응답 형식(choices 외 필드) 추가 확인.
