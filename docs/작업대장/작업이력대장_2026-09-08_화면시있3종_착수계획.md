## 0. 먼저 — 셋 중 둘은 이미 만들었습니다

착수 계획을 세우기 전에 시안과 실제 코드를 한 줄씩 대조했습니다.

| 시안 | 상태 |
|---|---|
| **패널결재** | **거의 다 됨** (커밋 `c9a0f66`) — 셋 빠짐 |
| **도구패널** | **대체로 됨** (`3c07f77` · `22dd552` · `5a4afce`) — 둘 빠짐, **하나는 시안과 다르게 만듦** |
| **셸구조** | **손도 안 댐** |

그래서 이 계획은 「셋을 새로 만드는 계획」이 아니라
**「빠진 것 다섯 + 셸 하나」의 계획**입니다.

## 1. 패널결재 — 빠진 셋

| # | 시안이 말한 것 | 지금 | 왜 빠졌나 |
|---|---|---|---|
| B-1 | **반려 사유를 그 자리에서 읽는다**<br>「로드맵 3분기 칸이 비어 있습니다」 — 관리자, 9/2 | 「반려됐습니다. 고쳐서 다시 낼 수 있습니다」 <b>일반 문구</b> | 아래 참고 |
| B-2 | 「낸 것 보기」 · 「승인본 보기」 | 없음 | 스냅샷 뷰어를 편집 화면에서 여는 길이 없었다 |
| B-3 | 「수정 그만두기」 | 없음 | `apiEndRevision` 은 있는데 안 불렀다 |

### B-1 이 시안의 약속과 어긋나는 지점

시안에는 **「서버는 손대지 않습니다」**라고 적었습니다. 그건 상태·저장·의견까지는 맞습니다.
그런데 **반려 사유는 `/status-map` 이 안 줍니다** —

```
StatusChip = { approval_id, status, round, kind, decided_at, created_at, state, locked }
                                                                    ↑ 사유가 없다
decision_message 는 Approval(상세)에만 있다
```

고르는 길이 둘입니다.

- **ㄱ · 상세를 한 번 더 부른다** — `apiGetApproval(chip.approval_id)`.
  서버 안 고침. 대신 **반려·수정 중일 때 요청이 한 번 더** 나갑니다(그 때만).
- **ㄴ · `/status-map` 에 사유를 실어 준다** — 서버 한 줄.
  요청은 안 늘지만 **목록 열 때마다 사유가 12건씩** 따라옵니다.

**ㄱ을 권합니다.** 반려는 드물고, 그때만 한 번 더 묻는 게 늘 싣고 다니는 것보다 낫습니다.

## 2. 도구패널 — 빠진 둘, 그리고 다르게 만든 하나

| # | 시안 | 지금 |
|---|---|---|
| C-1 | 툴바 **가운데가 고른 것을 따라간다**<br>표→표 도구 · 글상자→글자 도구 · 연결선→선 도구 | **안 함.** 그리기 도구만 접었다 |
| C-2 | 접고 편 상태를 **기억한다** | **안 함.** 고를 때마다 초기화된다 |
| C-3 | 묶음을 **일 단위로 다시 나눈다**<br>칸 · 행 · 진행 표시 · 크기·자리 · 테두리·머리글 | **다르게 만듦** — 옛 탭 이름 그대로(표 · 스타일 · 텍스트 · 정렬) |

### C-3 을 짚고 갑니다 — 여기가 제일 큰 차이입니다

시안이 든 예가 정확히 이것이었습니다:

> 「크기」가 **정렬 탭**에 있습니다. 표 칸의 글자를 키우려면
> 「셀 글자 크기」(표 탭)인지 「글자 크기」(텍스트 탭)인지 먼저 정해야 합니다.

제가 만든 것은 **탭 넷을 그대로 접이식으로 감싼 것**입니다. 넷이 한 화면에 보이니
「어느 탭에 있더라」는 줄었지만, **「크기」가 정렬 안에 있는 것은 그대로**입니다.
시안이 없애자고 한 그 문제가 반만 풀렸습니다.

- **ㄱ · 지금대로 둔다** — 넷이 한 화면에 있으니 찾기는 이미 나아졌다. 위험 0.
- **ㄴ · 시안대로 다시 나눈다** — 「크기」가 「크기·자리」로 가고, 표의 글자 크기와
  글상자의 글자 크기가 **같은 「글자」 묶음**에 온다.
  대신 `RightPanel` 본문을 **처음으로 실제로 재배치**합니다 —
  지금까지는 본문을 한 글자도 안 건드렸습니다.

**정해 주셔야 합니다.** ㄴ이 시안의 뜻이지만, 이번 세션에서 가장 큰 재배치가 됩니다.

## 3. 셸 — 안 한 것

### 지금 구조

```
App.tsx
  view === 'editor' ? <Layout/> : <LibraryScreen/>      ← 화면은 둘뿐
  덮개: 결재함 · 팀 공유 (LibraryScreen 안)
        환경설정 (Layout 안)
        팀 관리 · 계정 관리 (UserBar 안)
  라우터: **없다** (주소는 ApprovalViewer 링크 하나만 씀)
```

### 셸이 실제로 요구하는 것 넷

1. **`LibView` 를 둘에서 여섯으로** — `library · editor · inbox · team · admin · settings`
2. **덮개 다섯을 화면으로** — 지금 `onClose` 를 받는 패널들이라, 껍데기를 벗기고
   본문만 셸 안에 놓아야 합니다. 다섯 파일이 다 바뀝니다.
3. **셸 컴포넌트** — 머리 52px + 사이드바 214/60px + 빵부스러기 + 역할별 메뉴 + 대기 배지
4. **주소** — 시안이 말한 「뒤로 가기·새로고침이 안 통한다」를 정말 고치려면 여기가 필요합니다

### 주소를 어디까지 할지가 갈림길입니다

- **ㄱ · 안 한다** — 셸만 넣는다. 갈 곳은 왼쪽에 늘 있지만
  **새로고침하면 「내 자료」로 돌아옵니다.** 시안이 든 불만 중 하나가 안 풀립니다.
- **ㄴ · `history.pushState` 로 최소만** — `/inbox` · `/team` 정도.
  라우터 라이브러리 없이 50줄쯤. 뒤로 가기·새로고침이 통합니다.
- **ㄷ · 라우터를 넣는다** — 의존성이 하나 늘고 `App.tsx` 가 다시 짜입니다.

**ㄴ을 권합니다.** 이미 `ApprovalViewer` 가 `window.location.pathname` 을 읽고 있어서
주소를 보는 습관이 코드에 이미 있습니다.

### 그리고 편집 화면

시안 그림은 편집 화면도 셸 안에 있습니다. 그런데 편집 화면은
**왼쪽 필름스트립 + 캔버스 + 오른쪽 패널**로 이미 꽉 차 있습니다.
사이드바 214px 를 더 얹으면 캔버스가 그만큼 좁아집니다 —
**방금 C에서 패널 자리를 아끼자고 한 것과 반대로 갑니다.**

- **ㄱ · 편집에서는 사이드바를 기본 접힘(60px)** — 아이콘만. 갈 곳은 있고 자리는 덜 먹는다.
- **ㄴ · 편집은 셸 밖에 둔다** — 지금처럼 전체 화면. 나가는 길은 「☰」 하나 그대로.

**ㄱ을 권합니다.** 「편집 중에도 나갈 수 있다」가 셸을 넣는 이유의 절반입니다.

## 4. 순서

```
0. 푸시 (69 커밋)
   ↓
1. B 잔여 셋 — 작다, 이미 있는 카드에 붙인다
   ↓
2. C-1 · C-2 — 툴바·기억. 파일 둘
   ↓
3. C-3 재편 — **정해 주시면**. RightPanel 본문 재배치
   ↓
4. 셸 — 혼자 화면 전체를 바꾼다. 맨 뒤
```

**왜 셸이 맨 뒤인가.** 셸은 덮개 다섯 개의 껍데기를 벗깁니다.
그 다섯 중 넷(`ApprovalsPanel` · `TeamLibraryPanel` · `UsersAdmin` · `TeamsAdmin`)은
**이번 세션에 A②·ㄴ으로 이미 손을 댄 파일**입니다. 지금 또 뜯으면
무엇이 무엇을 깨뜨렸는지 가려내기 어려워집니다. 한 번 쓰고 나서 가는 게 낫습니다.

**왜 푸시가 먼저인가.** 69 커밋이 이 노트북 디스크에만 있습니다.
셸은 이번 세션에서 가장 크게 뜯는 작업입니다 — 되돌릴 데가 없는 채로 시작하지 않는 게 좋습니다.

## 5. 위험

| 위험 | 왜 | 대응 |
|---|---|---|
| 덮개 다섯을 화면으로 바꾸다 A②·ㄴ이 깨진다 | 같은 파일을 두 번째로 뜯는다 | 하나씩. `modal_shell.test.mjs` 를 매번 돌린다 |
| 편집 화면이 좁아진다 | 사이드바가 214px 를 먹는다 | 편집에서는 기본 접힘(60px) |
| 주소를 넣다 `ApprovalViewer` 링크가 깨진다 | 이미 `pathname` 을 읽고 있다 | 그 경로를 먼저 검사로 못박고 시작 |
| C-3 재편이 도구를 잃는다 | 본문을 처음으로 실제 재배치 | 재배치 전에 **지금 있는 도구를 전부 세는 검사**를 먼저 만든다 |

마지막 것을 특히 지킵니다 — **옮기기 전에 세어 두지 않으면 하나 잃어도 모릅니다.**

## 7. 이 계획이 다루지 않는 것

시안 「셸구조」 3번이 남겨 둔 넷 중 **둘은 이미 끝났고**(패널 탭 → C①, 도구 흩어짐 → C②),
남은 둘은 여기서도 안 다룹니다:

- **새 페이지 고르기** — 시안에는 카드 14종이라 적혔는데 **세어 보니 19종**입니다.
  이름만으로는 뭔지 모르는 문제는 그대로입니다.
- **자료 목록의 결재 칩** — 편집 화면에는 B로 카드가 생겼지만 **목록 칩은 그대로**입니다.

둘 다 따로 시안을 만들어야 하는 크기입니다.
