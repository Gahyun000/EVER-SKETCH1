### 판단 근거 — ㉮ 방식의 유일한 함정을 구조로 없앴다

- [x] 버튼식에는 **「확인은 했는데 그 뒤에 아이디를 고친」 상태**가 존재한다.
      이 상태를 무효로 되돌리지 않으면 **중복된 아이디로 가입 버튼이 켜진다.**
      서버가 막아 주긴 하지만 그건 *막는 것*이지 *알려주는 것*이 아니고,
      사용자가 보는 것은 "확인까지 했는데 왜 안 되지"다.
- [x] **그래서 화면은 「확인했다」는 깃발을 들지 않는다.** `checkedFor`(어떤 값으로 확인했는가)를
      들고 지금 값과 **매번 비교**한다. 깃발이면 지우는 걸 빠뜨릴 수 있지만, 비교는 빠뜨릴 자리가 없다.
      `signup_check.test.mjs` 의 `'확인 뒤 아이디를 고치면 다시 막힌다 — 이게 핵심이다'` 가 이 계약이다.
- [x] **대소문자·공백만 달라진 것은 「고친 것」이 아니다.** `gahyun` 으로 확인한 뒤 ` GaHyun ` 이 되어도
      유효하다. 정규화 규칙을 서버 `signup()`(`strip().lower()`)과 같게 맞췄다 — 다르면
      "확인한 아이디"와 "실제로 가입되는 아이디"가 어긋난다.
- [x] **형식이 확인 결과를 이긴다.** 확인해 둔 값이 있어도 지금 값의 형식이 틀렸으면 형식부터 말한다.
      아니면 「사용할 수 있습니다」와 틀린 형식이 화면에 함께 떠 있게 된다.
- [x] **확인 요청이 실패하면 「확인 안 함」으로 되돌린다.** 실패를 「사용 가능」으로 두면
      눌러 놓고 가입에서 막힌다.
- [x] 형식은 **서버에 묻지 않고 화면이 판정**한다. 서버 호출은 형식이 맞은 다음에만 나간다 —
      규칙이 화면에 아예 없던 것도 함께 고쳤다(「사내 아이디」뿐이었다).

### 판단 근거 — 계정 존재 노출

- [x] **이 API 는 제품의 다른 규칙과 반대 방향이다.** 로그인 실패는 "아이디 또는 비밀번호"로
      뭉개고, 자료 조회는 404 와 403 을 일부러 통일한다(`authdeps.require_project`).
- [x] **그래도 넣는 근거: 이미 새고 있다.** 가입 폼을 제출하면 지금도

      **있는 구멍을 빠르게** 만든다. 그래서 막을 것은 "알려주는 것"이 아니라 **"빠르게 많이 묻는 것"** 이다.
- [x] 방어: 같은 IP **1분 20회**(사람이 가입하며 누르는 횟수는 몇 번, 긁는 쪽은 수천 번) ·
