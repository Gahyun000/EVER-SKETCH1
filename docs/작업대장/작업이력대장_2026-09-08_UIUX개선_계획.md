## 2. 순서와 그 이유

```
0. 올리기(보험)  →  A. 확인창 표준  →  B. 패널 결재  →  C. 도구 패널  →  D. 셸
                     ↑ 여기가 먼저인 게 핵심
```

### A가 B보다 먼저인 이유 — 안 그러면 같은 일을 두 번 한다

B(패널 결재)는 **편집 화면에 확인창을 하나 더 만드는 일**이다.
A를 건너뛰고 B를 하면 손으로 그린 확인창이 8개에서 **9개**가 된다.
A를 먼저 하면 B는 `ui/Modal` 을 그냥 가져다 쓴다 — 새로 그릴 게 없다.

이건 취향이 아니라 순서의 문제다. 뒤집으면 B에서 만든 창을 나중에 다시 뜯는다.

### ㉠의 답이 B와 C를 붙일지 뗄지를 정한다

- **ㄱ(패널 맨 위 고정)을 고르면** — 카드가 탭보다 위에 얹히므로,
  C가 바꾸는 **본문 구조(탭 → 접이식)와 안 겹친다.** B와 C를 따로, 순서 상관없이 할 수 있다.
- **ㄴ(아무것도 안 골랐을 때)을 고르면** — 카드가 「페이지」 패널 **안**으로 들어간다.
  C도 같은 자리를 건드린다. **둘을 한 덩어리로 묶어야** 하고, 그만큼 한 번에 커진다.
- **ㄷ(맨 아래 고정)을 고르면** — ㄱ과 같이 떼어낼 수 있지만,
  표 탭이 길어서 카드가 내용을 가리는 문제를 C(접이식)가 **먼저** 줄여 놔야 쓸 만하다. 즉 **C → B** 순서가 강제된다.

**권하는 것: ㄱ.** 셋 중 유일하게 순서를 안 묶는다.

### D(셸)가 마지막인 이유

셸은 「어디로 가는가」를 바꾼다 — 결재함이 왼쪽 나비게이션으로 올라간다.
그러면 B의 카드에 「결재함으로」 같은 연결이 생기고, 라이브러리의 제출 아이콘도 자리를 옮긴다.
반대로 **B·C는 셸이 어떻게 생겼든 그대로 산다.** 의존이 한쪽으로만 흐르므로 큰 것을 나중에 둔다.

## 3. A · 확인창 표준 맞추기

> 시안: `docs/화면시안_확인창표준_v1.0.html`

### A① 작성자 확인창 4개에 진행 중 잠금 — **가장 먼저**

지금 「제출」을 빠르게 두 번 누르면 요청이 두 번 간다.
서버는 두 번째를 「이미 결재 대기 중입니다」로 막지만, **화면에는 빨간 오류로 뜬다.**
성공했는데 실패한 줄 안다. 넷 중 **지금 사용자에게 틀린 화면을 보여주는 유일한 항목**이다.

- 손댈 곳: `src/persistence/LibraryScreen.tsx` — `busy` 상태가 **하나도 없다**(변수 0개).
  확인창 4개(제출 · 수정 요청 · 자료 삭제 · 폴더 삭제) 전부.
- 검증: `busy` 를 일부러 빼고 e2e에서 두 번 눌러 **두 번 가는 것을 먼저 본다.**
  넣고 나서 한 번만 가는지 본다. 깨뜨려 보지 않은 잠금은 잠금이 아니다.

### A② 손수 만든 확인창 8개를 `ui/Modal` 로 갈아 끼움

| 파일 | 개수 |
|---|---|
| `LibraryScreen.tsx` | 4 (429 · 469 · 503 · 547) |
| `ApprovalsPanel.tsx` | 1 (314) |
| `UsersAdmin.tsx` | 2 (171 · 224) |
| `TeamsAdmin.tsx` | 1 (306) |

Esc · 포커스 가두기 · 포커스 되돌리기 · 배경 스크롤 잠금 · `role="dialog"` 가 한 번에 따라온다.
**새로 만드는 게 아니라 갈아 끼우는 일이다** — 문구는 지금 것이 표준보다 나으니 그대로 옮긴다.

- **한 번에 하나씩** 바꾸고 매번 테스트한다. 8개를 한 커밋에 넣지 않는다.
- 화면 테스트 다섯(`approvals_screen` · `revision_screen` · `folder_screen` · `teams_screen` · `viewer_screen`)이
  확인창을 클래스 이름으로 찾고 있을 수 있다. **`ui/Modal` 이 `className`·`scrimClassName` 을 받는 이유가 정확히 이것** —
  기존 이름을 그대로 넘겨 선택자를 살린다.

### A③ 삭제 확인창은 **글로도** 구분

표준은 「시각적으로도 **문구로도** 구분」을 요구한다. 지금은 버튼만 빨갛다 —
색을 못 보는 사람에게는 승인 창과 똑같이 보인다.

### A④ 검사 하나 더 — 다음에 또 손으로 그리는 것을 막는다

`no_native_dialogs.test.mjs` 옆에 「스크림을 직접 그리지 않는다」를 둔다.

**주의 — 글자로 잡으면 안 된다.** A② 뒤에도 `scrimClassName="es-confirm"` 은 남는다(선택자를 살리려고).
`<div className="es-confirm">` 처럼 **div에 직접 붙은 것만** 잡아야 한다.
안 그러면 검사가 방금 고친 코드를 틀렸다고 한다.

이 검사가 없으면 다음에 급할 때 또 손으로 그린다 — **이번 8개가 그렇게 생겼다.**

## 4. B · 패널에서 결재 제출

> 시안: `docs/화면시안_패널결재_v1.0.html` · **㉠의 답이 나와야 시작한다**

### 새로 만드는 것은 하나뿐

| 조각 | 상태 |
|---|---|
| 저장 상태 | `useAutosave` — 있음 |
| 확인 안 한 의견 | `countMyTurn` — 있음(미리보기 위에 이미 뜸) |
| 문서 상태 | `/api/approvals/status-map` — **서버에 있고 목록만 부른다** |
| 제출 · 수정 요청 API | 있음 |
| **빈 칸 세기** | **새로** |

**서버는 손대지 않는다.**

### 지킬 것 셋

1. **제출은 저장부터 하고 낸다.** 결재본은 서버에 저장된 문서를 얼린다.
   목록에서 낼 때는 `backToLibrary()` 가 나오면서 `flushSave()` 를 해 줘서 **우연히** 맞았다.
   편집 화면에서 바로 내면 그 우연이 없다 — **방금 쓴 줄이 빠진 채로 얼어붙는다.**
   버튼이 `flushSave → request` 순서로 묶여야 한다.
2. **상태는 서버가 말한 것만 그린다.** 대기·승인·수정 중을 화면이 다시 계산하면 규칙이 두 곳에 생기고,
   어긋나는 날 사용자에게는 「승인이라 적혔는데 안 눌린다」로 보인다.
3. **빈 칸이 있어도 막지 않는다.** 알리고 그 칸으로 데려다 줄 뿐이다.
   임원이 일부러 비우는 칸이 있다(「이번 달 해당 없음」). 화면이 대신 판단해 막으면
   그 사람은 고장 났다고 이해하고 관리자에게 전화한다.

### 빈 칸 세기 — 반드시 `.ts`

`node --experimental-strip-types` 는 **`.tsx` 를 못 읽는다.** 이 저장소에서 이미 두 번 걸린 자리다.
순수 함수를 `.ts` 로 빼고, 화면은 그것을 부르기만 한다. 표준 양식에만 표시하고 자유 이북에는 안 띄운다(칸 이름이 없으니까).

## 5. C · 도구 패널 개선

> 시안: `docs/화면시안_도구패널_v1.0.html`

1. 탭 4개 → 접이식. 접힌 줄에 **현재 값**이 보인다(「글자 12pt」).
2. **패널의 병합/해제 삭제** — 툴바와 겹치는 유일한 중복.
   `table_merge_smoke.mjs:135` 가 「오른쪽 패널을 열지 않아도 툴바에 병합이 있다」를 지키고 있다.
   예전에 일부러 툴바 쪽을 고쳐 넣은 것이므로 **툴바가 본체, 패널 쪽이 사족**이다.
3. 툴바가 선택을 따라간다. 표를 고르면 펜·형광펜·지우개는 「그리기」 하나로 접힌다.
4. 패널 머리에 무엇을 골랐는지 — 표준 양식이면 칸 이름 그대로(「① 로드맵 / 마일스톤」).

**기능은 하나도 안 없앤다.** 줄어드는 건 중복 병합 버튼 하나(2개 → 1개)뿐이다.

> 「자주 쓰는 것」을 위로 올린 순서는 **내 짐작이다.** 재 본 게 아니다.
> 임원진이 실제로 뭘 자주 만지는지 아시면 그쪽이 맞다.

## 9. 검증 방식 — 단계마다 같다

이 저장소의 방식대로, **새 잠금은 일부러 깨뜨려 본다.**
넣고 나서 통과하는 건 증거가 아니다 — 빼고 나서 **실패해야** 그 잠금이 무언가를 지키고 있다는 증거다.

- A① : `busy` 를 빼고 두 번 눌러 두 번 가는 것을 **먼저** 본다
- A② : 갈아 끼운 창마다 Esc · Tab · 휠을 실제로 해 본다
- A④ : 새 검사에 `<div className="es-confirm">` 을 일부러 하나 넣어 **잡히는지** 본다
- B  : 저장 안 한 채로 제출해 **빠진 줄이 얼어붙는 것**을 재현하고, 묶은 뒤 안 그런지 본다
- C  : `table_merge_smoke.mjs` 가 계속 통과하는지 (툴바 병합이 살아 있다는 뜻)
