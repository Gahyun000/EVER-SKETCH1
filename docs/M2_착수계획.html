M2 착수 계획 · G3

카드 카탈로그 13종 + 편집 UI

M1(종단 슬라이스)에서 검증한 파이프라인 위에, 목업 수준의 카드 빌더를 실제 React 컴포넌트로 구현한다. 자유 캔버스는 M3, 발표는 M4에서. 이번 목표는 "카드만으로 다장 이북을 완성".

0스킬 사전 선언 (AGENTS.md 규약)

적용: uniever-development-standard(UI 표준·필수) · frontend-design(DESIGN 토큰) · karpathy-guidelines(과잉구현 방지). 부분: test-driven-development(export 계약 테스트). 미적용: 그 외 확장. 선언한 SKILL.md를 실제로 읽고 적용한 것만 증적으로 인정.

1컴포넌트 설계 (목업 → React)

컴포넌트역할경로
PageView ★페이지 1장을 cardKey로 렌더(표지·목차·본문·KPI·플로우·마인드맵·스티키…). 미리보기와 PNG 내보내기가 공유하는 심장.src/cards/PageView.tsx
Layout3분할 셸 + 좌/우 접이식(기본 펼침), 중앙 미리보기 크게src/builder/Layout.tsx
TopBar제목·세로/가로·타이포·발표·이북 만들기src/builder/TopBar.tsx
Palette카드 카탈로그(그룹별) — 클릭 시 페이지 추가src/builder/Palette.tsx
Filmstrip페이지 목록 — 선택·순서·삭제src/builder/Filmstrip.tsx
Editor선택 카드의 칸 편집(예시 프리필, 실시간 반영)src/builder/Editor.tsx
store전역 상태·액션(확장 완료)src/state/store.ts
exportBookN개 페이지 → PageView 오프스크린 렌더 → PNG → /api/buildsrc/export/exportBook.ts
Help(온보딩)사용설명서 버튼·코치마크(TEAM A)src/builder/Help.tsx
핵심 결정: PageView를 미리보기·내보내기 공용으로 둔다. 화면에 보이는 그대로가 PNG가 되므로 "미리보기 ≠ 산출물" 괴리가 원천 차단된다. M1의 임시 카드 렌더는 이 컴포넌트로 대체된다.

2빌드 순서 (수직 → 수평)

M2.1 상태 + PageView
store 확장(완료) + PageView로 표지·본문·목차·KPI·마무리 렌더. viz(플로우·마인드맵·스티키)는 뼈대 후 채움.
✔ 카드 1종을 store→PageView로 미리보기
M2.2 레이아웃 셸 + TopBar
3분할 접이식(중앙 크게) + 제목·방향·타이포 컨트롤.
✔ 빈 셸에서 방향/타이포 전환 반영
M2.3 Palette + Filmstrip
카탈로그 클릭→페이지 추가, 필름스트립 선택·순서·삭제.
✔ 여러 카드로 페이지 구성
M2.4 Editor
선택 카드 칸 편집(예시 프리필)→미리보기 실시간.
✔ 글 고치면 즉시 반영
M2.5 내보내기 일반화
exportBook: 표지+목차+본문N+뒷표지를 PNG 폴더로 → /api/build 다장 이북.
✔ 카드만으로 다장 이북 생성
M2.6 사용설명서(온보딩)
도움말 버튼 + 첫 실행 코치마크 + 빈칸 안심 문구.
✔ 낯선 경영진 안내 동작

3수용 기준 (M2 나가기)

  • 13종 카드 모두 Palette에 노출·추가 가능
  • 선택 카드 편집이 미리보기에 실시간 반영
  • 세로/가로·타이포 프리셋이 미리보기와 산출물에 일치
  • 카드만으로 표지→목차→본문N→마무리 다장 이북 생성 성공
  • Playwright 스모크: 카드추가→편집→이북만들기 200 OK

4리스크 · 메모

  • PNG 폰트 임베드 — M1에서 나온 결과를 그대로 계승. 깨지면 폰트 preload 처리.
  • 다장 내보내기 성능 — 페이지 많으면 순차 toPng가 느릴 수 있음 → 진행 표시/병렬 검토.
  • 목차 자동 — 우리 TocCard를 00. 목차.png로 낼지, 생성기 자동 텍스트 목차에 맡길지 M2.5에서 확정.
