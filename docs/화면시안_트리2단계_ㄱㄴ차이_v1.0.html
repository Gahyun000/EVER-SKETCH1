트리 2단계 — ㄱ과 ㄴ이 무엇이 다른가

말이 아니라 결과로 보여 드립니다. 왼쪽이 ㄱ, 오른쪽이 ㄴ이고 둘 다 눌러집니다.

① 뿌리를 골랐을 때 「＋ 형제」

뿌리에는 부모가 없습니다. 그래서 형제를 만들면 부모 없는 상자가 둘이 됩니다. 아래 두 화면은 뿌리(검은 상자)를 고른 채 「＋ 형제」를 누른 결과입니다.
ㄱ 못 누르게 — 뿌리는 하나
뿌리에서는 흐려집니다
한 뿌리

좋은 점 — 트리가 늘 하나입니다. 방향 전환·쪽 나누기·되읽기가 「뿌리 하나」만 생각하면 됩니다.
아쉬운 점 — 나란한 흐름 두 줄을 한 장에 못 그립니다. 장을 나눠야 합니다.

ㄴ 뿌리를 둘로 — 나란한 흐름
뿌리 1개
뿌리 여럿

좋은 점 — 「기획 흐름」과 「검수 흐름」을 한 장에 나란히 둘 수 있습니다.
치를 값 — 뿌리가 여럿이면 ③ 쪽 나누기가 어느 뿌리의 몇 레벨인지 물어야 하고, 방향 전환도 뿌리마다 따로 계산해야 합니다.

참고 — 머메이드로는 지금도 뿌리를 여럿 쓸 수 있습니다(A --> B 와 C --> D). ㄱ을 골라도 글로 넣는 길은 막히지 않습니다. 단추만 안 열리는 것입니다.

② 접은 채로 PDF · PPTX 로 내보내면

왼쪽 화면에서 접어 두고, 그 상태로 내보냈을 때 나오는 종이가 어떻게 다른지입니다. 지금 화면은 「결재」가 접힌 상태입니다.
편집 화면
ㄱ 보이는 대로 나간다
내보낸 종이

접기가 「요약해서 보여 주기」가 됩니다. 임원 보고에 큰 트리를 낼 때 윗단만 펴서 한 장으로 낼 수 있습니다.
조심할 것 — 접어 둔 걸 잊고 내면 내용이 빠진 채 결재에 올라갑니다. 그래서 내보내기 전에 「접힌 가지 N개가 빠집니다」를 한 번 물어야 합니다.

ㄴ 다 펴서 나간다
내보낸 종이

낸 것과 가진 것이 늘 같습니다. 접기는 편집할 때 눈이 편하라고 쓰는 것뿐이라 물어볼 것도 없습니다.
아쉬운 점 — 「윗단만 보여 주기」를 하려면 접기 말고 따로 손으로 지워야 합니다. 그리고 다 펴면 종이에 안 들어가 글자가 작아질 수 있습니다.

③ 쪽을 나눈 뒤, 앞 장을 고치면

3레벨에서 나눠 앞 장 · 뒷 장이 된 상태입니다. 아래 칸에 글자를 쳐서 앞 장의 「설계」 이름을 바꿔 보세요. 뒷 장이 따라가는지 보시면 됩니다.
앞 장의 「설계」 이름 →
ㄱ 한 트리로 묶어 둔다
앞 장
뒷 장

띠가 따라옵니다. 이름을 바꾸면 뒷 장 머리의 「↳ … 밑」도 같이 바뀌고, 다시 합칠 수 있습니다.
치를 값 — 뒷 장에 「앞 장의 어느 상자에서 이어졌나」를 저장해야 합니다. 그리고 앞 장을 지우면 뒷 장은 주인 없는 조각이 되므로 그때 처리를 정해 둬야 합니다.

// 저장되는 값 — 뒷 장
{ id: 7, cardKey: 'slide', treeRoot: 31, treeDir: 'LR',
  treeContFrom: { page: 6, elId: 12 },   ← 더 적는 값
  els: [ … ] }
ㄴ 나누면 남남
앞 장
뒷 장

띠는 나눌 때 한 번 적히고 그대로 굳습니다. 앞 장을 고쳐도 뒷 장은 모릅니다 — 나중에 보면 말이 안 맞는 띠가 남습니다.
좋은 점 — 저장되는 값이 지금과 똑같습니다. 뒷 장은 그냥 보통 트리라 앞 장을 지우든 순서를 바꾸든 아무 일도 안 생깁니다.

// 저장되는 값 — 뒷 장
{ id: 7, cardKey: 'slide', treeRoot: 31, treeDir: 'LR',
  els: [ … ] }
// 더 적는 값 없음 — 띠는 상자 글자에 섞여 들어간다

내보내기		 보이는 대로. 요약 보고가 됨 다 펴서. 낸 것 = 가진 것 ㄱ은 실수로 빠뜨릴 위험, ㄴ은 요약 기능이 없어짐
나눈 뒤
두 장		 묶어 둠. 따라가고 합쳐짐 남남. 저장값 그대로 ㄱ만 저장되는 값이 늘어납니다(treeContFrom)

제 생각을 물으시면 — ①은 ㄱ(뿌리 여럿은 남은 두 기능을 다 복잡하게 만듭니다), ②는 ㄱ에 내보내기 전 확인 한 번(요약이 실제로 쓸모 있고, 위험은 물어서 막힙니다), ③은 ㄴ(묶어 두면 앞 장 삭제·순서 바꾸기·복제까지 전부 따라 정해야 해서, 지금 단계에 비해 큽니다). 다만 정하시는 대로 하겠습니다.
