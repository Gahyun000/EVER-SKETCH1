# 자동저장 및 저장 확인 UX 구현계획서

- 문서일자: 2026-08-12
- 대상 프로젝트: ebook_html
- 계획 상태: 구현 전 계획안
- 적용 표준: Uniever 개발 표준, 작업대장 기록 원칙, TDD 기반 수용조건 정의

## 1. 배경

현재 HTML을 불러와 편집 가능한 슬라이드로 변환하더라도, 작업 상태는 브라우저 메모리의 Zustand store에 머무른다. 따라서 새로고침, 탭 닫기, 앱 재시작이 발생하면 import된 HTML 결과와 사용자가 편집하던 슬라이드/도형/텍스트가 사라진다.

`src/builder/chrome/TitleBar.tsx`에는 "저장됨" 표시가 있으나, 현재 확인 범위에서는 실제 작업 상태 저장/복원 로직과 연결되어 있지 않다. 이 표시를 실제 저장 상태와 연결하고, 작업 유실 가능성이 있는 액션에는 저장 확인 UX를 추가해야 한다.

## 2. 목표

1. 새로고침 후에도 마지막 작업 상태를 복구할 수 있게 한다.
2. HTML import 결과, 슬라이드 편집, 도형/텍스트/표/이미지 변경을 자동 저장한다.
3. 사용자가 명시적으로 저장할 수 있는 버튼과 저장 상태 표시를 제공한다.
4. 새 문서 시작, 새 HTML 불러오기, 데모 실행, 전체 교체 등 작업 유실 가능성이 있는 액션 전에 저장 확인 모달을 제공한다.
5. 저장 실패, 저장본 손상, 버전 불일치 상황에서도 앱이 깨지지 않게 한다.

## 3. 비목표

- 다중 사용자 협업 저장은 이번 범위에서 제외한다.
- 클라우드 계정 연동, Google Drive/Notion/SharePoint 저장은 제외한다.
- 서버 DB 영구 저장은 1차 범위에서 제외하고, 브라우저 로컬 저장을 우선한다.
- export된 이북 결과물 저장과 작업 초안 저장은 별도 개념으로 유지한다.

## 4. 저장 정책

### 4.1 자동저장

자동저장은 기본 ON으로 둔다. 사용자가 HTML을 import하거나 슬라이드를 편집하면 작업 초안이 자동으로 저장된다.

저장 트리거:

- HTML import 후 `importPages`, `importDoc`, `importDeckSlides` 완료
- 슬라이드 추가, 삭제, 복제, 이동
- 제목, 테마, 방향, 폰트, 크기 변경
- 필드 텍스트 수정
- 자유 캔버스 요소 추가, 이동, 크기 변경, 텍스트 수정, 삭제
- 연결선, 펜 stroke, 배경, 전환 효과 변경
- AI 편집/정리/요약 적용 후 상태 변경

저장 방식:

- 상태 변경 즉시 저장하지 않고 `500~1000ms debounce`를 적용한다.
- 저장 중에는 중복 저장 요청을 합치고, 마지막 상태만 저장한다.
- 저장 실패 시 상태를 `저장 실패`로 바꾸고 수동 저장 버튼을 노출한다.

### 4.2 수동 저장

자동저장과 별도로 명시적 `저장` 버튼을 둔다. 저장 버튼은 사용자가 심리적으로 현재 상태를 확정할 수 있는 장치다.

수동 저장 동작:

- 현재 builder state를 즉시 저장한다.
- 성공 시 "저장됨" 상태와 저장 시각을 갱신한다.
- 실패 시 "저장 실패"와 원인을 표시한다.

추후 확장:

- `백업 파일로 내보내기(.ebook-draft.json)`
- `백업 파일에서 불러오기`

### 4.3 저장 확인 모달

모든 변경마다 모달을 띄우지 않는다. 모달은 작업 유실 가능성이 큰 액션에만 사용한다.

모달 대상 액션:

- 새 HTML 불러오기 시작
- 새 문서 시작 또는 전체 초기화
- 데모 실행처럼 현재 상태를 임시로 대체하는 액션
- 저장본 삭제
- 복구하지 않고 새로 시작

모달 기본 문구:

> 현재 작업을 저장하고 계속할까요?

버튼:

- `저장하고 계속`: 즉시 저장 후 액션 실행
- `저장하지 않고 계속`: 저장하지 않고 액션 실행
- `취소`: 액션 취소

브라우저 새로고침/탭 닫기:

- 커스텀 모달은 브라우저 정책상 제한되므로 `beforeunload` 기본 경고를 사용한다.
- 조건: 마지막 저장 이후 변경분이 있고 저장이 아직 완료되지 않았을 때만 경고한다.

## 5. 저장소 선택

### 5.1 1차 권장: IndexedDB

이 프로젝트는 HTML import, 슬라이드 이미지, 자유 캔버스 이미지 dataURL을 다룬다. `localStorage`는 보통 5MB 안팎 제한이 있어 대형 HTML/PPT 변환 결과를 담기에 불안정하다. 따라서 1차부터 IndexedDB를 사용하는 것이 안전하다.

저장 구조:

- DB 이름: `ebook_html_workspace`
- Store 이름: `drafts`
- 기본 draft key: `current`
- 보조 key: `backup:<timestamp>` 추후 확장

### 5.2 localStorage 사용 범위

작은 UI 설정만 localStorage에 남긴다.

- 최근 열림 여부
- 복구 모달 마지막 선택
- 패널 크기 등 UI preference

작업 본문 상태는 IndexedDB에 저장한다.

## 6. 초안 데이터 스키마

```ts
interface WorkspaceDraftV1 {
  draftVersion: 1
  app: 'ebook_html'
  title: string
  sourceName?: string
  updatedAt: string
  savedAt: string
  state: {
    title: string
    orientation: 'portrait' | 'landscape'
    theme: string
    font: string
    size: 's' | 'm' | 'l'
    selectedPageId: number | null
    pages: Page[]
  }
}
```

스키마 원칙:

- `Page` 구조는 현재 store 타입을 그대로 보존한다.
- 향후 타입 변경을 대비해 `draftVersion`을 둔다.
- 복원 실패 방지를 위해 필수 필드가 없으면 안전한 기본값으로 보정한다.
- 알 수 없는 필드는 삭제하지 않고 가능한 한 보존한다.

## 7. UI 설계

### 7.1 TitleBar 저장 상태

현재 `저장됨` 표시를 다음 상태로 확장한다.

- `저장 중...`
- `저장됨`
- `저장 실패`
- `저장 안 됨`

표시 예:

- 초록 점: 저장됨
- 파란 점/스피너: 저장 중
- 주황 점: 저장 안 됨
- 빨간 점: 저장 실패

저장 버튼 위치:

- TitleBar 우측의 저장 상태 옆
- 또는 MenuBar `파일` 그룹 내 `저장`

1차 구현은 TitleBar에 `저장` 버튼을 두는 것이 사용자가 가장 쉽게 발견할 수 있다.

### 7.2 복구 모달

앱 시작 시 IndexedDB에 `current` draft가 있고 현재 store가 빈 상태라면 복구 모달을 띄운다.

문구:

> 이전에 작업하던 문서가 있습니다. 이어서 작업할까요?

표시 정보:

- 문서명
- 마지막 저장 시각
- 페이지 수

버튼:

- `복구하기`
- `새로 시작`
- `백업 내보내기`

### 7.3 저장 확인 모달

위험 액션 실행 전 표시한다.

문구:

> 현재 작업을 저장하고 계속할까요?

버튼:

- `저장하고 계속`
- `저장하지 않고 계속`
- `취소`

## 8. 구현 단계

### Phase 1. 저장 모듈과 테스트

파일 후보:

- `src/persistence/draftStorage.ts`
- `tests/harness/draft_storage_contract.mjs`

작업:

- IndexedDB wrapper 작성
- `saveDraft`, `loadDraft`, `clearDraft`, `getDraftMeta` 구현
- 스키마 검증/보정 함수 작성

수용조건:

- draft 저장 후 동일 state가 복원된다.
- 필수 필드 누락 draft는 앱을 깨뜨리지 않고 복원 가능한 부분만 복원한다.
- 버전 불일치 draft는 복구 모달에서 "복구 불가"로 처리된다.

### Phase 2. Zustand store 연결

파일 후보:

- `src/state/store.ts`
- `src/persistence/useAutosave.ts`
- `src/builder/Layout.tsx`

작업:

- builder state snapshot 생성 함수 추가
- autosave hook에서 store 변경 감지
- debounce 저장
- `dirty`, `saving`, `saved`, `error` 상태 관리

수용조건:

- HTML import 후 새로고침해도 페이지가 복원된다.
- 텍스트/도형 수정 후 새로고침해도 변경분이 유지된다.
- 저장 실패 시 UI가 실패 상태를 표시한다.

### Phase 3. TitleBar 저장 UI

파일 후보:

작업:

- `저장` 버튼 추가
- 저장 시각 tooltip 추가

수용조건:

- 변경 직후 `저장 중...` 또는 `저장 안 됨`이 표시된다.
- 저장 완료 후 `저장됨`으로 바뀐다.
- 수동 저장 버튼이 즉시 저장을 실행한다.

### Phase 4. 복구 모달

파일 후보:

- `src/persistence/RestoreDraftModal.tsx`

작업:

- 앱 시작 시 draft meta 확인
- 복구/새로 시작/백업 내보내기 버튼 구현

수용조건:

- 저장본이 있을 때 복구 모달이 뜬다.
- 복구 선택 시 이전 페이지/선택 페이지가 돌아온다.
- 새로 시작 선택 시 기존 draft를 삭제하거나 백업 후 초기화한다.

### Phase 5. 위험 액션 보호

파일 후보:

- `src/persistence/ConfirmSaveModal.tsx`
- `src/builder/chrome/ClassicBar.tsx`
- `src/builder/DemoPlayer.tsx`
- `src/builder/Layout.tsx`

작업:

- 새 HTML 불러오기 전 확인
- 새 문서/초기화 전 확인
- 데모 실행 전 확인

수용조건:

- `저장하고 계속`은 저장 후 파일 선택/액션을 진행한다.
- `취소`는 기존 작업 상태를 그대로 유지한다.
- 새로고침 시 브라우저 기본 경고가 작동한다.

## 9. 테스트 계획

### 단위/하네스

- draft 저장/복원 계약 테스트
- 스키마 버전/누락 필드 보정 테스트
- debounce 저장 횟수 테스트

### E2E

- AX HTML import → 16페이지 생성 → 새로고침 → 16페이지 복원
- 목차 페이지 `data-goto-seq` 유지
- 도형 추가/텍스트 수정 → 새로고침 → 수정 내용 유지
- 새 HTML 불러오기 전 저장 확인 모달 표시
- 저장하지 않고 계속 선택 시 새 import 진행
- 취소 선택 시 기존 문서 유지

## 10. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| IndexedDB 저장 용량 초과 | 이미지 포함 draft 저장 실패 | 저장 실패 상태 표시, 백업 내보내기 제공, 이미지 압축/분리 저장은 후속 |
| Page 타입 변경 | 이전 draft 복원 실패 | `draftVersion`과 migration 함수 도입 |
| 자동저장 중 대형 state 직렬화 지연 | UI 끊김 | debounce, 저장 대상 최소화, 필요 시 Web Worker 후속 검토 |
| beforeunload 커스텀 UI 불가 | 탭 닫기 UX 제한 | 브라우저 기본 경고 사용, 앱 내부 액션만 커스텀 모달 |
| 사용자가 자동저장을 신뢰하지 못함 | UX 불안 | 수동 저장 버튼과 저장 시각 표시 |

## 11. 우선순위

1. IndexedDB draft 저장/복원
2. HTML import 후 새로고침 복원
3. TitleBar 저장 상태와 수동 저장 버튼
4. 복구 모달
5. 위험 액션 저장 확인 모달
6. 백업 파일 내보내기/불러오기

## 12. 구현 착수 전 결정 필요사항

1. 자동저장 보관 개수: `current` 1개만 둘지, 최근 N개 백업을 둘지 결정한다.
2. 새로 시작 시 기존 draft를 즉시 삭제할지, `backup:<timestamp>`로 옮길지 결정한다.
3. 저장 버튼 위치를 TitleBar에 둘지, 파일 메뉴에 둘지 결정한다.
4. 이미지 dataURL까지 1차 저장 범위에 포함할지, 외부 이미지는 후속으로 둘지 결정한다.

## 13. 권장 결정안

- 자동저장 보관: 1차는 `current` 1개, 새로 시작 시 `backup:<timestamp>` 1개 생성
- 저장 버튼 위치: TitleBar 우측
- 저장소: IndexedDB
- 위험 액션 모달: 새 HTML 불러오기, 새로 시작, 데모 실행, 저장본 삭제에만 적용
- beforeunload: 저장 중이거나 dirty 상태일 때만 브라우저 기본 경고
