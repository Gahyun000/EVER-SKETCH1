“조회 화면은 시작일, 종료일, 검색어, 조회 버튼과 페이지 이동을 기본으로 한다. 행 클릭으로 상세 화면에 진입하며 중복된 상세보기 버튼은 만들지 않는다.”
정정
페이지 이동 바를 목록 위에 두었던 것은 제 실수입니다. v0.7 에서 폴더·자료 두 묶음을 나란히 두느라 각 묶음 머리에 붙였는데, 페이지 이동은 목록을 다 본 다음에 하는 일이라 아래가 맞습니다. 위에는 검색과 결과 요약이 옵니다 — 목록을 보기 전에 하는 일입니다.

1. 조회 화면 P4

검색어를 넣고 조회를 눌러 보세요. 진행 · 2026 · 예산 같은 말이 있습니다.

내 자료 깊이 0 / 3

~
🔍

1
위는 「보기 전」, 아래는 「보고 난 뒤」. 검색·결과 요약은 목록 위에, 페이지 이동은 목록 아래에. 각 묶음의 페이지 바는 그 묶음 바로 아래에 붙습니다 — 폴더 바가 자료 목록 밑에 있으면 무엇을 넘기는 바인지 알 수 없습니다.
2
기본이 「전체에서」입니다. 찾는 사람은 대개 어디 뒀는지 몰라서 찾습니다. 현재 폴더 안만 뒤지면 대부분 빈손이 되고, 그러면 폴더를 하나씩 들어가며 다시 찾게 됩니다.
3
검색 결과에는 경로가 붙습니다. 「내 자료 › 진행보고」 처럼요. 전체에서 찾았으니 어디서 나온 것인지 알려주지 않으면, 찾고도 다시 못 찾습니다.
!
검색 중에는 폴더 안으로 들어가는 대신 「검색 지우기」로 나옵니다. 검색 결과는 여러 폴더에서 모인 것이라 「현재 폴더」가 없습니다. 경로를 그대로 두면 지금 어디 있는지 화면이 거짓말을 하게 됩니다.

2. 규칙

값이유
검색 구성시작일 · 종료일 · 검색어 · 조회 · 초기화 표준 §3 의 조회 화면 기본 구성
검색어 대상자료 제목 + 폴더 이름 폴더도 찾는 대상이다. v0.7 의 「폴더 13개부터 별도 검색칸」은 이 칸으로 합친다
날짜 대상자료의 수정일만 폴더에는 사람이 기억하는 날짜가 없다. 날짜를 넣으면 폴더는 결과에서 빠진다
검색 범위기본 전체에서어디 뒀는지 몰라서 찾는다
결과 표시경로 + 일치 부분 강조어디서 나온 것인지 알아야 다시 찾을 수 있다
페이지 바 위치각 목록 아래페이지 이동은 다 보고 난 뒤에 하는 일
결과 요약 위치목록 위몇 건인지는 보기 전에 알아야 한다
행 클릭행 전체가 열기표준 §3 — 중복된 상세보기 버튼을 만들지 않는다
