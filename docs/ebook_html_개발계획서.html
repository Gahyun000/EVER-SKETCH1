개발 착수 전 계획서 · v1 · G0 산출물

ebook_html — 경영진 스케치 빌더 개발 계획

확정된 목업(카드 기본 + 자유 캔버스 + 발표 모드)을 실제 제품으로 옮기기 위한 착수 전 계획. 범위·기술·아키텍처 결정·마일스톤·검증·리스크를 default_skill 컨트롤타워(G0~G6) 기준으로 정리했습니다.

제품: 경영진 사업모델 → 이북/덱 빌더 스택: React + TypeScript 경로: /git/ebook_html (신규) 연결: PNG 폴더 → generator.py (uniever_ebook 무수정)

1목표와 성공 기준

목표 — 디지털에 낯선 경영진이 사업모델을 카드로 빠르게 조립하고(필요 시 Whimsical식 자유 캔버스로 자유 편집), 세로 이북 또는 가로 덱으로 내보내며, 그 자리에서 발표까지 할 수 있는 도구.

성공 기준 (측정 가능)

  • 낯선 경영진이 10분 내 카드만으로 사업모델 이북 1권 완성 → PNG 폴더 산출 → generator.py로 이북 생성 성공.
  • 자유 캔버스에서 도형·화살표·펜·이미지가 최종 이북(PNG)에 깨짐 없이 반영.
  • 세로/가로 전환, 폰트·크기 오버라이드가 미리보기와 산출물에서 일치.
  • 발표 모드로 완성물을 그대로 넘기며 브리핑 가능.
  • uniever_ebook은 단 한 줄도 수정하지 않음.

2범위 (In / Out)

MVP 포함

  • 카드 카탈로그 13종(FRAME 3 + BMC 9 + EXTRA 4)·편집·미리보기
  • 세로/가로 전환, 타이포 자동+프리셋 오버라이드
  • 자유 캔버스: 도형(5)·텍스트·스티키·이미지·아이콘·화살표 연결·펜·색·복제·정렬·되돌리기
  • 발표(프레젠테이션) 모드
  • PNG 폴더 내보내기 + generator.py 연동

이번 범위 밖 (후속)

  • 와이어프레임 컴포넌트 라이브러리(버튼·입력 등)
  • 실시간 협업·댓글, 멀티유저
  • 실제 생성형 AI 다이어그램(현재는 초안 데모 버튼)
  • 프레임/섹션, 무한 캔버스(페이지 경계 없는)
  • 버전 관리·클라우드 저장(1차는 로컬/파일 중심)
착수 전 확정 필요(G0) — 포지셔닝. 현재 목업은 "카드 단순 + 자유 캔버스 파워"를 한 화면에 합친 하이브리드다. 이대로 갈지, 아니면 "경영진=카드 기본 / 자유 캔버스=고급·실무자 모드"로 모드 분리할지 1차 릴리스 전 확정. 범위·UX 복잡도가 갈린다.

3기술 스택 · 프로젝트 구조

Vite + React + TypeScript. 상태는 경량(zustand/Context). 렌더는 카드=선언형, 자유 캔버스=DOM/SVG. 내보내기는 클라이언트 html-to-image.

4연결 계약 (재확인 · 불변)

ebook_html (React)→ export PNG 폴더 + links.json→ CLI generator.py (무수정)→ ebooks/<id> 이북

파일명 규칙: 표지.png / 00. 목차.png / NN. 제목.png(순번+제목) / 뒷표지.png. 빌드: python3 generator.py build <폴더> --style card --title "...". 카드+자유 요소는 페이지별 한 장 PNG로 합쳐 저장 → 커스텀 폰트·도형·펜이 그대로 반영, 생성기 무수정.

5핵심 아키텍처 결정 (ADR 요약)

ADR-1 생성기 블랙박스. uniever_ebook 무수정, PNG 폴더 공급자로만 연결. → 신규 리스크를 ebook_html에 격리.
ADR-2 페이지 = 바운디드 캔버스. 무한 보드가 아니라 이북 한 장 크기의 자유 캔버스. → 자유도 + 페이지 매핑 동시 확보.
ADR-3 카드 = 캔버스 위 템플릿. 카드로 기본 틀, 자유 요소는 오버레이. 경영진은 카드만으로 완성 가능, 파워유저는 자유 편집.
ADR-4 PNG 렌더로 타이포/도형 반영. 폰트·크기·도형·펜을 이미지에 구워 넘김 → 생성기 스타일 계약과 충돌 없음.
