## 1. 배경과 목적

- 해결하려는 문제: 경영진이 사업모델을 표준 틀(카드)로 빠르게 조립하고, 필요 시 자유 캔버스로 편집해 이북(PNG→PDF)·발표덱(PPTX)으로 내보내는 도구가 없다. 문서/기획 산출물 제작이 수작업에 의존한다.
- 기대 효과: 카드 카탈로그 기반 표준화로 산출 속도·일관성 향상, 자연어(챗)로 초안 생성·부분수정, 기존 `uniever_ebook` 이북 파이프라인 재사용(무수정).
- 성공 지표(초안): (a) 브리프 한 줄→이북 초안 생성 성공, (b) 카드 13종 렌더 무오류, (c) export 체인(렌더→PNG→generator.py) 정상 산출, (d) 자기검증 경고 오탐/미탐 관리.

## 2. 범위

### 포함
- 카드 카탈로그(13종, group: frame/extra/viz) 조립 빌더 + 자유 캔버스 편집
- HTML 가져오기(import) → 카드 변환, 페이지네이션/정리
- 챗 에이전트: 문서 컨텍스트(G1) · 카드 미러(G2) · BookPlan 생성(G3, `/api/plan`) · 적용(G4) · 대화형 부분수정(G5, `/api/edit`) · 자동 export + 자기검증(G6)
- 내보내기: 이북 PNG→`generator.py`(`/api/build`), 발표덱 PPTX(`/api/deck`, `/api/deck/stream`), DOCX(`/api/export/docx`)
- LLM 설정(`/api/settings/llm`, 서버 저장) · EVER-FOLIO(8811) 연동 전환

### 제외
- `uniever_ebook` 및 `generator.py` 수정(불변 계약)
- 다중 사용자/권한 서버(현재 로컬 단일 사용자)
- 상용·유료 외부 AI 서비스 상시 연동(무료·오픈소스/사내 self-host 우선 — UDS-107)

## 4. 적용 수준, 개발기법과 AI 권한

- 프로젝트 수준: `L2`(안) — 내부 업무 도구, 로컬 단일 사용자
- 주요 기능 개발기법: `T2`(안) — 문서→BookPlan 생성/대화형 수정이 모델 호출 + 상태·검증·반복 포함
- AI 권한: `A2`(안) — AI는 초안까지, 최종 수용은 인간 승인
- 선택 근거: LLM 게이트웨이·플래너·에디터가 자유형 출력을 생성하므로 계약·검증기 분리 필요(UDS-111)
- T2·T3 적용 기능: T2 — `/api/plan`(BookPlan 생성), `/api/edit`(대화형 수정), 자기검증. T3 해당 없음(운영 무인 자동화 아님)
- 하네스 설계서 경로: `docs/기술문서/하네스설계서.md`, `docs/기술문서/개발기법선정서.md`
- 승인 필요 작업: 외부 전송/배포, LLM provider를 상용으로 전환, 대량 파일 변경

- 계약·법률: 사내 데이터만 처리, 개인정보 미수집 원칙
