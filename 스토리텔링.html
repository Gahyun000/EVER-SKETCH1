어떤 레퍼런스로, 어떻게 만들었나

경영진이 직접 사업모델을 한 권의 이북으로 만드는 도구 ebook_html을, 무엇을 참조해 어떻게 계획하고 만들었는지 한 편으로 정리했습니다. 핵심 메시지는 하나입니다 — 검증된 레퍼런스 + 내부 개발 표준으로 계획을 먼저 세웠더니, 같은 이북 작업이 하루로 끝났습니다.

목표
디지털에 낯선 경영진도 혼자서 사업모델을 이북으로.
레퍼런스
Whimsical · Miro · 비즈니스 모델 캔버스 · Figma · 내부 표준(default_skill).
방법
표준을 먼저 이식하고 M0~M6 게이트로 계획 주도 개발.
결과
전 기능 완성 · 자동검증 25/25 PASS · uniever_ebook 무수정 연결.

1출발점 — 무엇을, 왜

기존 uniever_ebook은 이북을 생성하는 엔진은 있지만, 경영진이 내용의 '틀'을 짜는 입구가 없었습니다. 그래서 경영진이 카드를 고르고 내용만 채우면 그것이 곧 이북이 되는 앞단 도구를 새로 만들기로 했습니다. 세 가지를 처음부터 못 박았습니다.

전제내용
사용자는 완전 초보"디지털이 낯선 임원도 설명 없이 10분 안에" — 단순함이 최우선 스펙.
기존 엔진 무수정uniever_ebook은 한 줄도 고치지 않고, 이미지(PNG) 폴더를 넘겨 generator.py만 호출.
새 앱은 표준 위에React·TypeScript로 새로 만들되, 사내 default_skill 표준을 이식해 방식부터 통일.

2벤치마킹 — 무엇을 보고, 무엇을 취했나

유명한 도구를 그대로 베낀 것이 아니라, 어떤 상호작용이 초보에게 통하는지를 관찰해 필요한 것만 골라 우리 방식으로 다시 구현했습니다. 아래 표의 "채택 / 조정 / 제외"가 그 판단의 기록입니다.

레퍼런스무엇을 관찰했나어떻게 반영했나
Whimsical
다이어그램·보드		 도형·스티키로 흐름도를 그리는 자유 캔버스, 도형끼리 잇는 연결선, 한 글자 단축키. 채택 자유 캔버스(도형·텍스트·스티키·아이콘), 연결선(도형 클릭→클릭, 자동 직각 라우팅), 펜, 단축키 체계.
조정 연결선을 선 아무 데나 잡아 꺾기로 쉽게. 단축키는 입력 중 자동 비활성(초보 오작동 방지).
제외 다중 꺾임·곡선 연결(백로그), 무한 캔버스 개념.
Miro
협업 화이트보드		 넓은 캔버스에 자유 배치, 스티키 메모, 슬라이드처럼 넘기는 발표. 채택 자유 배치 캔버스 + 전체화면 발표 모드(키/클릭 넘김).
조정 무한 캔버스 대신 한 페이지 크기에 고정 — 보이는 그대로가 이북 한 장이 되도록.
비즈니스 모델 캔버스
Osterwalder · Strategyzer		 사업모델을 9개 블록(가치제안·고객군·수익원·채널·핵심자원·활동·파트너·고객관계·비용)으로 나누는 프레임. 채택 카드 카탈로그의 뼈대로 BMC 9블록 전부를 카드화 + 표지·목차·성과·로드맵 등 보고용 카드.
조정 빈칸에 예시 문구를 미리 채워 초보가 '고쳐 쓰기'만 하도록.
Figma
디자인 시스템		 흑백 기반 + 절제된 색, 일관된 타이포·간격 토큰. 채택 흑백 + 파스텔 블록의 디자인 토큰화(Inter·JetBrains Mono). 선택 도구 단축키 V도 이 계열에서.
default_skill
사내 개발 표준		 작업 전 스킬 사전 선언, 게이트별 검증, 테스트·완료전 검증 규약. 채택 표준 스킬 7종을 그대로 이식해 계획·품질의 기준선으로 사용(§4).
중요 — 코드가 아니라 '방식'을 참조했습니다. Whimsical·Miro의 코드나 컴포넌트를 가져오지 않았습니다. 화면과 동작을 관찰해 React로 직접 다시 구현했으므로, 결과물은 우리 자산입니다. 반면 default_skill은 사내 표준이라 파일을 그대로 이식했습니다.

3레퍼런스를 실제로 참조한 증거 — 단축키 1:1 대조

"참조했다"는 말이 구호에 그치지 않도록, Whimsical 공식 단축키와 우리 앱을 직접 맞춰봤습니다. 편집 단축키는 완전히 동일하고, 도형 키도 대부분 일치합니다.

기능Whimsicalebook_html비고
되돌리기 / 다시 실행⌘+Z / ⌘+⇧+Z⌘/Ctrl+Z / ⌘/Ctrl+⇧+Z동일
복제 / 삭제⌘+D / Delete⌘/Ctrl+D / Delete동일
복사 / 붙여넣기⌘+C / ⌘+V⌘/Ctrl+C / ⌘/Ctrl+V동일
사각형 · 원 · 마름모 · 텍스트R O D TR O D T동일
연결선C 또는 LC일치
선택 도구SVFigma식으로 조정
스티키NS니모닉 조정
펜(자유 선)HP'Pen' 니모닉

즉, 임원이 이미 다른 도구에서 익힌 ⌘Z·⌘C·⌘V 같은 손버릇이 그대로 통합니다. 몇 개 니모닉만 우리 도구 이름에 맞춰 바꿨습니다.

4계획 수립 — 이번엔 왜 순탄했나

가장 큰 차이는 '무엇을 만들까'가 아니라 '어떻게 진행할까'를 먼저 정한 것입니다. 착수 전에 사내 표준 default_skill 7종을 이식하고, 모든 작업을 스킬 사전 선언 → 게이트 통과 규약으로 묶었습니다.

이식한 표준(요지)이번 프로젝트에서 한 일
개발 표준 · 관제탑UI/작업 규약 통일, 단계별 산출물·게이트 정의.
프론트엔드 디자인디자인 토큰(흑백+파스텔) 확립.
Karpathy 가이드과잉 구현 억제 — 필요한 것만.
테스트 주도 · 완료 전 검증 · 웹앱 테스트Playwright 자동 스모크로 매 단계 회귀 방지.

5그래서 나온 굴곡 — 같은 이북, 다른 결과

이전 · uniever_ebook

계획을 제대로 세우지 않고 착수 → 기획안이 여러 판 뒤집힘 → 방향을 잃고 시간이 오래 걸림.

이번 · ebook_html

표준 이식 + 계획을 먼저 문서화 → 게이트대로 착착 → 하루 만에 순탄하게 완주.

발표자료 3페이지 '성장일지 · 계획수립의 굴곡'이 바로 이 대비를 곡선으로 보여줍니다.

7주요 의사결정과 근거

결정대안왜 이렇게
하이브리드(카드+자유캔버스 한 화면)모드 분리(초급/고급)낯선 임원이 모드를 오가게 하지 않기 위해. 대신 설명서·튜토리얼로 안내.
자유 캔버스 항상 켜짐스위치로 켜고 끄기스위치 존재 자체가 혼란 → 제거하고 기본 '선택' 도구로 안전하게.
단일키 단축키 + 입력 중 자동 비활성단축키 없음 / 항상 켜짐숙련자에겐 빠르게, 초보에겐 오작동 없이. 마우스로도 100% 가능.
페이지 크기 고정 캔버스무한 캔버스(Miro식)"보이는 그대로가 이북 한 장" — 미리보기와 산출물 괴리 원천 차단.
네이티브 재구현외부 라이브러리/코드 차용가벼움·독립성·자산화. 결과물은 온전히 사내 소유.

8맺음

이 프로젝트의 진짜 성과는 도구 하나가 아니라 재현 가능한 방식입니다. 검증된 레퍼런스로 무엇을 만들지를 좁히고, 사내 표준으로 어떻게 만들지를 먼저 고정하면, 지난번 이북 작업이 오래 걸렸던 것과 달리 같은 결과가 하루로 압축됩니다. 남은 단계는 실제 경영진 한 분의 파일럿 관찰(M6)이며, 관찰 가이드까지 준비되어 있습니다.

"무엇을 볼지(레퍼런스) × 어떻게 갈지(표준) = 속도와 품질." — 이번 결과를 한 줄로 요약하면 이렇습니다.
